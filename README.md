# NBTCreator

面向 **Minecraft Java 1.20.1** 的 Windows NBT 建筑创作工作台。在同一工作区管理建筑、预览材质、编辑结构、生成 AI 构件，并与外部 Agent 协作。

支持打开 Java 结构 NBT 和完整主模型。修改先进入候选预览，由你主动导出下一版，保留原稿。

## 下载与启动

从 [GitHub Releases](https://github.com/Try2findwhoasked/NBTCreator/releases) 获取 Windows x64 版本。

| 交付形式 | 用途 |
| --- | --- |
| 完整免安装文件夹 | 直接运行文件夹内的 `NBTCreator.exe` |
| `windows-x64-portable.zip` | 首次下载，完整解压后运行 |
| `windows-x64-app-update.zip` | 已有兼容运行环境，仅更新应用 |
| `windows-x64-runtime.zip` | 与应用更新包解压到同一父目录，合并同名文件夹 |

完整版内置 Python、NumPy、Pillow 和 Chromium，Electron 提供 Node 运行环境，无需另行安装开发工具。**保留完整目录，不要只复制 EXE。** 应用更新包不包含完整运行环境，启动时会检查兼容性。

首次选择创作项目的根目录，建筑默认存放在工作区的 `nbt_models/` 中。应用目录与创作工作区可以分开。

## 快速上手

1. **打开建筑**：在“项目管理”选择已有建筑，或点击“打开 NBT…”。没有建筑时，先在“提示词方案”编写初稿要求，交给外部 Agent 制作。
2. **查看模型**：点击“预览”，默认显示带材质的 3D；进入“模型编辑”后可切层、剖切、取材和标注。
3. **进行修改**：限定修改范围，使用建模工具，或让 AI 添加局部构件。更新效果预览后，可撤销、重做和对比。
4. **检查结果**：检查当前效果、保护区与适用的通路报告，再实际查看图片或 3D。
5. **保存下一版**：满意后主动执行“导出建筑下一版”。生成建议、恢复草稿或检查通过都不会自动导出正式 NBT。

## 主要功能

### 项目与版本

- 按项目、形状、对象和版本浏览，组合筛选最新版本、历史版本、创作阶段与文件状态。
- 识别 `nbt_models/形状/对象/版本` 和 `nbt_models/项目名/形状/对象/版本`。浏览、排序与标记不移动实际文件；支持单独查看待修复文件。
- 在同一镜头下对比两个已保存版本或当前候选，标记新增、删除、替换及墙层变化。
- 批量生成截面图、检查文件与声明路线、标记阶段；制作批次可关联正式模型、交付图册和 Agent 任务。
- 自动保存编辑草稿，恢复参数、未导出步骤、镜头、图层、剖切和未保存标注。源文件变化时保留旧草稿，不自动套用。

项目页提供“生成并加载缩略图”：为当前筛选结果生成缺失缩略图，限制并发并显示进度，可随时停止。默认随滚动自动加载更多卡片，也可关闭自动加载并手动追加。

对 bugged 或无法读取的结构，可选择分类并点击“尝试修复并归类”。脚本只恢复可确定的数据，原文件保留；成功后生成新主模型候选并切换到目标分类，失败时给出报告。不会自动修补设计、删除冲突方块、丢弃实体或导出 NBT，候选仍需看图检查。报告位于 `.nbtcreator/repairs/`。

### 预览与建模

- 默认使用材质 3D，支持图片、视角预设、切层、剖切、保护区显示、取材与选点标注。
- 26 项共用工具涵盖方块、梁、边框、几何体、复制与变换、选区替换、对齐、阵列、楼梯、道路、屋顶、混材与风化。
- 几何工具支持截面扫掠、放样和旋转体；道路可按平面或地形生成，屋顶提供多种形态。
- 步骤可命名、启停、重排、复制和删除；操作历史支持撤销、重做和参数回退。
- 构件可通过数值、滑块和 3D 表面选点调整位置，支持绕 Y 轴旋转。

### 构件与配方

“资产管理”支持保存选区或独立创建构件，管理名称、标签、锚点与缩略图。构件可搜索、导入导出、回收站恢复、旋转、镜像及批量放置；常用工具序列可保存为配方，并复用材质主题。

构件放置先生成候选。暂不支持的方块朝向或状态变换会明确提示，不静默猜测。

### AI 与 Agent 协作

AI 是可选功能，普通浏览、编辑和导出无需 API。

- 在“AI 助手”配置连接、模型与 API Key，可调整采样、输出长度、超时和请求参数。
- 小型构件可只选择参考类型直接生成，也可补充风格、材质与用途；生成后预览，再整体移动或旋转。
- 小型构件默认裁掉候选中与保护区冲突的方块，**保留保护区原有内容**。关闭裁剪时，冲突会拒绝；覆盖开关与改动预算仍生效。
- “选区自然语言工具编辑”读取真实选区方块，返回可审阅的命名步骤，再由本地引擎检查和预览。
- 各工作流可分别配置创作偏好、规则、知识资料和视口截图；截图需要模型支持图像输入。
- 可检索本地参考资料与现有构件，查看出处后选择发送；内部 API 与对外 Skill 的知识配置分开管理。
- 标注可整理为任务并交给外部 Agent；回传版本后可同镜头对比，逐条核对意见。

AI 返回内容须通过本地格式、工具、坐标、材质、保护和预算检查。API 的 JSON 模式不等于供应商强制保证全部建模规则；检查报告不替代实际看图或游戏内验收。

## 视图、设置与快捷键

| 操作 | 入口或默认方式 |
| --- | --- |
| 默认使用 3D 或图片 | 设置 → 视图与预览 → 默认预览方式 |
| 默认 3D 质量 | 设置 → 视图与预览 → 默认 3D 质量 |
| 视角速度与反转 | 设置 → 视图与预览 → 3D 视角操作 |
| 启停工具添加入口 | 设置 → 常规配置 → 建模工具启停 |
| 搜索工具和操作 | `Ctrl+K`，支持中文名、工具 ID 和收藏 |
| 切换工作区 | `Alt+1`～`Alt+6` |
| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Y`，可在设置中调整 |
| 3D 转向 / 平移 / 前后移动 | 左键拖动 / 中键拖动 / 滚轮 |

默认预览用于项目预览和首次打开模型；图片缺失时回退到 3D。已保存的草稿优先恢复原视图。工具启停控制新增入口，已有步骤仍可编辑、预览和导出。

全屏闪退问题已修复，原 NBTC-001 已关闭。设置、配色与操作偏好随工作区保存。

## 数据保存位置

| 内容 | 位置 |
| --- | --- |
| 建筑、主模型与版本输出 | 工作区 `nbt_models/` |
| 应用偏好、索引与编辑草稿 | 工作区 `.nbtcreator/` |
| 构件 / 配方与材质主题 | `.nbtcreator/components/` / `.nbtcreator/reusable/` |
| 外部 Agent 入口 | `.agents/skills/nbtcreator-workspace/SKILL.md` |
| 标注、提示词方案、Agent 交接 | 建筑版本内的 `修改意见/`、`提示词方案/`、`Agent交接/` |
| API Key 与更新访问令牌 | 本机 Windows 用户配置目录，加密保存 |

迁移创作数据时保留完整工作区，包括隐藏目录。凭据不会随工作区或模型导出，也不会打入发行包。同一建筑建议由应用与 Agent 轮流修改，修改后刷新。

## 外部 Agent 与命令行

让 Agent 在创作项目根目录读取 `.agents/skills/nbtcreator-workspace/SKILL.md`，按任务进入所选知识路由。应用与 CLI 使用同一套引擎，无需 GUI 自动点击建模。

```powershell
python .agents/skills/nbtcreator-workspace/nbt.py capabilities
python .agents/skills/nbtcreator-workspace/nbt.py paths
python .agents/skills/nbtcreator-workspace/nbt.py feedback scan --workspace .
```

便携版也可通过 `NBT工具.cmd` 使用内置运行环境：

```powershell
.\NBT工具.cmd --workspace "D:\MyMinecraftProject" capabilities
```

各命令用 `--help` 查看参数。对外工具与知识可在应用的 AI 设置中管理；Agent 回传、任务完成和工具检查不构成用户批准。

## 更新与常见问题

**如何更新？** 在“设置 → 更新”检查稳定发行版并下载，校验后关闭应用，再解压到新目录或按更新包说明合并。保留原工作区，不覆盖运行中的程序。

**为什么有些模型只能查看？** 编辑可能需要补齐坐标、开口、墙层或验证上下文。界面会列出缺失项；未知碰撞形状、通路失败与文件损坏会分别说明。

**为什么 AI 生成后没有 NBT 文件？** 返回的是建议或候选。先载入预览并检查，最后手动导出下一版。

**为什么切换默认预览后仍恢复旧镜头？** 草稿优先恢复上次状态。默认设置用于新开的预览，可在常规设置管理草稿恢复。

**如何反馈问题？** 在 [GitHub Issues](https://github.com/Try2findwhoasked/NBTCreator/issues) 提供版本、操作步骤、任务错误与必要截图，不要附带 API Key 或私人工作区数据。

## 从源码运行与构建

开发需要 Node.js 24、Python 及 NumPy/Pillow：

```powershell
npm ci
npm ci --prefix .agents/skills/minecraft-nbt-modeler/assets/viewer
python -m pip install -r .agents/skills/minecraft-nbt-modeler/requirements.txt
npm run build:web
npm start
```

```powershell
npm run doctor
npm run check:tools
npm run test:api
npm run test:desktop
npm run package:portable -- --directory-only --out dist/full-folder
```

`--directory-only` 生成包含全部运行环境的免安装目录，不制作 ZIP；省略此选项会同时生成完整包、应用更新包和运行环境包。生产版使用预构建前端。
