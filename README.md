# NBTCreator

Minecraft Java 1.20.1 NBT 建筑创作工作台，集成建筑方案、模型编辑、3D 预览、AI 构件生成与 Agent 协作。

## 主要功能

- **建筑方案**：选择形状填写尺寸、布局、材质与构造要求，AI 可辅助完善完整初稿方案。
- **项目管理**：按“项目 → 形状 → 对象”浏览，包含 bugged 待修复分类；筛选最新、历史、中间稿和文件状态，查看图片或只读 3D 预览，点击建筑进入模型编辑。
- **资产管理**：独立工作区管理构件，保存当前 3D 选区、名称、标签、锚点和缩略图；支持搜索、导入导出、回收站恢复与重复放置。
- **模型编辑**：打开完整 NBT 或主模型，调整材质、地面和结构；工具步骤可命名、启停、重排、复制和删除，预览后另存下一版。
- **编辑恢复**：自动保存工作区内的编辑草稿，恢复建筑、参数、未导出步骤、镜头、图层、剖切和未保存标注；源文件变化时保留旧草稿并拒绝自动套用。
- **版本对比**：按需读取两个已保存版本或当前候选，保持同一镜头切换，彩色标记新增、删除、替换和墙层变化；支持仅看变化与逐区域定位，不改动模型。
- **操作历史**：记录当前建筑的候选参数，支持改名、跳转、撤销与重做；连续输入合并，长期保留可保存调整设置。
- **候选检查**：核对当前参数与所看快照，检查预算、保护、密闭和静态通路，失败保留报告。
- **3D 与标注**：紧凑单行视口工具栏；摄像头原地转向、沿视线前后移动、平移、切层、取材、选点与修改意见。
- **AI 构件**：45 种构件参考，支持相对坐标生成、3D 放置、立即预览和整体 XYZ 偏移。
- **AI 创作偏好**：各使用区域单独设置保守／天马行空、简洁／详细、朴素／丰富、延续／变化，应用与外部 Skill 共用工作区配置。
- **AI 工作流**：分别配置规则、资料库和视口截图；内部 API 与对外 Skill 独立管理。
- **快速操作**：Ctrl+K 搜索工作区、参数面板和全部建模工具，星标常用命令；在设置中修改快捷键，收藏和配置随工作区保留。
- **设置与记录**：常规配置、关于、检查更新，以及 AI 请求和本地预览的阶段日志。

## 下载与启动

从 [GitHub Releases](https://github.com/Try2findwhoasked/NBTCreator/releases) 下载 Windows x64 版本；当前仓库公开，可直接下载。

| 下载包 | 用途 |
| --- | --- |
| windows-x64-portable.zip | 完整便携版，解压后运行 NBTCreator.exe |
| windows-x64-app-update.zip | 已有兼容运行环境时更新应用 |
| windows-x64-runtime.zip | 与应用包解压到同一父目录，合并同名文件夹 |

完整版内置 Python、NumPy、Pillow 和浏览器，无需安装开发环境。启动时会检查运行环境版本是否兼容。

首次选择项目根目录，建筑默认存放于 nbt_models 下，按形状、中文名称和版本归档。项目配置与知识库保存在工作区的 .nbtcreator 中；修改方案保存在当前结构版本的 Agent交接 文件夹。API密钥仍在本机独立加密保存。

项目管理直接识别现有目录：`nbt_models/形状/对象/版本` 归入当前工作区项目；`nbt_models/项目名/形状/对象/版本` 可分项目浏览。bugged 作为待修复分类展示，大量旧文件先建立轻量索引，点击打开或预览时再完整检查；已知损坏文件显示原因，可按“待检查”筛选。默认优先展示每个对象最新保存的非中间版本；“最新保存”不代表已经批准或通过验收。筛选和浏览不会迁移文件。

同项目、同形状、同中文名的交付副本与正式主模型归为一个对象。“仅最新”优先正式主模型，再比较版本日期和修订号，最后参考文件修改时间；“全部版本”保留交付副本并标注来源。左侧文件树支持折叠、方向键导航、双击对象进入编辑，bugged 默认排最后；可拖动、点击上下箭头或用 Alt + ↑ / ↓ 排序，顺序保存在工作区的 `.nbtcreator/project-manager.json`，不移动实际文件。

大型资料库再次打开时先显示 `.nbtcreator/cache` 中的建筑索引，再在后台核对变化；首次扫描时也可切换其他工作区。卡片按批追加，缩略图只在接近可见区域时加载，最多同时处理两项。索引用于浏览，打开模型和执行修改时仍读取、检查实际文件。

首次使用默认进入项目管理；已有启动页选择保留在设置中。索引只保存路径、名称、版本、尺寸等元信息，不载入完整方块数组。已打开模型的元信息会更新到索引，文件变化后重新检查；完整模型和 3D 只在打开对应对象或进入模型编辑时加载。

预览封面默认优先当前几何版本的整体截面图，再选择已有整体视图，忽略单独墙层。选图索引与缩略图保存在 `.nbtcreator/cache/section-covers`，原图、图像说明或模型文件变化时重新选择；浏览时只读取已有图片，不自动批量渲染模型。

旧模型尚无几何索引时，可通过图像说明中的源文件哈希匹配已有预览；兼容 `.json` 和 `.png.json` 两种图片说明。没有当前版本图片时，点击“预览”才生成简化材质的截面示意图并缓存，下次浏览直接复用；不会拿旧版本图片代替当前版本，也不改动建筑文件。3D 中左键拖动以摄像头当前位置转向：向右拖就向右看、向下拖就向下看；中键平移，滚轮沿视线持续前进或后退，可穿过原来的观察目标；相机预设仍可恢复指定视角。在“设置 → 视图与预览 → 3D 视角操作”分别调整转向、平移和滚轮速度（10～300%），独立勾选横向、纵向转向反转；保存后立即应用到现有及新开的 3D 视口，配置随当前工作区保存。100% 保持当前慢速。

项目、形状、创作阶段、版本范围和文件状态均支持勾选多个条件：同组内满足任一条件，不同组之间同时满足。创作阶段包含“未精修／已精修／已定稿／废稿”；废稿默认在列表和文件树中隐藏，勾选“废稿”或“全部”后可查看，重置筛选会再次隐藏。卡片下方可手动标记或恢复自动判断；默认只依据明确阶段记录或精修版本目录判断，不把 `final` 文件夹当作已定稿。手动状态保存在 `.nbtcreator/project-stages.json`，只绑定当前文件版本，文件变化后重新确认，不改动 NBT，也不替代看图确认、精修授权或验收。

项目与资产管理共用紧凑浏览布局：标题与操作、搜索与筛选、左侧目录和右侧卡片保持相同位置。工作区路径和切换入口位于项目页右上的“工作区”菜单；构件按标签和未分类浏览，点击卡片查看详情、整理和放置。所有说明按钮使用统一单圈图标。

项目管理支持多选版本，批量生成截面预览、检查文件和声明路线、标记创作阶段。任务队列显示逐项进度，失败不阻塞其余版本；修复后只重试未完成项，历史和报告随工作区保存。批量完成不等于定稿或游戏验收通过。

命令搜索默认使用 Ctrl+K，也可点击顶部搜索按钮；Alt+1～6 切换工作区。搜索框支持工具中文名和 box、beam 等工具 ID，星标命令优先展示。在“设置 → 操作与快捷键”录入或清除组合键，保存后立即生效；配置位于 `.nbtcreator/commands.json`。输入框保留文本撤销等编辑行为，命令搜索也可从提示词与模型3D视口打开。

构件资产保存在 `.nbtcreator/components/`；在模型编辑的“修改范围”限定选区后，点击“选区存为构件”，再到资产管理选用。默认放置锚点为底部中心，支持坐标输入和3D表面选点，先生成候选再由你导出下一版。回收站可恢复，旋转或镜像不支持的状态会明确提示。

资产管理左侧的“操作配方 / 材质主题”可保存常用工具序列，调整高度、坐标、方块等参数后复用，也可统一映射构件材质。构件详情支持 XYZ 数量与间距，一次放置最多64份；先看3D候选，再导出下一版。配方和主题保存在 `.nbtcreator/reusable/`，可导入、导出和恢复，Agent 通过 `recipes` 与 `components batch` 调用同一套能力。

“AI助手 → 内部 AI → 使用位置 / 工作流”提供四组创作滑块。保存到 `.nbtcreator/ai-style.json` 后，应用与外部 Agent 读取同一份偏好；内部规则与资料仍分别配置，不会随偏好同步暴露。外部可调用 `python .agents/skills/nbtcreator-workspace/nbt.py ai-style prompt --workflow small_structure` 读取对应参数。

## 使用流程

1. 在“提示词方案”创建要求，保存或复制给 Agent 制作完整初稿。
2. 在“项目管理”浏览或打开 NBT，预览后点击建筑进入“模型编辑”，调参或让 AI 生成局部构件。
3. 检查图片、3D 和修改意见，满意后“导出建筑下一版”，保留原稿。3D 的“保护区”用金色显示受保护体积，失败时红色标出触及的位置，可一键定位。
4. 在“任务记录”查看状态，在“设置 → 视图与预览”调整预览、缩放和视图操作，在设置中查看版本和下载更新。

AI 是可选功能，在“AI助手”配置 API；展开详细配置可调整采样、输出长度、超时并编辑请求参数 JSON，保存后用于实际请求。视口截图需要视觉模型支持。生成建议和预览不自动覆盖建筑。

提示词方案按“AI 建模 → 建筑要求 → 工具序列 → 验证上下文”四步组织，可跳过 AI 直接填写。模型编辑会恢复与当前源、参数匹配的未采用 AI 候选；旧版纯文本或已过期建议只供参考，避免误用。设置的“常规 → 界面配色”提供清爽蓝、森林绿、紫罗兰、暖沙色和石墨灰，应用与提示词工作台同步使用，随工作区保存。

应用与 Agent 共用工作区。启动应用后，Agent 可读取工作区的 .agents/skills/nbtcreator-workspace/SKILL.md 调用同一套工具。同一建筑应轮流修改，完成后刷新列表。

提示词方案会自动保存到对应建筑的 `提示词方案/`：已有模型放在当前结构版本内，首次创建放在建筑归档根目录。正文、方案、操作计划和上下文按修订保留，关闭应用前补存。Agent 使用 `python .agents/skills/nbtcreator-workspace/nbt.py prompts scan` 查找，再用 `prompts read --index <index> --id <id>` 读取并核对源版本；旧的 Agent 交接提示词也可扫描。

评论保存或导出时，当前结构版本内会更新 `修改意见/评论索引.json`，原图、3D 快照和引用文件按哈希归档。Agent 可直接扫描：

```powershell
python .agents/skills/nbtcreator-workspace/nbt.py feedback scan --workspace .
python .agents/skills/nbtcreator-workspace/nbt.py feedback collect --version nbt_models/形状/中文名/版本 --output nbt_models/_tasks/意见报告_新编号
python .agents/skills/nbtcreator-workspace/nbt.py validate --request 参数.json --snapshot preview/after.json --output nbt_models/_tasks/候选检查_新编号
```

旧评论可用 `feedback archive --source <完整主模型> --output <新报告目录>` 补建索引和稳定证据；评论不等于精修批准。

## 接着上次编辑

“设置 → 常规”可开启或关闭自动保存与恢复。草稿保存在工作区 `.nbtcreator/edit-sessions/`，使用工作区相对路径；常规退出前会补存最后输入。默认项目页只显示“继续上次编辑”，点击后才加载模型。

恢复候选时会从当前源重新计算，保留尚未预览的参数与上次画面的区别。评论草稿只回到编辑框，点击“保存这条意见”后才进入结构版本的正式评论索引；恢复不自动导出 NBT。原文件变化时，旧草稿保留在独立哈希记录中，不自动应用。

## 更新

“设置 → 更新”可检查 GitHub 稳定发行版，一键下载应用包或完整版并验证 SHA256。下载完成后关闭程序再解压更新，不覆盖运行中的应用。

私有仓库可配置独立的 GitHub 只读访问令牌，与 AI API Key 分开加密保存。

## 开发

源码运行需要 Node.js 24、Python 与 NumPy/Pillow：

```powershell
npm ci
npm ci --prefix .agents/skills/minecraft-nbt-modeler/assets/viewer
python -m pip install -r .agents/skills/minecraft-nbt-modeler/requirements.txt
npm run build:web
npm start
```

```powershell
npm run test:desktop
npm run test:api
npm run test:api-desktop
npm run package:portable
```

详细操作见 [AI 工作流](docs/AI_WORKFLOW_1.8.md)、[共享工作区](docs/SHARED_WORKSPACE.md) 和 [构建发布](docs/CI_CD.md)。
