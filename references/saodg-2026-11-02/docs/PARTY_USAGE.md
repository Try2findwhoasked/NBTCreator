# 副本队伍

0.41.15 起，普通玩家可创建和加入最多 4 人的副本队伍。此队伍复用副本大厅名单，不修改 SAO 原生社交队伍。队长退出会解散大厅，其他成员退出只移除自己；大厅超时或服务器重启后需重建。

1. `/saodg party` 打开队伍页；点击难度创建，或使用 `/saodg party create`（默认试炼）。`/saodg create standard` 可指定难度。
2. 队长在队伍页点击附近玩家的邀请按钮，或使用 `/saodg invite <玩家>` / `/saodg party invite <玩家>`。
3. 被邀请者点击聊天的“接受邀请”或队伍页的“接受邀请并加入”；也可使用 `/saodg join <队长>` / `/saodg party join <队长>`。没有邀请时不能加入。可点击拒绝，邀请最多保留 120 秒。
4. 全员在队伍页点击准备，或使用 `/saodg ready`。成员和难度变化后全部准备状态清空。
5. 队长点击开始，或使用 `/saodg start`。不需要 OP；其他成员不能代替队长开始。按钮不可用时悬停查看原因。
6. `/saodg party leave` 或 `/saodg leave` 退出。

邀请尚未接受时不会变更名单或清除准备。接受时重新检查在线队长、邀请令牌、队伍是否存在、剩余名额与成员占用；旧令牌、重复点击、他人令牌、过期邀请、已关闭队伍均不能加入。每人同时保留一份有效邀请，需要先处理后才能接收另一支队伍邀请。

0.41.21 起按用户要求默认开放开发实例生成和启动，`unrestrictedDevelopmentEntry=true` 时不再要求旧 `enableDevelopmentRuns`、STANDALONE 预设、等级/前置或最低人数。仍需队长开始、全员准备且在线，并通过非和平难度、实际人物状态、实例容量、资产及存档/回程检查。奖励开关独立；默认开放开发入口不表示整合包正式发布验收完成。设为 false 才恢复旧开发门槛。

当前协议为20，客户端与服务器需要使用配套版本；邀请仅驻留服务器内存。0.41.45新增可选小首领日志字段，旧记录缺失时不自动补造小首领；升级/回滚需连同匹配的内容一起处理。

## 原生阵容试跑流程（0.41.53）

1. 更新后启动SAO-0.8，进入用于测试的存档，输入 `/saodg`。标题应显示0.41.53；已有队伍时默认打开准备页，进入副本后默认打开当前区域目标，结算时优先展示本局奖励或战斗报告。
2. 第一次选择试炼，可单人创建；多人先邀请、接受，再全员准备，由房主开始。开始不可用时先看悬停原因，不需要逐个尝试不同开始命令。
3. 从固定入口沿地图橙色主线推进。普通房只需击败星标敌人；清房获得共享钥匙，用于下一道煤炭块门。支路可自由探索，未探索地图只显示相邻一层问号，不提前展开房形。
4. 安装配套SAO与灾变时，默认刷新绿/灰哥布林和尸鬼，使用原生动作与AI；自制战术攻击和粒子预警暂时关闭。既有存档若显式配置过 `customEncounterSkills=true`，保存退出后将其改为false。`nativeEncounterMobs=true` 控制新局使用原生阵容；缺少这两个模组的基础环境使用后备阵容。
5. 守卫型普通房与精英最后一轮会刷新星标小首领，原生池为哥布林酋长和皇家尸鬼。它们是必要目标，不能跳过清房；普通星标怪与小首领不是同一概念。模板随机选择，不保证每局都出现守卫型普通房。
6. 封印大厅保留多轮。清完后先决定是否补支路、谜题与秘密；任一队员进入紫色传送门，就会带本队在线未淘汰成员进入独立最终Boss场地并结束探索。当前原生阵容由徘徊者担任本副本最终首领，按其原生机制战斗，不使用旧守门者的封印阶段；尚不代表灾变所有Boss均已接入。
7. 击败最终Boss后可在奖励箱处查看个人结算，停留或主动返回。外面仍可用 `/saodg rewards` 查看，战绩页保留本局结果。当前正式奖励经济没有开放；关闭奖励的局只保存战绩/合格通关，不会因为点击箱子而补发物品或珂尔。

0.41.52起，SAODG的HUD队友状态默认关闭，可从副本菜单右上角“显示设置”重新开启。发现区域、清房、拿钥匙和波次等自动消息以轻量系统提示卡呈现；首领转场、阵亡和结算仍在聊天留档。邀请接受/拒绝及领取/恢复消息保留原操作方式。关闭HUD后，自动消息继续显示在聊天中。[本轮界面更新与安装记录](validation/SAO_GAMEPLAY_PRESENTATION_0.41.52_2026-10-30.md)。

0.41.53起，右键结算箱聚焦本局：有本局奖励时查看对应奖励，没有可领取物品时查看已保存的本局战斗报告。可从报告确认返回大厅；历史奖励仍可通过 `/saodg rewards` 或个人奖励页查看。原生首领页面显示其战斗目标，不再列旧守门者封印字段。[菜单与结算衔接](validation/SAO_MISSION_FLOW_0.41.53_2026-10-30.md)。

服务器本体与SAO-0.8已备份更新0.41.53，见[原生战斗验证](validation/NATIVE_AI_AND_ROLLOUT_0.41.50_2026-10-30.md)、[UI依赖修订](validation/SERVER_UI_DEPENDENCIES_0.41.50_2026-10-30.md)及[最新启动修复与安装回执](validation/CLIENT_PALETTE_STARTUP_0.41.51_2026-10-30.md)。旧服务器可从 `/sao` 主页点击“副本队伍”，完整客户端保留原主页，直接使用 `/saodg party`。用户已确认新局原生怪显示、清房开门和跨房通行正常。当前SAO-0.8的sao_interface_pack-client.toml仅关闭deathEffects死亡视觉组，以处理实测水晶绘制卡顿，其他界面维持原设置；见[性能记录](validation/CLIENT_FRAME_STUTTER_2026-10-30.md)。第一次测试优先使用测试存档，不要在游戏运行时替换JAR或脚本。地图页在矮窗口可滚动查看队友，HUD显示设置只保存在本机。

## 局域网测试开关

由开世界的人保存退出后，修改其游戏目录下 `saves/<世界名>/serverconfig/saodg-server.toml`，在已有 `[dungeon]` 节设置：

```toml
unrestrictedDevelopmentEntry = true
```

其他配置保持原值，再进入该测试存档并开放局域网。加入方自己的存档配置不控制房主的世界。新版本缺省即为 true；仅当世界显式关闭了该项时才需修改。

0.41.17 起，“开始挑战”悬停提示区分测试开关关闭、整合服预设、和平难度和保存异常，队长与成员都能看到环境阻塞原因；环境允许后，成员才显示队长权限提示。按钮与实际开始命令复用同一份服务端环境检查，保存异常时不会显示可开始。提示也明确给出房主配置位置和重新进入步骤，不自动修改存档。
