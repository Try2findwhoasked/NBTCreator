# 双实例实局隔离与槽位复用

术语同步（2026-10-31）：正文采用现用名称；版本、验证结果及代码/日志原文仍按当时记录。

新增 ConcurrentInstanceGameTest：四名实际 PlayerList 成员、每队两人；先让第一局进入，再生成第二局，遵守引擎一次只生成一张图的限制。两局探索阶段重叠，默认并发上限仍为 2。

## 已实际证明

- 每人经正式大厅邀请、revision 准备、入场与回程；两局占不同槽位，四份回程标记独立保存。
- 双向将一方玩家/敌人和带真实出生租约的箭移到另一方场地，实际 hurt 事件不降低目标生命；同局合法攻击能降血，同局友伤被拒绝。Support/Harm API 对同局合法对象放行，对另一队拒绝；这只证明 API 筛选，未调用 SAO 治疗所有者。
- 外队玩家移到秘密的安全可见近处，先确认触及距离/视线成立，再确认交互被拒绝且没有给另一队秘密或贡献。各玩家界面投影只有自己的实例和冻结名单。
- 第一队仅杀星标得自己的钥匙，另一队不自动清房/得钥匙；一队回程、清理和释放槽位期间，另一队实际确认一次击杀并保留剩余星标。
- 复用已释放槽位，新 runId 改用自有敌人；旧局仍保持其冻结的原版僵尸策略。旧敌人/旧箭引用失去授权，同 UUID 与复制 NBT 的未加入世界对象不能冒充实际自有敌人或造成伤害。
- 第二队继续杀剩余星标，取得自己的钥匙；全部成员回程后，原物品完整 NBT/数量、钱包字段保留，人物文件确认回程维度/模式，所有受管敌人、区块票据及槽位租约释放。

人物最大生命提高、怪物关闭 AI 以隔离权限路径与清理断言；这不证明平衡、性能或实际客户端延迟。只跑了一个两队场景加一次槽位复用，未冒充 50 次完整通关、真实四客户端或完整技能/资产矩阵。

0.41.7 明确补充范围：该无 KubeJS 的夹具以 ForgeData 下的同名钱包字段作为保全哨兵，并未加载原钱包所有者。实际目标 KubeJS 的余额在 KubeJSPersistentData；原钱包真实扣款/读盘需看[独立钱包验证](LEGACY_WALLET_2026-10-28.md)，不能由此处字段保全断言推导。

## 发现与修复

初版同时请求两张图，受到 `generation_busy` 拒绝，日志 `logs/concurrent-2026-10-28.log`；夹具改成先入场第一局再启动第二局。
下一次 `logs/concurrent-sequential-entry-2026-10-28.log` 暴露自有敌人控制器在 addFreshEntity 之前调用严格世界对象身份检查，替换局中止。后续另一队超时是夹具等待该失败造成的结果，不是隔离成功。
修复为保持 UUID 登记及其检查点在入场前，战斗控制器在实际 addFreshEntity 成功后注册；随后设置星标名称，保留自有角色名与普通敌人的隐藏名称规则。严格实际对象校验保留，不退回仅凭 UUID/NBT 授权。

最终命令 `gradlew.bat build runGameTestServer -PgameTestRunDirectory=run/gameTestServer-concurrent-verified-2026-10-28 --offline --console=plain`；`logs/concurrent-verified-2026-10-28.log` 完整构建成功，90 项 JUnit、41 项 required GameTest 全部通过，退出 0，2 分 44 秒。
验证时版本标记仍为 0.40.1；随后仅把产物版本提升为 `0.40.2-dev` 再构建，以区分已在运行的旧客户端。内容仍 `ruins-dev-17`、协议 14，未改变安全房门、封印大厅多轮或独立首领场地。
版本提升后的 `gradlew.bat build --offline --console=plain` 也成功，`logs/concurrent-package-0.40.2-2026-10-28.log`，耗时 54 秒；90 项单测重新执行通过。没有把这次仅构建表述为另一次运行 41 项 GameTest。
当前用户客户端保持其明确授权启动的 0.40.1，不因后台测试强制重启；正式 SAO、真实多人、完整故障/性能矩阵及正式开本仍未验收，付费奖励保持关闭。
