使用现有开发环境 run/client；启动前确认无运行中的 Minecraft Java 进程。命令 gradlew.bat -Dnet.minecraftforge.gradle.check.certs=false runClient --offline --console=plain，日志 logs/client-04110-manual-20261029.log。仅启动客户端，不自动进入世界、修改存档或原整合包，窗口交给用户操作。

本轮实际创建 Minecraft Forge 1.20.1 窗口（启动时 Java PID 18268），08:02:36 纹理资源加载完成；runClient 会话 60850 留待用户操作，不主动关闭/重启。观察到既有 shader/Realms 提示，未以此冒充大厅画面检查。用户随后明确回复“显示正常”：本次大厅准备/开始/退出按钮及成员状态的窗口/GUI 缩放人工检查通过，未记录具体尺寸和缩放值。

本次重点检查：

1. 进入原测试世界，通过 /saodg 创建试炼大厅。缩小窗口或调整 GUI 缩放，检查准备、开始、退出三按钮是否互相遮挡，成员人数、名字与准备状态是否可读。若按钮受开发开关阻断，只能检查当前显示，不擅自修改存档开关或记为完整可操作通过。
2. 封印大厅完成后仍可继续探索。此时 /saodg bossready 应只显示前往紫色传送门的提示，不传送或消耗钥匙；进入真实传送门才到独立首领房，广播/目标说明此动作结束探索。

多人后续再检查：候选超过当前可见行数时，前后页和候选栏滚轮可浏览服务端投影的最多 12 人；成员栏空间不足时独立滚动，满员邀请禁用。单人世界没有候选，不能将空列表当作分页通过。

重连检查点需要存活的服务端实例。关闭单人世界会停止集成服务器并按既有策略中止局，不能用这种方式验证短线重连；实际网络断线/新登录身体仍待专服多人验收。
