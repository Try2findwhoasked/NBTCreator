# 固定星标/普通敌人与精英多轮（0.39）

术语同步（2026-10-31）：正文采用现用名称；版本、验证结果及代码/日志原文仍按当时记录。

历史记录：下列是 0.39 已实际验证的原规则。用户随后要求封印大厅保留多轮，当前规则及新验证见[0.39.1 封印大厅多轮](BLOOD_WAVES_2026-10-28.md)，不再采用封印大厅单批。

按用户要求，普通房与封印大厅改为一次固定生成，只有精英房保留多轮。
源码版本 `0.39.0-dev`、网络协议 13、目录 `ruins-dev-14`，沿用 28 个逻辑房间与 41 份已注册结构，不修改或注册用户 beta 素材。

## 当前规则

| 房间 | 首批 | 后续 |
| --- | --- | --- |
| 普通战斗房（四种配置） | 2 名星标、2 名普通 | 无 |
| 封印大厅 | 4 名星标、2 名普通 | 无 |
| 精英房 | 2 名星标、1 名普通 | 清完首轮星标后等待 60 tick，再生成 2 名星标 |

进入房间后首次生成，无首批等待；重返房间沿用原名单，不补怪。当前开发原版敌人模式继续使用受管僵尸。
星标名称以金色 `★` 开头并常显。只把星标 UUID 纳入清房/轮次目标；普通敌人死亡不会减少星标数量，存活普通敌人不阻止清房与主路钥匙。
普通敌人仍登记、限制在本实例房间、确认真实死亡并在结束时清理；清房后仍会拉回越界的存活受管敌人。
首领阶段限制旧探索区近战影响，沿用原投射物规则。首领与转场守卫仍是必要目标，未取消首领阶段或封印。
房间页与 HUD 区分剩余星标和精英轮次，普通房/封印大厅不再显示多轮提示。

## 数据与兼容

六份 encounter 改为 schema 3 / `ruins-encounters-3`，每批显式 `starred_count`，合法范围 1..count；旧 schema 1/2 缺省全部必要，不允许混用新字段。
目录加载拒绝非精英房的多轮定义，沿用候选整体失败、旧快照保留的策略。生成脚本已同步同一套配置，未运行全量脚本覆盖结构。
封印大厅增加两个刷怪点以容纳六名敌人，不更换结构 NBT。人物/世界主日志仍为原 schema，受管实体追加布尔 `required`；旧记录缺省 true，类型或值非法则拒绝读取，不猜测为普通敌人。
活动局持有旧快照；重启后沿用未完成局中止与回程，不把旧战斗转换成新名单。客户端与服务端均须更新协议 13，人工复测应新开实例。
