# 0.41.58 属性点经验结算与实例回收

## 问题与规则

实际客户端日志显示，实例 `81df7de5-39c8-458a-812e-24db2b22eceb` 和 `aae3d401-b030-450f-b22e-db5c8a0b6126` 都已经进入 CLEANING，却因未知实体中止清理。只读区域文件检查将日志中的 UUID 分别对应到 `sao:points_experience`，其 NBT 带有 Owner 和 Points。它来自 `sao-points-0.75.2.jar`，与 `/saodg exp` 管理的角色经验不同。

用户明确选择：按原模组规则自动结算给归属玩家，再回收场地。不得直接删除未处理经验，也不得将任意同类型实体一律当作临时怪物。

## 实现

- `SaoPointsExperiencePort` 只支持四个固定原生类散列匹配的 sao-points 0.75.2，调用原生 `PointsData.awardReward`，保留原经验换算、余数、等级上限及 UUID 回执。没有复制原模组算法或源代码。
- 只接受实际世界索引中的准确实体、原生类型/类、合法 Owner/Points、当前清理区域与本局成员归属。带未知能力数据、附加 ForgeData、乘骑关系、错误归属或已变更身份的实体保留为未知资产。
- 新增独立 `data/saodg/points_settlement` 原子日志。READY 先保留来源，INTENT 在调用原生入账前记录人物基线；保存并读回匹配后记录 PAID，再移除经验球。PAID 来源回执长期保留，防止原模组 512 条回执环覆盖后旧实体再次发奖。
- 日志保留中的经验球通过原生 Tick/拾取钩子暂停到期和自行领取。等待玩家上线、复活、结束旁观或保存确认时保留实体与清理区块票，不再作为未知内容直接隔离。每 tick 最多处理两笔保存。
- 存储不确定时保留经验球及资产锁；重载后只接受同 UUID 原生回执或完全一致的未应用基线。人物资料不一致时不盲目重发。
- 清理完成仍须通过原来的全区域两遍检查、伴生/投射物/角色经验约束与区块保存，才释放槽位。未知普通物品和容器仍能阻止清场。
- 旧版将 CLEANING 的错误也标成 `preflight_foreign_content`。升级时仅对这种旧原因且有已生成遭遇登记的隔离局排队重检；生成阶段碰撞、没有登记遭遇的实例不自动解除隔离。重检不跳过任何清理检查。
- 新版清理阶段外来资产错误使用 `cleanup_foreign_content`，不再误记为生成失败或改写为 RETURNING。没有空闲场地时，界面能显示具体属性点结算等待原因。

存档主 schema 不变，增加独立侧记日志。运行范围仅作用于已登记结算的经验球，普通世界的原生拾取不被全局替换。日志容量上限为十万来源；达到上限保留源实体并等待处理。
