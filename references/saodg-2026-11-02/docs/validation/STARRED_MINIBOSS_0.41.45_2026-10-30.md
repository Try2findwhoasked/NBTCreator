# 星标小首领刷新：0.41.45

术语同步（2026-10-31）：正文采用现用名称；版本、验证结果及代码/日志原文仍按当时记录。

生产提交 `fada4d3a2ad0`。在0.41.44原版僵尸战术角色基础上，加入独立小首领预算与身份，不将所有星标怪都当小首领，也不把它们当最终首领。

## 玩家能体验的变化

- 使用 `combat_guarded` 的普通房固定批次第一个星标为“回廊守卫长”：基础90生命、5攻击。
- 精英房前一轮保持现状，最后一轮第一个星标为“遗迹冠军”：基础120生命、6攻击。
- 两者均占用原批次中的一个星标名额，不额外叠加敌人或波次；显示星标名称并发送刷新提示。仅在进入实际房间/对应波次时生成，其他普通房不保证出现。
- 小首领沿用其槽位的三种战术角色之一，使用预警攻击；生命只乘一次冻结的队伍人数倍率，原版身体模式也保留小首领自身预算，其余普通僵尸仍为20基础生命。
- 小首领属于清房必要目标：其他星标死亡后仍须击败它，死亡取消、消失、重复回调沿用既有确认规则。没有新增独立物品/珂尔掉落或成功结算路径。
- 封印大厅仍为多轮，完成后由实体传送门将本队带往独立最终Boss场地。既有遗迹守门者、两座封印、守卫与最终阶段保持；本轮不宣称新增第二种最终Boss或替换为未经兼容验证的第三方Boss。

## 数据与兼容

遭遇schema 4允许可选 `miniboss`：`index`、本地化键`name`、`health`、`attack`。索引必须位于已有星标范围内，必须有战术行为配置，一波最多一个。schema 1～3仍支持且不自动生成小首领；旧schema填写新字段会拒绝。两份新内容版本为 `ruins-miniboss-1`。

受管实体日志保存独立 `miniboss` 布尔字段，只有必要非最终Boss可为true；缺失旧字段按false读，不从显示名、玩家NBT或外部标签推测身份。字段错误类型或非0/1拒绝。已有副本重启中止/回程政策保持。旧JAR不认识新遭遇schema 4，回滚运行端时必须同时回滚匹配内容，不混用新数据包与旧引擎。

示例：

```json
"miniboss": {
    "index": 0,
    "name": "entity.saodg.miniboss.ruin_warden",
    "health": 90,
    "attack": 5
}
```

## 实际验证

从固定提交导出执行定向 `MinibossDefinitionTest`、`jar reobfJar`、`runGameTestServer -PgameTestNamespaces=saodg_miniboss`，日志 `logs/miniboss-fada4d3-20261030.log`，正常结束。JUnit XML确认2项、0失败；GameTest日志明确1项执行且通过。

GameTest从实际内容目录寻找含守卫房的有界生成布局，准备少量测试地面/区块后调用生产spawnWave。确认实际原版Zombie小首领、星标名称、双人成员90×1.55=139.5上限；通过EncounterProgress的取消/重复死亡确认检查证明其必要目标身份。此处死亡控制直接调用规则，不冒充真实战斗致死。

同一夹具调用生产spawnWave生成实际最终Boss，确认不同身体、不同房间、不同boss/miniboss身份，再通过RunRecord真实编解码区分两者，并验证旧日志不补造小首领。测试结束清理身体、索引、临时运行记录、测试地面与强制区块。不是整合包完整开本/自然清房/最终阶段/额外掉落验收；精英最后一轮在本轮只通过内容加载和配置规则检查，没有单独实战生成证明。

后续packTest源码生命检查已识别miniboss预算，避免将它错误断言为20基础生命；尚未执行新的原生整合包矩阵，不修改已有0.41.42报告。
