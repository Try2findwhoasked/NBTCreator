## SAO 查询边界

`integration/sao/SaoProviders` 将全部 SAO 类名与反射入口限制在适配包内。
本轮只读取本地服务端 r234 JAR 的公开成员声明，未调用其游戏逻辑：

- `PlayerData.level(Player)`：现有攻略等级。
- `Professions.role(ServerPlayer)`、`NAMES`：职业 ID 与可选显示名，不假定编号永远不变。
- `SocialSystem.downed(Player)`、`DOWNED_TICKS`：濒死状态与等待窗口。
- `SAOTeamManager.teamOf(server, ServerPlayer)`：原生社交队伍，只读在线成员。

查询显式区分 `KNOWN / UNAVAILABLE / UNSUPPORTED / ERROR`。没有 SAO 时使用明确的原版模式；
检测到 SAO 而濒死接口不明时拒绝入场，局内未知状态只有有界等待，不伪造 false。
真正死亡仍根据原对象和事件链确认；濒死查询为 true 时不记阵亡、不结算。
没有调用 `tryDown`，不会重新触发一次濒死或救援倒计时。

开局记录成员显示名、等级/职业查询快照和当时社交队伍身份。
中途换队只提示救援/增益仍遵守原生关系，不改计分板队伍，也不扩大冻结参战名单。
队伍查询没有可靠队长接口，故保持 `leaderKnown=false`，大厅创建者权限不由社交队名推断。
离线社交成员不做在线 UUID 查询之外的网络查名；尚无法解析的数量单独记录。

查询签名存在只显示 `DETECTED_UNVERIFIED`；实际补丁、濒死/救援与多人行为还需后续统一验收。

## 原生救援成功分支

新增可选 `saodg.sao.mixins.json`，目标类名、原生数据字段与字节码定位全部限制在 `integration/sao`。
`SaoMixinPlugin` 只对当前本地 r234 的 `SocialSystem.class` 原始 SHA-256
`4d5dd9b2536adf405a385496da846a6c9cd187e62e890870f852f034d952783c` 启用钩子。
这是版本匹配条件，不是运行认证；重映射后的开发 JAR、其他版本或资源读取失败都不强套本地变量索引。
实际安装的其他变换器、可选 Mixin 挂载与缺 SAO 启动仍待统一验收。

钩子在原生 `tickDowned` 选取候选救援者时调用 `SaodgApi.canSupport`：
双方都在外部世界时保持原生选择；涉及迷宫区时要求同一本局、合法房间路径与可行动的救援者。
它不改社交队伍、原生救援时长或救援者排序，不启动第二次濒死。
仍保留原生的同队、距离、潜行和受击条件。

只有原生救援成功、恢复生命并进入发放原生救援收益的分支，才安排迷宫区证据候选。
在下一 tick 检查同一被救对象仍在线/存活、仍属本局且明确退出濒死；状态未知只等待最多 20 tick。
失败、取消、倒计时末尾再次死亡或重生对象替换不计成功，不能从一个布尔状态变化猜出救援者。
每局对同一被救目标只记一项有效行为；不额外发珂尔、不调整协作分，也不改变已发奖励。

状态诊断区分二进制不支持、钩子尚未观察、候选过滤已观察及成功分支已观察，均不报告 VERIFIED。
缺此钩子时不记录推测救援贡献。正式开本安全阻断继续保留。
通用 `canSupport` 同时提供给 KubeJS `saodg.canSupport` / `global.saoDungeonCanSupport`；
其他技能仍须在自己的实际施加路径调用，不会因为提供了工具函数就自动完成全技能隔离。

## 原生持久宠物租约

源码新增 `CompanionPort`、`CompanionLease`、`CompanionService` 与 `integration/sao/SaoCompanions`。
只读取本地 r234 `PetLedger` / `PetSystem` / `SaoPet` 的公开签名与必要保存布局，未调用本地整合包的游戏逻辑。
原生类名、字段名和台账保存文件名只存在于适配包；纯领域规则不引用这些类型。

原生台账是宠物所有者。`inspect` 同时核对台账记录 `Id`、`Deployment`、`Entity`、原生 `ownsDeployment` 及主人 UUID，
再形成有独立端口 ID 的不透明令牌。复制实体 NBT 不能单独获得局内租约。
入场前捕获原生已出战宠物，先写本局归还意图，再调用原生 `PetLedger.store`，保留其状态/昏迷处理。
无法找到原台账中的出战实体时拒绝入场，不重建宠物、不修改部署号来绕过检查。
无 SAO 时这一步返回明确的空集合；检测到 SAO 但接口/菜单守卫未知时不当作“没有宠物”。

局内在实体加入及有界扫描时登记租约，持久保存于运行记录的可选 `companions` 列表。
每局最多 128 条历史租约；扫描每秒一次、最多 512 个不同实体，不按多格房间重复计数同一对象。
只有仍匹配原台账的 ACTIVE 租约参与权限和攻击归属，贡献交给冻结名单中的主人。
主人濒死/离线/资产冻结时不允许宠物代打；目标选择、友伤、攻击距离房间路径和闭门检查复用实例权限。
核心授权的首领/重连房间传送可带本局宠物到安全落点，其余越界/穿门移动回到上个合法房间或请求原生收回。
实体跨维度许可由具体传送玩家 UUID 限定，不向同一调用栈中的其他实体开放全局许可。

退出、掉线、淘汰、重启中止及清理时，租约按 ACTIVE → RETURN_INTENT → CONFIRMED 流程处理，冲突进入 CONFLICT。
先保存世界意图并持有玩家资产锁，再由原台账收回、通过原生 SavedData 保存、回读 `world/data/sao_pet_roster.dat` 比较原生序列化结果，
最后确认世界租约。协调者不直接覆盖原生台账文件，也不自行 `discard` 既有宠物。
保存不明时保留锁和租约，不回滚、不重复构造宠物。新部署替代旧部署时只撤销旧权限，不直接删除旧对象。
原生自动恢复产生的新对象只有在台账证明仍是同一项原资产时，才可在回程阶段追加归还租约。

找不到实体时按本局已记录位置、原生位置提示及本实例占地清单轮询恢复区块，最多 16 份恢复票据、每 tick 最多两份新加载请求。
只有实体区块加载完成并至少经过两个 tick 才轮换。完整有限扫描仍找不到持久宠物时进入冲突，不当作已收回；不会强加载外部存档。
玩家可先安全回程，宠物未归还确认则实例不能释放；清理始终把宠物视为资产，不能因有租约就删除。
`admin inspect` 显示租约，原 `admin cleanup <run> <reason>` 仅重试身份/归还和现场检查。
面板只同步自己的待确认宠物数量及提示，不暴露其他成员台账或不透明令牌。

`SaoPetAssetMixin` 限定当前 r234 `PetSystem.class` SHA-256
`83c8cb2dc213d4e0530bcb4d35eb43cd6e9dc010c0cd582c407912658df9b057`。
在资产锁期间停止玩家发起的出战、选择、召回、治疗、复活、喂养和模式变更；原生死亡存储与自动恢复仍可执行。
二进制匹配、守卫观察与各适配器反射状态分别报告，均只记 UNVERIFIED。
原生保存 IO、死亡昏迷、恢复部署、缺依赖、两个队伍、多人和原生菜单尚未运行验收，正式开本阻断不变。

当前未把临时 `SaoMount` 灵宠或任意第三方驯服实体当作持久台账宠物。临时灵宠使用下一节的独立出生端口；未知第三方对象不自动获准。

## 临时灵宠出生与原生结束

`CompanionPorts` 按每项租约中固定的端口 ID 路由；持久台账与 `sao:spirit_birth_v1` 不能互相接管。
可选 Mixin 观察新对象 `beginSpiritPet` 的原生调用，核对真实主人、有限时长（1～72000 tick）、实体尚未加入世界、无装备/物品处理器库存与乘客，
并记录新生成的出生 nonce、原生到期时间和能力数据指纹。世界租约先于 `addFreshEntity` 保存；只复制 Owner 或 `saodg` 标记不能产生出生证明。
既有坐骑、未观察到出生调用的实体与其他模组驯服实体都不通过此端口。

调用点早于世界插入但已有原生落点，核心重新检查房间路径、关闭的门、距离及碰撞；非法落点请求原生结束，不给予作战资格。
每成员最多四个 ACTIVE 租约，每局保留最多 128 条历史记录；超限的持久宠物通过原生台账收回，不直接丢弃实体。
NPC 的 Owner、原生生命/攻击数值、召唤消耗与冷却沿用原生逻辑；召唤物不增加人数倍率。

`expireSpiritPet` 的前后钩子分别核对资产安全与实际移除结果，只有确实到达原生结束分支才记录 `native_end_observed`。
带装备、坐骑库存、乘客或变化能力数据的实体会保留现场并进入冲突，原生结束不能借此删除玩家资产。
无法观察结束而实体缺失时，先完成清单内有限恢复扫描；只有原生到期时间已过，才允许撤销纯临时租约的权限。
这一退役不计击杀、不发奖励、不声称写过持久宠物台账，也不授权删除后来出现的对象。
之后清图仍必须加载并检查完整占地，出现未知实体/物品继续隔离；持久台账宠物始终要求原生文件回读。
骑乘与实体精确交互在迷宫区中受保护，原生菜单和资产锁继续生效。

`isManaged` 为旧奖励/缩放补丁保留已登记宠物 UUID/类型的历史抑制，`runId` 与作战贡献仍要求当前有效租约和原生身份。
已结束或冲突的历史记录不能重新授予作战、受益或跨实例权限。

## 宠物技能效果入口

`SaoPetSkillsMixin` 只作用于读过的 r234 `PetSkills.class`：施法和执行入口先检查当前实例身份与可行动状态，
原生区域目标谓词保留原有敌对/同队/范围/视线条件，再追加实例与门路径条件。
伤害、状态、燃烧、击退及速度设置在实际调用前分别重查，避免只在选中目标时检查而漏掉后续效果。
使用已读取的固定 SRG 调用名，二进制不同则不套用；当前源码没有执行构建、Mixin 挂载或实战验证。
原生宠物自增益/自愈仍走原生逻辑，核心不改成长，不采样无法证明的治疗贡献。
`canCast`、`canHarm`、`canSupport` 也提供给服务端脚本；提供查询不代表其他技能已经接入。
职业与呼吸法效果隔离已有下一节源码；其余剑技、目标枪械和实际挂载/运行仍需继续接入及验收。

## 职业与呼吸法的实际效果入口

新增限定 r234 二进制的 `Professions`、`ProfessionExpansion`、`BreathArts`、`BreathMoves` 及 FireShot 读取接口钩子。
只在公开施法/命中入口与实际伤害、治疗、状态、燃烧、速度、传送调用处追加权限条件，不复制职业公式或替换消耗/冷却。
原生队友选择和范围/视线条件先保留，再追加当前实例、冻结成员、合法房间与可行动检查。
治疗和状态按每位实际接收者复查，命中入口在 `Balance.pierce` 等前置处理前拒绝非法目标。
自己已有的原生被动治疗/自增益仍由原生维护；核心不把未知治疗、护盾或控制当作贡献，也不为此额外发奖。

`SkillMovementPolicy` 检查从实际位置到拟定位置经过的占地/房间/门，拒绝跨关闭的门、实例外单元和非有限/过远坐标。
瞬移还检查落点碰撞，成功后更新该实例的合法房间跟踪，后续效果以真实新位置为准。
速度设置保留原生矢量，检查预计的实例路径，普通物理碰撞仍由 Minecraft 处理，不把技能统一改成固定速度。
闪现不能因此跳过共享钥匙或关闭门；原生在房间内部的掩体机制仍按自己的落点逻辑执行。

持续职业/呼吸动作在实际启动时记录实例与维度，同时保存在自己的 `PlayerPersisted.saodg.skill_origins`。
后续 tick 只拦截旧动作的效果函数，原生年龄/冷却递减继续执行，避免取消整段 tick 把职业卡在忙碌状态。
进程重启或重登后可从标记拒绝旧副本未完成施法在外部世界/新局继续生效；旧版无标记数据不被伪造为当前副本施法。

火球私有队列按真实记录对象保存创建实例。倒计时生成新记录时继承旧来源，执行前丢弃跨实例/维度或不可行动的旧记录。
图腾绑定放置时实例，当前队友或角色改变不能重新解释它的来源；原生替换/到期/reset 后释放跟踪记录。
队列跟踪最多 4096 项，停服调用已读过的原生 transient clear，不改角色成长、钱包或持久主线。
原生数据布局、各职业/呼吸法效果、延迟回调、内外世界切换与移动落点均未构建或运行验收。
状态只报告二进制匹配/观察到的 UNVERIFIED 信息，正式开本阻断继续保留。

## 投射物来源与命中隔离

`ProjectileOwnerMixin` 观察真实 `Projectile.setOwner(Entity)` 调用，在主线程捕获源对象、父实体、运行/成员、房间和来源位置。
在世界加入时核对同一个真实对象，才生成新 nonce 并持久登记。仅解析 Owner NBT 不会走这个调用点，不能因此获得权限。
已登记对象还要匹配当前对象引用；只有明确来自磁盘加载且与既有记录/nonce/类型相符，才允许恢复对象引用，普通新对象不能接管旧 UUID。
活动权限按固定 run/parent/player 记录解析，最多八层父链；不在命中时用射手当前队伍或当前位置重新归属。

当前具体类白名单为原版 Arrow、SpectralArrow、ThrownTrident、Snowball。前两者与三叉戟接通原版弓、箭类弩弹和三叉戟物品入口；
弩载烟花与未支持的模组弹药不会通过这一入口，目标枪械仍需要独立适配。雪球白名单只声明服务端弹体路径，不泛化到所有投掷物。
每局最多 16384 项身份历史、256 个已加载的在场或保留弹体，武器入口与松弓前检查预算。
投射物不持有任意物品处理器库存；能力数据变化时保留实体，不按普通杂兵清除。

移动/命中从上次合法位置检查真实轨迹涉及的房间与门，单次移动采样有上限。
伤害优先使用直接弹体的权威身份和实际位置，不能因射手后来移动到别的房间而改变命中权限。
死亡候选在事件发生时冻结来源事实，下一 tick 仍检查最终取消状态与确认死亡，避免弹体随后消失或射手重连导致来源丢失。
已发出的有效弹体保留发射时的参与者证明；不能借此创建死亡后的新弹体或重新授予参战身份。
机关、谜题重置、首领准备、宠物出生和伤害还会即时检查合法房间，周期性越界修正之外也拒绝短暂穿门操作。

Forge `STOP_AT_CURRENT_NO_DAMAGE` 在该基线会直接丢弃箭，故非法命中采用取消效果并按资产分类处理。
不可拾取且无库存、能力指纹不变的已证明临时弹体可持久退役后清除；可拾取箭、所有三叉戟及未知数据对象保留为实体。
在原生箭/三叉戟 tick 和拾取入口追加守卫，避免失效主人、结束阶段或未知归属触发忠诚掉落、跨实例拾取或不受控消失。
拾取要求当前本局身份、合法房间路径、近距离和完整身份/能力条件；未知 ItemEntity 在迷宫区中不允许直接拾取。

## 原物品托管归还与发射扣除凭证

新增独立 `ItemReturnService`，记录目录为 `world/data/saodg/item_returns/`。
目录有 schema 1 manifest，每笔操作按 ID 的 UUID 前缀分片保存为独立原子 NBT 文件，不在每次归还时重写全部归还记录。
来源实体、实例、nonce 派生固定 ID；父实体、原成员、第一位合法收件人、完整物品 hash、能力指纹和 commit 固定。
同一个来源只能有一笔托管；后续触碰不能换收件人、改数据或要求额外数量。

物品来自原生虚方法 `getPickupItem` 的完整保存 NBT，保留名字、耐久、附魔、tag 与 ForgeCaps。
重建/拷贝不能完整往返时不发简化替代品。只有原生 ALLOWED 的物品可自动归还，创意/禁止拾取标记不会被转成免费物品。
三叉戟只接受原成员拾取；箭按合法本局成员拾取条件确定第一位收件人，结束阶段默认回原成员。
托管文件强制写入与回读确认后，才移除同一个已观察、nonce/类型/能力一致的物理对象。
地图可在原成员离线时清理，物品继续由独立日志持有；旧区块副本重现时核对持久来源墓碑并抑制重复拾取/效果。
额外库存、能力或物品 hash 不明的副本保留现场，不能借墓碑删除未知资产。

归还流程为 ESCROWED → INTENT → APPLIED_UNCONFIRMED → CONFIRMED，冲突保留为 CONFLICT。
先核对/保存玩家库存基线，写固定 before/after 意图并持有资产锁，再一次性修改主背包与自己的归还回执。
随后调用原生单玩家保存入口，回读实际 UUID、完整库存和同一回执；确认后再写世界确认并解锁。
背包满、鼠标有物品或其他资产提交者占锁时保持托管。刚加载的无回执 INTENT 只有磁盘/内存均匹配原基线才可重放。
世界确认后保留墓碑、丢弃已转移物品负载，并清理临时玩家回执；旧操作不会因回执清理而重新发放。
归还不改 XP、等级或钱包，也不发布 `rewardCommitted` 或任务事实。

原版弓、弩、三叉戟发射动作另有前后钩子，按实例与真实玩家对象分组分配扣除序号。
世界弹体先记录所需组/序号；原生动作结束后，写玩家扣除进度、保存并读取真实库存，再确认世界中的扣除凭证。
嵌套动作只提交连续完成前缀，重登/重生使用新分组，不会把旧的未完成扣除解释成已支付。
归还前还会读取人物档中的匹配组/实例/进度；缺少旧凭证就保留实体，不因人物档回滚而重复补发。
非玩家父实体的明确服务端资产来源单独标记，未知玩家脚本发射不推测已扣物品。

目录上限为 100000 项去重历史、8192 项待处理记录，新发射为在场弹体预留容量。
托管与实际归还每 tick 各最多两项，自动归还每五 tick 调度；同一成员未确认操作优先，避免被其余待归还队列饿死。
`/saodg itemreturns` 与 `retry` 只查看/重试自己的记录，奖励页显示自己的计数与重试入口。
OP 的 `admin recoveritem <id>` 也只能重试原收件人/原物品，不能强制解除冲突或补建库存。
日志丢失/损坏、临时文件孤立、回执不明或其他资产操作未完成时保持冻结/现场；备份必须包含人物档与全部日志，不能声称跨文件天然原子。

原生发射/消耗、加载、忠诚、穿门、联机拾取、背包满、重复归还、局部保存及崩溃矩阵均未运行验收，当前源码没有构建。

## 可选 KubeJS 插件

`kubejs.plugins.txt` 声明 `SaodgKubePlugin`，编译目标为本地同版 KubeJS `2001.6.5-build.26`。
通用模组入口不引用插件类型；只有 KubeJS 插件发现器加载该类。
它给服务端脚本绑定 `saodg`，不在客户端或 startup 脚本绑定服务器对象。

接口调用在服务器主线程，返回的 NBT/记录是副本：

| 接口 | 行为 |
| --- | --- |
| `apiVersion()` / `generation()` | API 版本与当前注册代际 |
| `isManaged(entity)` | 使用真实登记表，不以复制的 NBT 当授权 |
| `canSupport(source, target)` | 服务器支持/救援资格过滤；不执行治疗，也不替换原生社交条件 |
| `canCast(source)` / `canHarm(source, target)` | 施法与逐目标效果隔离查询，保留技能所有者的范围、消耗和敌友条件 |
| `profile(uuid)` / `party(uuid)` / `member(uuid)` | 只读资料、社交队伍与本局身份 |
| `open(uuid)` | 给在线玩家打开自己的迷宫区面板 |
| `admission(AdmissionPolicy)` | 空字符串允许，非空理由拒绝；null 不算成功 |
| `wallet(RewardTransactionPort)` | 注册独立、稳定 ID 的完整事务提交者 |
| `walletAccess(id, balance, maximum, writer, diskBalance, save)` | 将钱包所有者回调接入共同的预检、回执与玩家文件回读边界 |
| `facts(ConfirmedFactSink)` | 注册必须幂等的持久事实接收方 |
| `questAudience(QuestAudienceProvider)` | 结算时读取接收任务事实的团队身份与路由 |
| `connectFtb(json)` | 验证自有章节/任务后创建可选 FTB 接收器；缺依赖或接口不明返回 null |
| `finish()` | 当前脚本代际注册完成；不等于能力验收通过 |

重载开始即使旧注册失效。开本、事实投递和领奖动态解析当前服务。
钱包端口的每一步均检查代际；旧预检计划不能在新脚本代际继续应用资产。
注册与调用同步于同一状态锁，避免重载线程在检查后切换旧回调。
不同服务器实例使用不同代际号，避免集成服重新开世界后误用旧全局对象。

运行记录在开局保存 `reward_port`，`RewardOperation` 保存 `transactionPort`，旧记录缺省为 `saodg:native`。
操作不能因为切预设或缺脚本就交给另一个提交者；不匹配返回待处理，回执也记录端口身份。
脚本重载时仍可按开局端口准备固定奖励方案，领取等待该端口恢复，不因适配器暂时缺失而丢弃通关结果。
开局预留奖励与事实记录容量，已存在的待处理记录不通过自动删除腾位。
原生端口仍只支持物品与迷宫区 XP、珂尔变更为 0；不接管现有钱包。

## 兼容材料

`compat/kubejs/` 内有四个服务端模块与默认关闭的入场/任务配置。
桥接会在服务端加载/首个 tick 注册当前代际对象，旧函数不会因留在 `global` 中而自动复用。

- `sao_dungeon_admission.js`：迷宫区/难度/等级及可选任务前置，缺实际等级条件时拒绝，而不是猜一个等级。
- `sao_dungeon_bridge.js`：权威受管查询、资产冻结查询、当前代际服务装配。
- `sao_dungeon_wallet.js`：连接钱包所有者回调，也保留 `saoDungeonRegisterWalletPort(port, generation)` 自定义完整端口入口。
- `sao_dungeon_quests.js`：按配置连接内置 FTB 接收器，也保留自定义任务端口入口。

**钱包参与者和 FTB 接收器已提供源码，兼容材料尚未安装及运行验收。**
现有 `saoWalletTransact`/NPC 任务回执不满足通用迷宫区事务契约，因此新增钱包所有者边界，
不把旧交易调用成功当作迷宫区保存成功。缺接入时能力不可用，事实留在 outbox。
接收方不可用时不写重复失败记录；失败投递使用有界退避，不回滚已确认资产。

`compat/patches/` 提供：

- `saodg-managed-entities.patch`：四个旧脚本在权威受管实体上跳过调血/狂暴/额外收入与护甲掉落。
- `saodg-wallet-freeze.patch`：旧商店、强化、存币、回购、战斗入账、任务发款、补发恢复及公共提交入口在迷宫区资产未确认时拒绝改变资产。
- `saodg-wallet-transaction.patch` / `sao_wallet_dungeon_extension.js.inc`：由旧钱包模块提供余额读取、内存资产应用和保存回调。
- `SOURCE_MANIFEST.json`：生成补丁时的源文件 SHA-256，`applied=false`。

本轮只在 SAODG 仓库生成材料并分模块本地提交，没有修改相邻静态仓库、客户端/服务端目录或线上配置，没有推送或部署。
这些补丁也不等于完整隔离：原生 SAO XP 确认/保存、市场与其他模组直接写入仍需对应路径处理；原版统计与旧 KillTask 的当前源码策略见下文，尚未运行验收。

## 钱包所有者提交边界

`PackWalletTransactionPort` 复用原生端口的完整背包预检、迷宫区 XP、固定操作回执和玩家文件回读。
余额字段只由原钱包模块的回调访问；Java 协调者不硬编码旧钱包字段，也不新建第二个币种。
0.41.7 根据实际 Rhino/人物文件检查区分两个命名空间：当前 KubeJS 的 `player.getPersistentData()` 使用顶层 `KubeJSPersistentData`，原钱包不迁移；磁盘余额回调读取同一位置。Java `PackWalletTransactionPort` 在所有者完成余额/库存内存写入后、保存前，将迷宫区 XP/回执写入原生 `ForgeData.PlayerPersisted.saodg`，脚本不再写另一份迷宫区回执。[实际失败与修复记录](validation/LEGACY_WALLET_2026-10-28.md)。
回执的资产哈希包含物品、迷宫区成长及钱包所有者/余额；内存与实际玩家文件均须匹配。

顺序为：固定选择 → 世界 INTENT 保存 → 获得资产锁 → 应用物品/余额/回执 → 钱包所有者保存 →
回读玩家文件 → 世界 ACK 与事实 outbox 保存。预检拒绝时不部分发放，未知保存结果保留锁和原操作。
扩展不会进入旧钱包的“保存失败即回滚”路径；可能已落盘时回滚后重发会破坏幂等性。
重连后仅当磁盘没有回执且资产与新载入玩家吻合，才允许重放缺失应用。
当前内容仍全部珂尔变更为 0；新增端口不等于批准付费档或解除正式开本阻断。

## FTB 事实接收器与独立章节

适配包 `integration/ftb` 只反射本地 FTB Quests `2001.4.22`、FTB Teams `2001.3.2` 与 Library `2001.2.13` 已读取的公开入口。
没有 FTB 时通用模组入口仍可加载；任务配置 `enabled=false` 时不创建接收器。
独立章节提供四个布尔 custom 任务：试炼首通、标准/精锐首通、S+、团队十次通关。
新增 chapter/quest/task ID 记录在 `compat/FTB_CONTENT_IDS.json`；不修改已有主线任务，也不配置重复资产奖励。

连接时确认四项任务属于指定自有章节、最大进度为 1、所在任务无奖励。
接收器先在 `world/data/saodg/quest_facts.nbt` 持久保存带事实 UUID/载荷哈希的 intent，
然后从已收到的合格事实计算目标值，用 `setProgress(task, 1)` 单调更新，不调用累计加进度。
同一 FTB 团队的四名参战者完成同一局，十次通关计数只增加一个 run UUID。

事实保存结算当时的 FTB 团队 UUID 和任务路由哈希，离线成员也通过 UUID 查询。
重试不查询当前新队伍来重新归属；团队消失时保留待处理。
结算时归属未知默认 `keep_pending`，明确选择 `personal_only` 只保留个人事实，不向后来的团队补算。
修改迷宫区/章节/四项目标会改变路由，已有日志必须显式迁移，不能静默重解释。

更新后调用 FTB 原生保存入口，再回读实际团队 SNBT 并比较序列化结果，确认后才 ACK。

## 房间预览与清理

新增源码命令均要求 OP 2：

```mcfunction
/saodg admin preview saodg:ruins/combat_l 90
/saodg admin previews
/saodg admin previewvisit <previewUUID>
/saodg admin roominfo saodg:ruins/combat_l
/saodg admin previewclear <previewUUID> <reason>
/saodg admin cleanup <runUUID> <reason>
```

预览使用固定维度内的独立区域 8/9，与游戏实例的 0～3 槽位分离，最多两份预览。
预约、放置清单、访问者原位置/模式保存于 `world/data/saodg/authoring.nbt`，使用原子写入与回读。
预览不创建遭遇、秘密完成事实或奖励，未用端口封闭。
访问前保存回程，使用 `/saodg leave` 返回；重连先回原世界，不恢复到可能已复用的预览。

放置/清理复用全服世界写入预算。未知实体、容器、物品或其他玩家使清理隔离，
管理员重试也要重新扫描，不提供直接标 FREE 或强制删除未知资产的路径。
游戏槽位的 `cleanup` 命令同样只是重新检查；原来的待领奖和离线回程不会因清图而删除。
制作日志损坏时禁用制作工具并保留原文件，个人回程标记仍可用于安全返回。

这套工具尚未构建或在游戏中运行，旧开发 JAR 不具备这些新命令。

## 自动物品更新与资产保存

资产锁除限制主动操作外，现在还在 `Inventory.tick` 调用 Forge `ItemStack.onInventoryTick` 前暂停原生回调，覆盖主背包、盔甲与副手。
锁释放后调用原回调，不重放暂停期间的 tick，不复制物品实现或模拟耐久/充能公式。客户端及没有 SAODG 资产锁的正常物品更新继续执行。
这是该调用入口的保护，不代表所有模组事件订阅器或直接持有 ItemStack 的异步写入已经覆盖。

EpicACG 的包装 tick 在读取/清理动作前检查资产锁，可选原生 tick 钩子也在 HEAD 检查。
等待保存确认时保留当前动作年龄、冷却与待执行 finish，确认后继续原生下一 tick，由原生 finish 扣除耐久并结束动作。
没有只取消 finish 后让年龄继续前进，因此不会漏过判定斩的 `age == 18`，也不会持续执行细剑/双刀结束前的重复攻击。
原生 reset、失效来源取消与重启恢复策略仍有效；本次没有建立跨重启的独立耐久欠款或补扣系统。

原生背包物品回调、正常物品使用进度回调和 EpicACG cast/tick 还在 `AssetGuard.runAutomatic` 的同步作用域中执行，按服务器与玩家 UUID 阻止嵌套事务取得资产锁。
同一回调内的领奖/原物品归还返回忙碌，宠物收回等待下一次重试；其他玩家的事务不被该作用域阻塞。
作用域使用 try/finally，嵌套及异常退出恢复原深度。正在执行的原生更新不会被中途截图为奖励基线，锁也不能在技能已经开始伤害后才插入收尾之前。

新奖励与原物品归还在 prepare 和实际 apply 前都要求 `!player.isUsingItem()`，否则给出结束物品使用的中文提示，不应用部分奖励。
准备回调结束后再检查一次使用状态，避免在已写意图后才发现新动作；持锁期间直接 `startUsingItem` 入口也拒绝，原生保存回调不能在 prepare/apply 之间插入新动作。
对已恢复的持锁动作，`LivingEntity.updatingUsingItem`、`updateUsingItem`、`completeUsingItem`、`releaseUsingItem` 和 `stopUsingItem` 在锁期间暂停；包含 Forge 的 canContinueUsing/onStopUsing 前置路径，不主动调用 release 或消耗物品来结束它。
已有匹配回执仍可走保存确认，避免等待中的物品使用状态反过来阻止确认解锁。
钱包所有者端口继承原生物品事务准备流程，因此同样遵守新物品使用检查。

这些新增源码均未构建/运行；尤其还需要证明 Forge 实际回调匹配、盔甲/副手更新、嵌套失败与异常退出、原生完整技能阶段和保存故障恢复。
此边界不替代原生 SAO XP 确认、其他自动资产写入与第三方原始对象路径审计。

## 旧击杀目标策略

新配置 `dungeon.allowLegacyKillObjectives=false` 在开局复制到运行记录 `legacy_kill_objectives`。
false 时，受管临时怪不推进原版击杀记分/总数、按实体类型击杀统计、对应玩家击杀进度与旧 FTB KillTask；true 保留原行为。
旧记录缺少字段按 true 读取，不回滚已有统计/任务进度；错误字段类型/取值不静默重解释，配置重载也不修改已经开始的局。
只按权威运行注册表与确切敌人类型判断，普通世界与伪造 `saodg` NBT 不会因此被跳过。

原版统计实际有独立入口：`ServerPlayer.awardKillScore` 管理记分/总击杀和玩家击杀进度，`Player.killedEntity` 另写实体类型统计。
