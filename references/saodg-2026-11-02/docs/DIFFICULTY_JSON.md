# 难度、刷怪 JSON 与地牢等级纪念品

2026-11-02 更新，Minecraft 1.20.1 / NeoForge 47.1.106 / Java 17。

## 配置入口与优先级

首次创建副本时，将随包 `saodg/encounters.json` 复制到游戏目录的 `config/saodg/encounters.json`。默认文件在 `src/main/resources/saodg/encounters.json`，可先复制后编辑。已有文件不会被覆盖。

保存 JSON 后，下一次新建副本自动重读，不要求重启。所有四档预设一起校验；拼错字段、漏填字段、未知实体、越界值、文件超过 256 KiB 都拒绝本次开局，保留原文件，不占用实例槽位。当前副本使用入场时持久化的完整配置快照，重连和恢复不读取新配置。旧版本快照没有 profile 时继续使用原生/房间属性与旧怪物池。

原有 TOML / `/saodg admin config` 仍控制入场楼层、经验、敌人模式、指定数量和最终生命/攻击倍率。JSON 提供细分基础值。`enemyType=AUTO` 在 SAO + 灾变原生适配通过验证时优先使用对应角色的原生怪物权重；未配置原生条目则使用既有原生池。原生模式不混入自制弓手、重装兵、巨像。原生适配关闭或缺失时使用 JSON 后备池；`CONSTRUCTS` 或固定类型优先于 JSON 怪物池。`enemyCount=0` 才使用 JSON 密度。关闭 `supportMobs` 会从 JSON 池剔除弓手、重装兵。

服务器TOML的游戏内写入已与自动解析重载同步，避免同时改动配置表。当前NightConfig版本可能忽略外部编辑器产生的合并修改事件，因此手工编辑TOML后应确认游戏内设置已更新；游戏内管理员入口可以直接保存生效。这一限制不影响上述JSON在新开局时主动重读。实现与实际文件监听验证见[配置重载同步记录](validation/CONFIG_RELOAD_SYNCHRONIZATION_2026-11-02.md)。

JSON 的 `AUTO` 抽签项用于原版/构装体后备路线。为兼容此前已经生成的 JSON，即使旧池主要是自制怪，原生模式也会优先使用既有 SAO/Cataclysm 池，无需覆盖管理员文件。最终 Boss 身份沿用原生适配开关，JSON 只调属性，不替换最终 Boss。其他模组自行计算的技能数值不承诺随基础攻击改变。SAODG 脚本近战读攻击属性，SAODG 弓手箭矢也使用调整后的攻击属性。

## 默认四档基础值

这些数值是本次可调整的初始预设，尚未经过整合包单人/四人实战校准，不代表生产平衡验收。以下为 JSON 基础值，尚未乘 TOML 倍率和房间深度成长。生命不是 SAO 玩家等级，也不修改 SAO 钱包和人物属性。

| 难度 | 普通生命/攻击 | 精英房生命/攻击 | 血房生命/攻击 | 小 Boss 生命/攻击 | 最终 Boss 生命/攻击 | 密度 | 每房生命/攻击成长 |
|---|---|---|---|---|---|---|---|
| 简单 trial | 24 / 3 | 40 / 4 | 36 / 4 | 100 / 6 | 180 / 7 | 0.60 | 1% / 0.5% |
| 标准 standard | 32 / 4 | 55 / 5 | 50 / 5 | 160 / 8 | 240 / 10 | 0.85 | 1.5% / 1% |
| 高难 elite | 44 / 5 | 80 / 7 | 72 / 6 | 260 / 11 | 280 / 14 | 1.10 | 2% / 1.5% |
| 极难 extreme | 64 / 7 | 120 / 10 | 100 / 9 | 420 / 15 | 320 / 20 | 1.40 | 3% / 2% |

例如极难普通敌人在第 6 个布局房间：生命 `64 × 2 × (1+5×0.03)=147.2`，攻击 `7 × 2 × (1+5×0.02)=15.4`。实际属性还受 Minecraft/其他模组属性范围与战斗系统限制。

密度是对房间面积推导数量的倍率，再向上取整。每波 16、每局同时存活 64、全服同时存活 160、全路线可选幸存者 48 的既有预算继续生效；必杀星标数量不会减少。因此较长路线或空间狭窄时，不同密度可能得到相同实际数量，不保证极难每房都多于高难。难度同时由血量、攻击、护甲、怪物池和路线长度体现。

## JSON 字段

根字段必须为 `schema_version: 1` 和 `difficulties`，后者必须包含 `trial`、`standard`、`elite`、`extreme`。每档必须完整包含：

- `density`：0.1–4，数量倍率。
- `healthPerRoom`、`attackPerRoom`：0–0.2，按布局房间索引的线性成长，最多计算 29 次。不是当前波次，也不是 SAO 主线通关层数。
- `roles`：可填 `ordinary`、`elite`、`outpost`、`miniboss`、`boss`、`guard`，对应普通、精英房、血房、星标小 Boss、最终 Boss、阶段援军。
- `entities`：按允许的实体 ID 覆盖普通/精英房/血房数值；小 Boss、最终 Boss、援军继续使用角色值。
- `floors`：以 `"1"`–`"30"` 为键，覆盖该布局房间所有角色的属性。留空 `{}` 使用角色/种类值。这里的层指本副本布局房间序号，不会读取或修改 SAO 楼层。
- `roster`：`{"entity":"saodg:end_golem","weight":6}` 这样的加权项，最多 64 项，权重 1–10000。相同种子、房间、波次产生相同抽签序列。

每组属性完整填写：`health`（0–100000）、`attack`（0–1000）、`armor`（0–30）、`speed`（0.05–0.6）、`knockbackResistance`（0–1）。生命/攻击为 0 表示保留原生/房间值；不提供的角色保持原生/房间基础值。字段覆盖顺序：`floors` → 小 Boss/Boss/援军角色 → `entities` → 普通角色 → 原生/房间值；最后乘 TOML 倍率与深度成长。

例如在某档的 `floors` 内加入：

```json
"6": {"health":160,"attack":12,"armor":10,"speed":0.22,"knockbackResistance":0.5}
```

这表示第 6 个布局房间所有敌人使用这组基础属性，之后仍计算倍率与成长。需要只调整某种怪时，应编辑 `entities`。

## 怪物与大型怪

### 刷怪位置偏好

服务器 TOML 新增 `spawning` 分类，三项均可在 `/saodg admin config` 的难度分类编辑，新副本生效并保存到本局快照：

| 配置键 | 默认 / 范围 | 行为 |
|---|---|---|
| `spawning.bodySpacing` | 0.15 / 0～2 格 | 同波准备生成的怪物碰撞箱之间额外保留的空间。0仍检查实体实际碰撞，较大间距可能使狭窄平台无安全位置。 |
| `spawning.avoidPlayersRadius` | 4 / 0～16 格 | 优先选择存活、可行动、非旁观的本队玩家附近半径外的安全点；没有半径外候选时，选择离最近队员最远的安全点。0关闭该偏好。使用三维距离，不保证隔墙或不同楼层的路径距离。 |
| `spawning.rangedHighGround` | true | SAODG弓手优先使用比最低采样地面高至少3格的平台。玩家避让优先；关闭后按单元占用及怪物间距分布。 |

规则用于普通波次及大型怪放不下时的小型后备选点；最终Boss和阶段援军继续使用既有专用锚点。避让玩家是候选排序，不会为了凑半径跳过完整实体碰撞、地面、房间归属或已加载区块检查。候选之间同分时仍按本局种子抽签；玩家位置变化会影响新波次选点。

遭遇配置快照升级为版本3，保存上述三项；版本1/2旧局继续使用历史间距0.15、关闭玩家距离偏好、开启弓手高台偏好。新版本快照缺失字段或越界时拒绝读取，不静默修补。管理员改配置不会改变已有副本的规则；回退旧模组版本无法读取新版遭遇快照。

允许的原生条目为 `NativeEncounterIds.ORDINARY` / `MINIBOSSES` 中已核验的具体 ID，包括 SAO 哥布林守卫、末影类怪、骷髅战士、哥布林酋长，灾变 `cataclysm:draugr`、`cataclysm:royal_draugr`。普通怪与小首领分别抽签，最终 Boss 不进入随机池；缺少原生适配时跳过这些条目。`entities` 同样支持这些已核验原生 ID。

允许的后备怪物：`AUTO`、`saodg:ruins_enemy`、`saodg:ruins_duelist`、`saodg:ruins_channeler`、`saodg:ruins_archer`、`saodg:ruins_brute`、`saodg:ruins_warden`、`saodg:end_golem`，以及 `minecraft:zombie`、`minecraft:husk`、`minecraft:spider`、`minecraft:vindicator`。`AUTO` 只能用于怪物池。

新增重甲卫士与末地巨像使用独立 SAODG 实体身份；末地巨像使用本项目守卫模型和原版末地石材质，碰撞体宽 2.4、高 6 格。2026-11-02 起默认池改为 SAO/Cataclysm 原生怪物权重；巨像保留为显式可选后备，不再默认混入原生模式。极难巨像基础生命 300、攻击 22、护甲 12、速度 0.16、击退抗性 1；重甲卫士基础生命 150、攻击 11、护甲 14。

大型怪必须通过现有地面、房间归属、完整实体碰撞与分散生成检查；放不下时替换为小型遗迹敌人，保留星标身份，不扩大或破坏建筑。它不是最终 Boss，也不沿用其他模组末地傀儡的代码或资源。窄门导航、外观与实战难度仍须真实客户端验收。

## 地牢等级奖励

独立地牢等级仍为 1–20，累计经验阈值 `100×(等级−1)²`。领取经验奖励时，每跨过一级发放一枚 `saodg:level_memento`（地牢等级纪念章），附等级和获得者 UUID。一次升多级会逐级发放；已有高等级玩家不追溯补发。纪念品可转移，UUID 是纪念记录，不是绑定限制。

纪念章只有展示意义，不增加战斗属性、货币或额外经验。纪念章、经验、原有物品和回执在原奖励事务一起写入；背包不足时全部暂缓，腾出空间后重试。领取同一事务不会重复发放。原有奖励总开关和资格规则继续有效；使用继承原生事务端口的整合包钱包时同样生效，自定义独立事务端口需实现相同奖励契约。

## 显示配置与生成效率（2026-11-02）

显示设置保留在 SAODG 指令体系：`/saodg display` 或 `/saodg config display`。这是客户端本机命令，无需管理员权限，不修改服务端规则；管理员规则配置仍为 `/saodg admin config`。本机显示配置仍写入客户端 TOML，怪物 JSON 只承担战斗配置。

布局搜索按模板/旋转预编译形状、门口与门口几何，搜索候选不再重复构造字符串和旋转门口。不会跨内容重载复用旧缓存；仍保留原搜索上限、优先级、连通/钥匙/隔离校验和种子规则。建筑准备复用每房原点与一次旋转结果，用原生 long 集合去重区块，减少逐方块临时对象。检查点按区块分组，以便提前完成已加载区块的预检。没有调大每 tick 方块预算或跳过异物/空气位置检查。原有 `dungeon.blockChangesPerTick` 仍可在 `/saodg admin config` 的性能分类调整（默认 2048，上限 8192）；这影响放置吞吐与服务器负载，布局加速比例不能直接当作总建造时间的加速比例。

`SAODG generation plan` 日志新增 `layoutMs` 与 `preparationMs`；`run entered` 继续记录 `generationTicks`。据此可以区分布局搜索、建筑计划准备和分 tick 放置的耗时。小样本布局对照结果与实际验证范围见 [NATIVE_ROSTER_GENERATION_2026-11-02.md](validation/NATIVE_ROSTER_GENERATION_2026-11-02.md)。
