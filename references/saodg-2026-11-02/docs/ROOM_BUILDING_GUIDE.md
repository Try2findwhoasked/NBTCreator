# SAODG 房间结构制作指南

想先看简单操作，打开[一页可视化指南](structure-guide.html)。

2026-10-30 用户已选结构的接入结果、原图册编号、分类、来源与未通过原因见[已选房间注册目录](validation/SELECTED_ROOM_IMPORT_2026-10-30.md)。可用 `/saodg admin rooms selected` 查看已加载的精选房间，或用 `/saodg admin rooms cross`、`/saodg admin rooms waterworks`、`/saodg admin rooms 001` 按形状、主题、原编号筛选；目录条目可点击填入 `roominfo` 命令。

后续0.41.63-dev接入三套无外门2×2 Boss场地、开侧门的固定鸟居安全房，以及带尖拱传送门生成的固定符文封印大厅。`/saodg admin rooms boss`、`safe`、`outpost`、`runes` 可按角色/主题查询；[源文件、协议扩展与实际验证](validation/BOSS_SHRINE_RUNE_0.41.63_2026-10-30.md)。

适用 Minecraft Java 1.20.1，配套[完整方案](DUNGEON_DESIGN.md)。当前0.41.47支持定义加载、多格拼接、声明旋转和独立预览；schema 4的 `door_y` 配置门高，schema 5可使用稀疏主体/墙层合成分片。实际通行和方向性方块旋转仍需逐房检查，精选refined房间目前只声明0度。

使用技能导出的分层文件时，在schema 5的parts中填写 `body_template`、`wall_template`、`offset`，不要再同时填写 `template`。两层同尺寸、同原点、不重叠且省略空气；加载器先合成完整体积，再按原流程检查与放置。旧schema与完整template格式仍支持。[完整示例、refined来源和验证范围](validation/REFINED_LAYERS_0.41.47_2026-10-30.md)。

## 1. 先做一间单格房

在单独的创造存档制作，先选原版石砖、深板岩、木材和装饰。当前导入器只接受 `minecraft:` 方块，不导入实体或方块实体NBT，具体禁用项以内容加载器为准。做完整房间模板，不需要手工搭出整座随机迷宫。

| 项目 | 第一间房的标准 |
| --- | --- |
| 外部占地 | 48×48格，包含外围墙 |
| 导出高度 | 24格，可容纳地板、装饰和顶棚 |
| 局部范围 | X/Z为0～47，Y为0～23 |
| 地面 | 走道地板方块位于局部Y=1，玩家脚部位于Y=2 |
| 门口 | 6格宽、5格高；同一逻辑房间所有外门共用一个局部门高 |
| 第一间类型 | 东西贯通的普通战斗房 |

局部原点选房间西北角的最低保存方块。东为+X，南为+Z，向上为+Y。建筑可以有曲线、斜边、洞穴外观或内部高低差，但外部端口必须满足统一规格。

此前草案的5格宽门已改为6格宽：48格模板的几何中心位于23与24之间，居中的偶数宽开口便于四方向旋转后严格对齐。

上表是第一间房的简化例子。模板高度可为 8～48；需要地下室或更高楼层时，按第3节设置 `door_y`。实际生成以 49 格为相邻单元原点间距，在两个 48 格模板间留一格连接；引擎铺连接地板、开墙，主线煤炭门位于中间，未使用出口封石砖。同一多格房的内部连接不设钥匙门。制作时不用把连接缝烤进 NBT。

### 墙面NBT与49格间距

48格是包含外墙的模板占地，49格是运行时相邻单元的原点间距。例如A模板占世界X=0～47，B模板占X=49～96，X=48是一格接缝；不能把房间或单片墙面导出成49格来占用该接缝。

当前推荐使用schema 5的两层形式：每个有效单元的主体和墙面各一份同尺寸、同原点的稀疏NBT，在同一项 `parts` 中填写 `body_template`、`wall_template`、`offset`。两层省略空气，方块坐标不能重复或重叠；加载器先补空气并合成完整分片。这是按原模型墙mask分层，不是将一张墙片自动旋转铺到所有边界；也不包含独立门NBT，门洞连接和门禁仍由程序处理。

也可以单独制作墙面NBT作为普通素材，例如48×H×1，合并进完整房间，或与内部按互不重叠的空间划分声明为普通 `parts`。普通分片包括空气也不能重叠，合起来必须完整覆盖所声明房间体积；不能在一个已含全体积空气的完整房间NBT上再叠加墙面分片。

单格房可以拆成5片：南北墙各48×H×1，东西墙各1×H×46以避开四角，内部为46×H×46并包含地板、空气和所需顶面。该划分只是尺寸示意；端口、门高和完整房间定义仍需对应实际模型。`parts`没有独立旋转字段，整间房的声明旋转由引擎统一处理。

相邻的两个独立房间各自保留模板内的墙，程序只按实际连线处理标准门洞、连接及门禁。未连接的门洞在生成时连同房间内侧墙厚一起补齐：按每个高度、每个深度，从门洞左右各最多3格内的完整墙块取材，左右半边分别衔接对应墙面，保留已有完整墙块；最多向内探测8格，内侧任一边没有合适墙块时停止。外侧必须封实，缺少同高度材质时尝试上下2格，仍无可用材质则回退石砖。容器、流体、重力方块和非完整碰撞方块不作为复制材质。此处理支持旋转和自定义门高，只影响新生成实例的未连接出口；已连接通路、钥匙门及虚拟传送入口沿用原逻辑。

多格大房应按整个逻辑房间设计外轮廓；内部是否留墙由模型决定。内部接缝按模板边缘延伸填补，不会自动拆除整面内墙。开放大厅也必须确保必要跨片路线实际可走，不能只删除内墙就假定接缝全幅连续。

## 2. 可以制作哪些形状

`#`表示占用一格48×48单元，`.`表示不占用，不是把该位置填为空气。

```text
单格       长条       大房       L形       T形       十字
#          ###        ##         ##        ###       .#.
                      ##         #.        .#.       ###
                                                     .#.
```

- 单格、1×2、1×3、1×4、2×2、L形、T形、十字都可使用同一占地模型。
- 每个形状是一个逻辑房间，多片共享清怪进度、秘密与完成状态，不会自动变成多间小房。
- 一个单元可以是开放大厅的一部分；内部不必每48格都有隔墙。只在房间对外连接处留标准门口。
- 形状必须四邻接连通且放得进迷宫区网格；不连通的“飞地”首发不支持。
- 占用单元内部可以建任何可通行轮廓。引擎按整格预留空间，不会自动按建筑的每块轮廓把多个房间塞到同一格。
- L形缺角可供另一房间占用，因此分片不能把外接矩形中的缺角空气一并覆盖。

例如L形外接2×2，但实际只占三格：

```json
{
  "footprint": [2, 2],
  "cells": [[0, 0], [1, 0], [0, 1]],
  "parts": [
    {"template": "saodg:ruins/l_room_01/p00", "offset": [0, 0, 0]},
    {"template": "saodg:ruins/l_room_01/p10", "offset": [48, 0, 0]},
    {"template": "saodg:ruins/l_room_01/p01", "offset": [0, 0, 48]}
  ]
}
```

这是现有格式的占地/分片片段，完整定义还需类型、尺寸、旋转、端口和标记等字段。`template`单文件简写与`parts`多文件形式互斥，其他机关坐标相对于整个逻辑房间原点。

## 3. 门口怎么留

默认 `door_y=2` 的单格房端口闭区间坐标如下，范围内保持空气，脚下地板位于局部 Y=1。

| 朝向 | 开口范围 |
| --- | --- |
| 西门 | X=0，Z=21～26，Y=2～6 |
| 东门 | X=47，Z=21～26，Y=2～6 |
| 北门 | Z=0，X=21～26，Y=2～6 |
| 南门 | Z=47，X=21～26，Y=2～6 |

需要改变门高时使用 `"schema_version": 4, "door_y": H`：所有外门的 `min.y=H`、`max.y=H+4`，脚下地板在 `H-1`；`H` 为整数，范围 `2～height-6`。不同房间可以用不同的 H，同一逻辑房间的所有外门必须一致。引擎将整个模板放在世界 `Y=66-H`，使外部门洞统一对齐世界 Y66～70。到达点、刷怪、机关和秘密都填写原始局部坐标，不要预先减 H；引擎一起平移，不自动建内部楼梯。

例如模板高 32、`door_y=10`，门洞局部 Y10～14、地板 Y9；生成时结构基底为世界 Y56，门洞仍在 Y66～70。若在制作世界以 Y64 为模板原点建造，保存前门洞会在该世界 Y74～78，这是正常的；导出后由引擎对齐。旧 schema 1～3 与省略 `door_y` 的房间保持原高度。

墙厚超过1格时也要把门后走道打通，不能只挖外墙。门边至少留足无装饰碰撞的落脚空间，先用玩家实际走通测试。

不要求所有墙面都有门：一门尽头房、对向双门、转角双门、三门、四门都是合法模板。生成器只匹配声明且真实可通行的端口，未使用端口后续由引擎封闭。

多格房可以在多个外围单元上开口，例如长条的两端或L形的三个外端；不能把两个同房间单元之间的内部通道声明成外部端口。凹边端口也需严格匹配相邻空单元，具体组合受生成器校验。

## 4. 第一间房的具体坐标例子

假设房间原点为世界坐标 `(0,64,0)`，则保存范围为 `(0,64,0)` 到 `(47,87,47)`。

以下命令只应在空白制作区域执行，它们会替换对应范围方块；不要在已有建筑或正式服执行。

```mcfunction
/fill 0 64 0 47 65 47 minecraft:stone_bricks
/fill 0 66 0 0 77 47 minecraft:stone_bricks
/fill 47 66 0 47 77 47 minecraft:stone_bricks
/fill 0 66 0 47 77 0 minecraft:stone_bricks
/fill 0 66 47 47 77 47 minecraft:stone_bricks
/fill 0 78 0 47 78 47 minecraft:stone_bricks
/fill 0 66 21 0 70 26 minecraft:air
/fill 47 66 21 47 70 26 minecraft:air
```

之后自由装饰内部：柱子、高台、掩体、小侧室与秘密入口都可以。保留至少一条连接所有必要目标的可靠路线，避免只能靠特定职业位移通过。

第一间先放4～6个“预定刷怪位置”，用记录坐标或临时彩色方块帮助设计；导出前移除临时标记。不要预先保存真实怪物、掉落物或刷怪笼来实现清房，怪物以后由SAODG按实例生成。

## 5. 用结构方块导出

获得结构方块：

```mcfunction
/give @s minecraft:structure_block
```

以上述房间为例，把结构方块放在 `(-1,64,-1)`，位于保存区域之外，切换为SAVE模式。

| 字段 | 填写值 |
| --- | --- |
| 结构名称 | `saodg:custom/combat_first` |
| 相对位置X/Y/Z | `1 / 0 / 1` |
| 大小X/Y/Z | `48 / 24 / 48` |
| 包含实体 | 关闭 |
| 显示边界 | 开启，核对整房及地板/顶棚 |

点击SAVE保存到文件，不能只关闭界面。普通方块与楼梯等建筑可以保存；当前导入策略暂不接受箱子等方块实体，奖励使用个人面板。真实怪物、掉落和临时标记盔甲架不应成为模板内容。

Java版结构方块每轴最多保存48格；96格大房需要分为多个不超过48格的片段。[官方尺寸变更说明](https://www.minecraft.net/en-us/article/minecraft-snapshot-20w16a)

保存路径为制作存档内：

```text
generated/saodg/structures/custom/combat_first.nbt
```

此命名空间保存路径见[官方结构保存说明](https://www.minecraft.net/en-us/article/minecraft-snapshot-17w43a)。本项目针对1.20.1，目录使用复数 `structures`，不要照新版本教程改成其他目录。

若使用SAO-0.76版本隔离目录，存档通常位于 `D:/Minecraft/.minecraft/versions/SAO-0.76/saves/<制作存档名>/`；实际以启动器该实例的存档位置为准。

## 6. 大房和L形怎么分片

整间房可以连续建造，再按固定网格导出；不要为了导出在内部额外加墙。每片保存相同高度，片与片不重叠、不漏一列。

| 片编号 | 相对于逻辑房间原点的偏移 | 片大小 |
| --- | --- | --- |
| p00 | `[0,0,0]` | `[48,24,48]` |
| p10 | `[48,0,0]` | `[48,24,48]` |
| p01 | `[0,0,48]` | `[48,24,48]` |
| p11 | `[48,0,48]` | `[48,24,48]` |

2×2大房使用四片，L形只导出p00、p10、p01，缺角p11不导出。1×3沿Z的长条偏移为 `[0,0,0]`、`[0,0,48]`、`[0,0,96]`。

这里的分片偏移仍使用作者的 48 格逻辑网格，不要改成 49。引擎在世界放置时展开为 49 格间距并连接内部接缝。多格房所有分片共用相同高度与 `door_y`。

四方向旋转的是整个逻辑房间：占地、每片位置、模板自身方向、端口和机关一起变换。只需保存一个标准朝向，再用预览命令逐个验证四种旋转，不必手工制作四套 NBT。

## 7. 建筑之外需要记录什么

交付建筑时附坐标说明，或直接编写下节的 JSON。至少记录：

- 房间ID、类型、模板文件、实际占地形状和原点。
- 对外门口位置、朝向与 `door_y`，内部通路是否有特殊高度。
- 玩家安全落点、预定刷怪点及分组。
- 精英/波次目标、开门条件，哪些怪必须击败。
- 秘密入口和交互方块坐标，谜题说明与答案规则。
- 所有模组方块及其依赖，是否有方块实体、多方块结构或特殊旋转需求。

坐标统一写相对原点的局部坐标。例如世界 `(12,66,18)` 对原点 `(0,64,0)` 为 `[12,2,18]`。同房多片的机关坐标仍使用整个房间原点。

普通彩色方块、名字和告示牌不会自动变成刷怪/秘密标记。建筑和定义必须配套；到达点及刷怪位置上方留足空间，秘密/谜题装置使用定义要求的真实方块。

## 8. 预览与交付

先用另一个原版结构方块在空地LOAD同名结构，测试复制与0/90/180/270度旋转。旋转后的原点变化要看边界，不能只看结构方块所在位置；正式拼接由SAODG统一归一化坐标。

交付检查：地板/顶棚完整、门口贯通、没有临时标记/怪物/掉落、秘密可达、不需要唯一职业、复杂方块旋转正确。大房先检查各分片在原朝向拼起来没有断层，再测试整房旋转。

模板放入 `src/main/resources/data/saodg/structures/...`，配套定义放入 `src/main/resources/data/saodg/rooms/...`；也可通过同路径数据包提供。模板资源名 `saodg:custom/combat_high` 对应 `data/saodg/structures/custom/combat_high.nbt`；房间 ID `saodg:custom/combat_high` 对应 `data/saodg/rooms/custom/combat_high.json`。[Forge结构模板文档](https://docs.minecraftforge.net/en/1.20.1/misc/gametest/)

下面是高门洞、东西双门、无秘密的普通战斗房完整定义示例。它引用现有波次；需要实际制作相应的 48×32×48 NBT，保证各坐标处有安全地板及通路，此处没有自动提供该建筑。

```json
{
  "schema_version": 4,
  "type": "combat",
  "template": "saodg:custom/combat_high",
  "footprint": [1, 1],
  "size": [48, 32, 48],
  "door_y": 10,
  "rotations": [0, 90, 180, 270],
  "ports": [
    {"id": "west", "min": [0, 10, 21], "max": [0, 14, 26], "facing": "west"},
    {"id": "east", "min": [47, 10, 21], "max": [47, 14, 26], "facing": "east"}
  ],
  "spawns": [[16, 10, 30], [31, 10, 30], [16, 10, 36], [31, 10, 36]],
  "arrival": [24, 10, 24],
  "secrets": [],
  "secret_scenes": [],
  "enemies": 3,
  "health": 30,
  "attack": 3,
  "encounter": "saodg:ruins/combat_light"
}
```

把新房间 ID 加到 `data/saodg/dungeons/ruins_01.json` 的 `layout.room_pool`；保留原有必需入口、安全房、封印大厅、首领等定义。只放 NBT/房间 JSON 不会自动加入目录，当前加载器按房间池加载。使用数据包覆盖迷宫区定义时，基于当前版本完整文件增加条目，不要只提交一段 `room_pool`。

精选结构可附加可选 `identity`：`display_name` 为中文语言文件中的翻译键，`catalog_ids` 为原图册编号数组，`source` 为交付目录相对路径，`shape` 为实际单元形状，`theme` 为建筑主题，`connections` 为出口分类。加载器会核对形状和实际 `cells`，并核对出口类别与 `ports`，标签不匹配会拒绝重载；旧房间可不填该字段。该信息供管理员识别建筑，不改变 `type` 的玩法规则，也不会把未探索内容发送给玩家。

在独立制作世界执行 `/reload`，然后用 OP 2 权限检查与预览：

```mcfunction
/saodg admin validate
/saodg admin roominfo saodg:custom/combat_high
/saodg admin preview saodg:custom/combat_high 0
/saodg admin previews
/saodg admin previewvisit <预览UUID>
/saodg leave
/saodg admin previewclear <预览UUID> checked
```

`preview` 返回预览 UUID，等待 `/previews` 状态为 `READY` 再进入；`previewvisit` 要求不在大厅/活动局中。`/saodg leave` 从预览返回原位置及模式，`previewclear` 排队清理预览。一次最多保留两个预览，检查完一个先清理，再分别检查 90、180、270 度。不能直接把未替换的 `<预览UUID>` 占位符输入命令。`validate` 展示目录加载结果和最近错误，不代替逐房通行或随机种子验收；重载失败保留旧有效目录，应修正错误后重新加载。

新谜题房可使用房间 schema 2 的 puzzle_scene，具体字段见 DEVELOPMENT.md 的“房内交互与谜题表现”。

数学 NPC 房另用 schema 5：`"puzzle":"math"`、`"math_npc":[x,y,z]`、`"puzzle_controls":[]`，不填写 `puzzle_scene`。NPC 标记及上方两格必须为空气，下方必须有可落脚地板；NPC 由运行服务生成，不能写入 NBT 的 entities。普通谜题的三控制点规则不套用于数学房。随机题库、三道基础通关与两道可选奖励规则见 [挑战大积霸](CHALLENGE_MATH_MASTER.md)。

`balance`、`flow`、`circuit` 使用 schema 5，必须声明物理 `puzzle_scene`。三个 `puzzle_controls` 在模板中依次为红、绿、蓝羊毛；`indicators` 分别为 1/3/3 个灰色羊毛点。`circuit` 额外声明 7 个切制铜块 `terminals`，顺序固定为 U1、V1、W1、U2、V2、W2、STAR；控制器顺序为 U2、V2、W2。机关、指示点和端子上方至少两格空气，均与线索、复位、秘密和其他标记分离。加载器核对实际源方块，运行时只更新受管羊毛点。

接触器控制台采用 KM1 主接触器、KMY 星形接触器和 KMD 三角形接触器。初始 KM1 断开、KMD 闭合；断开 KMD 后合上 KMY 即清房，可以直接离开。可选右键启动台（或合上 KM1）进行星形启动，等待100 tick后断开 KMY，再等待10 tick合上 KMD，成功后每名合格成员通关基础奖励默认增加60副本经验/房。星形/三角形互锁；过早操作被拒绝，无爆炸或雷击。KM1可停机，保留清房；停机后重新准备星形可重启，重新计算加速时间。追加成功后锁定，每房一次；保留原有奖励资格和事务。 详见[玩家操作说明](CONTACTOR_ROOM.md)。
青金石为线索装置，红色陶瓦为重置装置，必须实际保存在模板中并与其他标记分离；光路房另用钻石/金块表示入射/接收端。
镜面按三控制点的固定图布置，保留规定高度的空气通道，所有标记交给统一变换旋转；不要把唯一答案、未发现秘密或整张地图坐标写进通用客户端投影。
原有 schema 1 手工房仍可使用旧兼容入口，新字段需明确升级 schema；使用 `door_y` 时升到 4，且每个秘密都需对应一项 `secret_scenes`，无秘密也写空数组。已有 28 房/112 朝向的历史实体验证见[记录](validation/ROOM_TRAVERSAL_2026-10-28.md)，自定义门高的验证见[记录](validation/ROOM_HEIGHT_ENTRY_0.41.21_2026-10-29.md)；新建筑仍需自己的通行和旋转检查。
