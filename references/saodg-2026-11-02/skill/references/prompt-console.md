# 建模提示词工作台

Windows双击skill根目录的 `启动网页细节控制台.cmd`，点击左上“建模提示词 · 当前建筑与工具参数”，在控制台内打开提示词编辑面板。旧 `启动建模提示词工作台.cmd` 兼容入口也进入同一细节控制台。页面与模板代码继续集中在 `prompt-console/`，不复制两套实现。

首次打开面板时载入当前已打开建筑、源文件哈希、真实尺寸、坐标/保护配置、相机和控制台当前参数；后端复用compile_plan，因此混材强度、局部选区、结构编辑、风化和自动地面的操作顺序与原控制台一致。导入状态默认“只读修改规划”，不凭打开网页推断精修授权。

关闭/返回面板保留文字与步骤草稿，细节控制台当前参数不变；再次打开不会覆盖草稿。点击“载入当前建筑与参数”明确重新载入，会替换提示词工具序列。切换到另一建筑后重新载入会重置上一建筑的要求与上下文，避免串版本；同一建筑保留设计要求。源内容变化会拒绝载入，需先重新打开建筑。面板修改只用于文本/计划，不反向写控制台参数，也不直接应用NBT。

仍可直接用浏览器打开 `prompt-console/index.html` 作为无依赖的离线备用入口；离线页不读取模型。两种模式都只生成任务文本与参数文件，不计算效果或写NBT。

## 使用

1. “建筑要求”填写阶段、名称、主题、整体尺寸、完整源路径与输出目录，分别修改天花、地板、墙面、道具和保留项。选独立建筑或SAODG接入，不强加统一占地。
2. “工具序列”按需添加18类工具；几何另含12种原语/布尔形状。数值、坐标、开关直接编辑，多点曲线、权重和复杂选区使用JSON。每步可以上下排序、复制、删除；高级完整JSON可补充后端支持的可选参数。
3. “验证上下文”填实际cells/door_y、玩家脚位start、targets、ports、interior_probes、protected_paths/boxes、route_legs与cameras。未知项留空；导出的context_draft.json是草案，不能直接当已验收配置。自动地面用include_boxes限定区域，不传不支持的lo/hi。
4. 复制完整提示词交给agent，或下载Markdown。`plan.json`含style_note与有序operations；`nbt_prompt_settings.json`包含全部建筑要求和参数，之后导入即可复用。两者用途不同，网页只导入自身schema_version=1的方案。

当前版本可直接编辑的默认完整提示词见 [完整模板](../prompt-console/完整可编辑提示词.md)，18类工具的起始参数见 [参数目录](../prompt-console/工具参数目录.json)。参数目录是参考清单，不建议整份作为操作序列执行；每个坐标、材质和预算都要对照实际建筑修改。日常维护以core.js内的defaults/catalog/prompt为共用来源，同步模板和目录。

浏览器自动暂存有效方案，正式保存请下载JSON；更换浏览器或移动页面后暂存不保证保留。页面不验证注册表、真实几何、碰撞、支承或保护区，也不制造确认记录。只读规划、新建初稿、已有建筑精修的提示词分别说明阶段；文件中的参数和文字不等于用户已看图批准。

## 维护验证

页面用原生HTML/CSS/JS，classic script支持file://离线打开，没有CDN或第三方前端依赖。已有viewer的Playwright仅供开发测试，日常用户无需安装。

```powershell
node .agents/skills/minecraft-nbt-modeler/prompt-console/test-console.mjs build/prompt_console_<全新编号>
```

合成浏览器回归检查全部工具渲染、参数绑定、步骤排序/复制/删除、方案导入导出、实际计划下载、无效参数阻止导出、浏览器暂存与窄屏布局。截图和报告在指定输出目录；它不建立模型，也不证明生成的参数适合某个用户资产。

集成专项：`node .agents/skills/minecraft-nbt-modeler/assets/viewer/test-prompt-integration.mjs <合成细节控制台fixture目录> <全新输出目录>`，覆盖实际后端编译、当前模型与保护配置联动、计划下载、保留草稿、源版本拒绝和原控制台参数不变。接口和静态白名单沿用本机Host/Origin限制，网页仅服务固定的四个提示词资源。
