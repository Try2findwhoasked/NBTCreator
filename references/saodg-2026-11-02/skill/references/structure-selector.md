# 已有结构：现有结构选择器

这是独立结构工作台的作者库标签，管理 `nbt_models` 完整主模型。代码与模组结构管理合并位于工作区 `tools/structures/workbench/`；双击仓库根目录的 `启动结构工作台.cmd`，或运行：

```powershell
python tools/structures/workbench/launch.py --library
```

`启动现有结构选择器.cmd` 现默认进入[模组结构管理器](mod-structures.md)，管理模组已登记的rooms/dungeons/structures。作者库与模组当前接入版本分别呈现，不把作者库存量当作模组已启用数量。

可用 `--workspace <仓库>` 指定库，`--port <端口>` 固定服务地址，`--no-open` 只打印地址。工作台仅绑定127.0.0.1，顶部标签在同一服务切换作者库与模组管理；细节控制台独立启动。旧skill启动器只作兼容跳转；复制skill不包含本仓库工作台。

## 浏览与选择

- 卡片显示中文名称、形状、尺寸及版本；点击卡片在右侧查看说明、完整文件路径、修改时间和几何哈希，可复制路径。
- 按中文名称、版本、日期或路径搜索，按形状筛选，并切换最近修改、名称或形状排序。每页最多36项，不截断整座建筑库。
- 默认每座建筑只显示最近保存的正式版本，同建筑同几何副本合并；“历史版本”显示旧稿和中间稿。规范路径 `<形状>/<中文名>/<日期版本>/` 中的日期目录属于同一建筑的版本。
- 封面仅使用元数据几何哈希匹配的已有PNG，按需载入320×200以内JPEG缓存；最多并行3个请求。不匹配的旧图不显示。无图时明确显示“占地示意”，不生成图片、不启动WebGL。示意优先读取声明的cells，否则使用形状图标，不是真实几何渲染。
- ☆收藏和卡片勾选的批量清单保存在工作区 `build/structure_workbench/structure_library.json`，首次启动复制旧清单并保留原字节。逐项更新串行原子写入，跨服务端口和重启复用；原有模型、中文描述、审阅图和批准记录均不改写。
- “我的收藏”“已选清单”同样遵循历史版本开关；查找已收藏的旧版本时开启历史版本。底部已选数量与导出包含库中所有已选版本，不受当前筛选或分页限制。
- “导出选择清单”下载JSON，包含源绝对路径、几何哈希、版本、形状、坐标及相机路径；它是引用清单，不打包NBT、不复制模型，也不是精修授权。不可用的已选路径会提示并从导出中排除，可清空清单移除旧引用。
- “在细节控制台中打开”将右侧当前查看的单座建筑交给原细节控制台，在不同端口的新窗口加载。卡片复选框用于批量清单，两者独立；原细节控制台不再内嵌结构库页面。

扫描隐藏bugged、测试、缓存、世界与迁移资料，保留 `runtime/parts` 中真正完整的主模型。源在索引后发生变化时封面请求拒绝继续，刷新可发现新增、删除或改版文件。索引缓存不代替加载时的实际模型校验。迁移中的库暂不列出，避免管理不完整资产。

## 范围与专项验证

管理动作只涉及收藏、引用清单和预览缓存；资产迁移、改名、删除与精修仍按原工作流执行。选择器不认证密闭、通路、墙归属、设计、49运行、旋转或多人。

```powershell
python .agents/skills/minecraft-nbt-modeler/scripts/check_skill.py
python .agents/skills/minecraft-nbt-modeler/scripts/check_detail_control_fixtures.py --output <新后端测试目录>
node tools/structures/workbench/tests/test-library.mjs --fixture <上述后端测试目录> --output <新浏览器测试目录>
```

浏览器专项仅用合成模型，检查日期版本归组、搜索/形状/历史筛选、分页、哈希封面、收藏与批量清单、并发保存、服务重启恢复、选择导出、旧源失效、刷新发现删除、另开独立细节控制台、控制台API隔离、窄屏/高DPI、跨站拒绝及源字节保留。工作台自己的test-separation.mjs另外检查同源双标签和旧数据迁移。生成的测试图不属于建筑设计验收或用户确认。
