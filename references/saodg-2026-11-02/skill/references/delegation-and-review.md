# 委派与阅读落实

用于已获准的subagent建模、批量制作和换agent接手；独立执行的agent沿用同样的必读与初稿验收标准。本文不授权新增委派，不要求用户重复确认常规读文件或内部质检，也不改变缩略图后精修的授权边界。

## 开工前明确必读范围

主agent给出实际skill路径、任务输出目录、设计目标与适用阅读清单。不能只写“使用这个skill”或复制主文件中的摘要，然后默认subagent读过引用。新建/重设计任务在编写本次几何生成器和制作主体前完成下表适用范围；修复已有模型则完整阅读主skill、细节设计和与修改有关的指导/工具章节，不强制重读无关目录。

| 条件 | 必读范围 |
| --- | --- |
| 所有新建/重设计建筑 | 工作区AGENTS.md、SKILL.md全文、player-scale.md全文、spatial-detail-design.md全文、本文件全文 |
| 未指定空间骨架、批量多样性或纠正重复 | design-grammar.md全文；不得只读选型维度或开头 |
| 建筑构造与风格 | architecture-knowledge-base.md引言、“建筑风格与构造语汇”和“把风格落实为方块构件”完整章节；所选原型条目完整阅读，未使用现成原型时无需遍读所有条目 |
| 拓展用途 | structure-atlas.md使用边界、选用类别/条目及“从目录继续生长”；不要求遍读全部72种原型 |
| 洞穴、曲面、有机或不规则空间 | organic-spaces.md全文 |
| 多空间、跨层联动或多格整体 | linked-spaces.md全文 |
| SAODG可拼接房 | saodg-constraints.md全文，核对当前相关加载实现；指南示例不增加设计限制 |
| 使用通用工具 | toolkit.md中实际使用的读写、预览、碰撞、整体切片、墙mask和交付章节完整阅读；需要时检查对应API，不以示例脚本当建筑模板 |
| 细微道具、手边部件与细部构造 | micro-props.md全文；交代实际方块状态、支承/使用侧、玩家站位，以及预览与碰撞支持范围 |
| SAO主题 | SAOartguide.md主题适配、适用类型的风格指导及相关反模式完整阅读；用户只做素材时不把整层选址/玩法要求扩展成新任务 |
| 用户已看图批准进一步精修 | refinement.md全文及本次使用工具的说明；未批准不得调用approve/apply |

“完整阅读”指所声明范围的正文已通过工具返回并被检查。可以分段读取；输出被截断时继续读取缺失部分，不能把 `head`/`TotalCount` 的开头、rg搜索结果、另一个agent的摘要或继承来的提示当作完整原文。可复用当前上下文中已完整读过且未变化的正文，不机械重复工具调用。新接手agent必须核对实际上下文和文件版本，不能继承前任“已读”的自报。

## 阅读记录与开工核对

subagent在任务输出目录保存简短 `reading_record.json`，可由本次多个模型共用并在各模型报告中引用。记录每个适用文件的实际路径、必读章节、实际覆盖范围、完整/部分/未读，以及从该范围落实到本次模型的具体决定。版本可用文件哈希或明确的修订记录关联，文档改变时补读相关变化。

记录必须如实：先读后记，部分阅读就标部分，不复制任务清单批量填“已读”。不要记录冗长引文来冒充理解；说明诸如“桥头落于厚承台并检查入口视角”“风格由开间/支承决定而非仅换石材”这类本次决定。记录不能自行证明阅读发生，主agent结合实际读取记录、覆盖范围和产物核对；缺少可核查证据时不代证完整阅读。

主体制作开始前，subagent向主agent简报已完成的适用必读范围、空间概念、关键构造和主题节点；未读完先补读，不以交付期限或“先跑起来”为理由略过。主agent发现只读开头、必要章节缺失或转述无法对应设计时，要求补读与修正方案，再继续主体制作。此为内部核对，无需把阅读表交给用户审批。

## 批量任务先验代表初稿

主agent先选一件能暴露本批关键构造/主题问题的代表作完成初稿。其他subagent可研究、核对接口、构思独立方向和准备通用工具；代表作经主agent实际看图并达到初稿设计标准前，不全面展开其余主体生成。第一件仍是初稿，不在用户选方向前做全面精修。

代表作必须提供整体、未剖切真实落脚入口及能看到实际连接/主题部件的节点近景。主agent检查 [初稿设计验收](spatial-detail-design.md#初稿设计验收)，发现共性简化手法先修复，并把具体教训反馈到后续委派；不能只根据subagent的 `passed`、最终文字或远景图宣布放行。代表作过关后，其余作品仍独立设计并逐件复核，不复制骨架批量换皮。

## 委派任务中写清的内容

用与任务相称的简短说明，不必逐字重复skill全文，但不可遗漏：

- 实际skill位置、输出目录、必读范围和阅读记录要求；先读完再建主体，部分阅读须自报。
- 按output-storage分配日期目录、唯一房间编号和日期文件前缀；并发任务不共写一个房间或版本。细微道具可发挥设计，不因预览限制全部退回整方盒；需要扩展形状工具时集中由一人维护，其他agent暂用已验证版本。
- 本件尺寸/cells、用户风格与自由度、与同批其他作品的空间差异，以及需要成立的构造/主题关系；由subagent发展具体设计，不把名称列表当白名单。分开交代整体包围与局部活动区净尺寸，要求报告路线净宽/净高、道具/站位及玩家视角证据，不以48格或最大高度作为默认内部空间。
- 初稿也要完成基本构造、重要边缘和可辨主题构件；不接收纯房壳、平台或占位设备作为完成品。技术检查和视觉设计分别验收。
- 先全局整体、后机械切片；开洞前密闭、门洞、路线、墙mask和48/49分别检查。保留失败目标与未验证项，不通过删目标或遮缝改形把报告变绿。
- 代表作复核顺序、实际看图和主agent复核职责；用户看过缩略图批准之前禁止精修approve/apply，不得制造批准。

subagent结束时回报实际文件、关键坐标、已看图路径、技术结果、设计缺项与未验证内容。主agent发现设计未达标时继续修初稿或明确交付为未完成实验样本；不能把“技术检查通过、设计留给精修”改写为初稿完成。用户的实际要求优先，内部阅读记录和设计复核均不替代用户判断。
