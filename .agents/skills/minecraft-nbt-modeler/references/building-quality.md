# 整栋建筑质量评分

在创作项目根目录运行。整栋评分适用于经 `architect plan-build` 绑定建筑方案的 SNBT 制作版。桌面端在“检查与交付 → 进一步检查 → 整栋质量评分”读取同一份报告。

## 登记验收条件

使用 `capabilities --architecture` 查完整建筑方案字段。归卷阁提供了可运行的登记示例。先冻结 `plan.quality.rubric`（`building-quality-v1`）、清单修订 `revision`、阶段 `stage`，以及可选的同任务 `comparison_scope`。同时为需求、活动及观察位置保留稳定 ID。清单增删或替换时更新修订并以 `changes[]` 登记 `previous`、`current` 和 `reason`，按需要省略其中一个 ID。

| 维度 | 登记与计分 |
| --- | --- |
| 建筑完成度 | 为现有 `requirements` 登记适用阶段、目标、必做性质和验收检查或机位。必做权重 2，其余权重 1，档位 0、2、4。构件存在提供部分实现的证据，验收条件需要逐项核对。 |
| 美观度 | 登记轮廓比例、视觉主次、色材明暗和视角协调，按需登记理由。整体判断须包括整体和玩家机位。档位 0 至 4。 |
| 玩家通路合理性 | 按 `activities` 逐段验证步行与操作面，再按活动等权汇总。在 `quality.activities[].segments` 按停靠顺序给每段登记稳定 ID、机位及三个体验判据。实际路径中 1.2×1.8 格宽裕净空占至少 80% 得 4 档，50% 至不足 80% 得 2 档，其余得 0 档。转身停靠、辨路与用途各按本段登记目标核对，档位 0、2、4。必要活动有阻塞或可行性证据缺口时，仍可读其他已证实路段的分项与脚位。旧清单的活动级 `criteria` 继续可读。 |
| 风格完成度 | 为每项风格登记适用部位、目标、变体、机位或量化证据。各特征等权，特征内各部位等权。档位 0 至 4，3 档及以上计为达标。 |
| 细节质量 | 为代表节点登记位置、部件关系、交接收口和使用可读性。目标明确的极简节点同样适用。节点等权，节点内各适用判据等权。档位 0 至 4。 |

适用但待测的条目计入覆盖率分母。填写 `not_applicable` 时需要本次设计的具体理由。满覆盖时给出维度分，部分覆盖时给出可能区间，零覆盖时显示待评估。先读阻塞及脚位，再看各维分数与覆盖率。静态通路与纹理预览的范围分别记录，游戏内光照和运动仍走游戏检查。

### 风格部位的量化证据

在风格部位添加 `quantitative`。用 `region` 冻结共同的采样盒，用 `members` 指定构件 ID、`style.materials` 中的材质角色和目标体素盒。所有盒使用含端点的世界 XYZ 坐标。一个构件可由多个盒组成，允许的端跨变化可用具名 `variants` 列出对应的盒。下面是一个梁架部位的量化字段示例。

```json
{
  "region": {"lo": [8, 7, 1], "hi": [12, 9, 24]},
  "members": [
    {
      "part": "ceiling_beam_3",
      "roles": ["frame"],
      "boxes": [{"lo": [9, 8, 16], "hi": [11, 8, 16]}],
      "variants": [
        {"id": "extended_end", "boxes": [{"lo": [9, 8, 18], "hi": [11, 8, 18]}]}
      ]
    }
  ],
  "bands": [
    {"kind": "lowpass", "high": 0.10},
    {"kind": "highpass", "low": 0.25},
    {"kind": "bandpass", "low": 0.15, "high": 0.18}
  ]
}
```

频率单位为每格周期。系统对实际与目标占用场分别使用 `rfft(..., axis=0)`，数组为 `[Z, Y, X]`，对选定频带逆变换后比较两份响应。采样盒须包含可分辨的频率，单部位最多 1,048,576 格，整份清单最多 8,388,608 格。需要报告的位移、尺寸和材质从构件实际方块读取。频带内按等权汇总，尺寸与位置按构件核对，材质按每个构件的实际合规方块比例计算。

频带、尺寸与位置、材质三组拟合度等权。若部位还登记了机位，通过真实审阅提交的档位作为第四组证据。综合拟合度乘 4 后取整得到 0–4 档。报告保留计算版本、各组拟合度、使用的频率和变体、位置偏差和材质例证。正式计算使用现有 Python/NumPy 环境，合成用例用于复验量化链路，真人评审用于校准档位。

## 检查、看图和续版

1. 正常运行 `plan-build` 和 `plan-check`。已登记量表的方案在回执中带 `quality`。必要路线或操作面导致建模退出时，失败回执同样提供定位、建议和复验条件。
2. 运行 `review-prepare`，再执行回执里的出图命令。看图后照常提交 `review-record`。在实物观察中添加如下量表记录，一项分值可引用多个已观察机位。观察写明可在图中辨识的位置与依据。

   ```json
   {
     "item": "details.archive.joints",
     "grade": 2,
     "reviewer": "human",
     "observer": "本次审阅者",
     "images": ["cabinet"],
     "note": "书柜最左格上方未接到深色压条，端头矮一格。",
     "suggestion": "将深色木压条补齐至书柜最左格的顶边。"
   }
   ```

   将该对象放入 `quality_observations` 数组。低于 4 档的条目需给出修改建议。量表观察随普通观察记录一起修订；更新时传入本轮整组观察。报告绑定审阅修订、渲染配置及实际图片。
3. 用 `architect quality-check --request <请求JSON>` 重读。请求填写 `source`、`source_sha256`。如需计入视觉观察，将 `review-record` 回执中的 `review_compare` 对象传作 `review`；桌面弹窗接受同一对象。审阅记录过期后可改用最新绑定，图片丢失时补拍并重记依赖该机位的观察。
4. 用 `architect quality-compare --request <请求JSON>` 对照上一版。增加 `previous` 对象，填写上版的源绑定及可选审阅。对照未保存的失败候选时，使用 `previous.report` 和 `previous.report_sha256` 指向 `plan-build --compact-report` 留下的完整失败回执。使用现有 `review-compare` 时可用 `current_review` 传入新版审阅。对照会追踪新增、持续、已复验解决和待复核的问题，给出双版条件一致的分差。
5. 复查实际缩略图并取得用户明确确认后再精修。定稿继续使用显式手动导出。

`quality-check` 和 `quality-compare` 都可用 `--compact-report` 将完整结果写入 `nbt_models/` 内的新 JSON。简报带报告路径和哈希；完整结果内的 `pointer` 或图片绑定可回查证据。

## 比较验收

默认反馈切换前，在同一批初稿上固定 Agent、制作源、基础技术回执和改动预算，分别追加既有房间评分与整栋报告并各改一轮。记录房间评分实际覆盖范围，优先比较两组均有有效评分的样例。留存任务逐例的必做问题修复率、新增通路阻塞、用户偏好、用时与改动量。用不同用途、尺度和装饰密度的留出样例校准。

使用 `reference review-prepare` 对同机位、同出图设置的渲染生成匿名 A/B。需要交换顺序时传入上次回执的 `reverse_of: {binding, binding_sha256}`，沿用同一对渲染、原始输入顺序和裁切，仅把 `public` 证据交给评审。用 `reference review-record` 记录用户和独立 Agent 的实际选择或平局、观察和分歧。等预算比较显示关键问题修复率提高、两类必要通路反例均正确定位且抽验无新增必要路线回归后，再启用默认整栋反馈。

归卷阁出图、分档、续版和桌面共用报告的自动回归入口为源码根目录的 `mise run test -- building-quality`。真实出图的自动化评分字段使用测试数据，人和 Agent 的实际盲评独立登记。
