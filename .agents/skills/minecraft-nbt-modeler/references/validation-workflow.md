# 密闭、开洞与分项验收

## 生成与检查

按需要选用程序化方块建模、3D模型体素化或游戏内导出。现有脚本直接构造体素，并未实现通用 GLB/OBJ 导入。可以修改形状函数或另写生成器，不必复现示例建筑。

导出 Java 1.20.1 gzip NBT（DataVersion=3465），`size` 按X/Y/Z，palette资源ID和Properties合法，坐标唯一且界内。面向当前 SAODG 时，必须单palette、空entities、无方块实体，并符合其方块导入策略。完整运行模板显式保存全体积含空气；schema 5的主体/墙面制作层只保存所属的非空气方块，由加载器补空气并合成完整运行分片，具体见拼接协议。配套JSON仅在接入房间时生成，内容需与模板一致。

按以下顺序检查，不用“先开洞再堵洞”的检查替代开洞前的密闭验收：

1. **开洞前**：构造完整密闭空间，明确设计内部空气范围；从包围结构六面外侧的空气进行六邻接洪水填充（必要时增加一层仅用于检查的外围空气），确认外部空气无法到达内部。多格建筑按组装后的逻辑空间检查，内部接缝不是对外开口。修复泄漏后再检查，保存通过结果；结合设计检查非预期封死的空腔。
2. **开洞**：密闭检查通过后，SAODG可拼接房按声明端口切出6格宽、5格高的开口，位置、朝向和 `door_y` 符合拼接协议；独立建筑按本次声明的开口尺寸与坐标制作，不套用SAODG端口大小。打通厚墙及门后必要通道，保留脚下地板；不随意增加其他边界开口。
3. **开洞后**：检查端口坐标及尺寸、门洞空气、地板、净空和必要路线；核对边界修改仅涉及已声明端口及其必要连接。可在验证副本中重新封住这些合法开口做漏口复查，临时封口不能写入最终NBT。没有声明端口时不执行开洞。
4. **最终落盘**：导出并回读NBT，核对尺寸、数量、坐标、palette索引和方块状态。保存开洞前密闭结果与开洞后端口/通路结果；最终有合法门洞的结构不能被标为“完全密闭”。

涉及台阶、半砖、多层通路或旋转时按实际碰撞和声明旋转验证，不用单层平地算法替代。未执行游戏加载、通行或多人检查时如实标记。

## 独立建筑的显式上下文

独立建筑的 `coordinates.json` 使用 `mode: "standalone"`，并明确提供 `openings` 数组；无门的闭合建筑也必须写 `openings: []`。每个开口为 `{id, lo, hi, facing}`，XYZ上下界含边界，facing从内部朝外。开口可在包围盒内部并覆盖厚墙，不要求6×5或48倍数。不能根据文件夹名、图片剖切或漏口自动推定开口。`ports` 属于SAODG模式，独立模式不能混填。

同一上下文须包含真实 `start`、非空 `targets`、覆盖设计腔体的 `interior_probes`，以及适用的 `protected_paths`、`protected_boxes`、`route_legs` 和相机。不能只将这些内容分散在历史报告中而不给应用可直接读取的坐标配置。`nbt_whole_validation.validate_whole` 检查声明开口的空气/地板格和邻接喉道，只在副本回封声明开口后验漏，再检查实际通路及指定连接；它不制造开洞前原始证明，报告保留 `original_preopening_proof: false`。制作初稿时仍须保存真实开洞前检查。

独立模式支持当前内存Volume的各轴1～294范围；交付机械拆为各轴≤48的XYZ块，边块保留真实尺寸并记录偏移，不补几何，不声明SAODG49接入。显式全局墙mask继续保留；若整件独立素材确实没有墙层，需要 `allow_empty_wall_mask: true` 声明，不能因为缺mask就自动补空墙。该策略只适用于独立模式，原SAODG逐cell墙层要求不变。未给mode时沿用原SAODG严格规则，未知mode直接拒绝。

独立模式也可显式给非空 `cells` 指定有效XZ占地（每格48，只作占地和存储约束，不强制SAODG门口）。要求整数非负、唯一、四邻连通且每格起点在真实尺寸内；非空气方块不得写入缺角。此时只对有效XZ格乘以各Y层切片，L形3格仍只出3份完整片和6份分层，缺角不出空片。未给cells或`cells: []`才表示完整自由尺寸包围盒；不得丢弃提示词工作台已经声明的占地。

有预览时查看生成图像，区分外观、剖视和真实开口。不要为仅更新skill说明而重建模组或重跑所有示例。

当前通路检查对少量已核实的 1.20.1 薄构件提供保守障碍上包络；代理不作地面支撑，报告明确保留非精确形状结论。适用名单、版本证据与 strict 模式见 [细件保守通路](collision-envelopes.md)。其余未知形状仍阻止认证，不删除细件或放宽范围来制造通过。

初稿完成必须分别记录技术验证、空间设计、构造细节和主题表达的结论。NBT格式、密闭、端口、通路、切片重组通过，只证明对应技术项目通过；不能使设计质量自动通过。代表节点缺失、道具仍是占位物或主题仅靠命名/换材质时，标记“初稿设计未达标”，先补足初稿再重新看图与重验受影响项目，不用“等待精修”掩盖缺项。49运行接缝、实际游戏验证与旋转支持继续单列，不能因48路线通过就标为可接入。按 [设计验收记录](spatial-detail-design.md#设计验收记录) 保存证据。
