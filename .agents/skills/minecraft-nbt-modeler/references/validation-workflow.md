# 密闭、开洞与分项验收

## 生成与检查

按需要选用程序化方块建模、3D模型体素化或游戏内导出。现有脚本直接构造体素，并未实现通用 GLB/OBJ 导入。可以修改形状函数或另写生成器，不必复现示例建筑。

制作阶段默认保存并回读完整 SNBT 主模型；用户明确要求定稿时，才导出 Java 1.20.1 gzip NBT（DataVersion=3465）。无论制作源还是定稿，`size` 按X/Y/Z，palette资源ID和Properties合法，坐标唯一且界内。面向当前 SAODG 时，必须单palette、空entities、无方块实体，并符合其方块导入策略。完整运行模板显式保存全体积含空气；schema 5的主体/墙面制作层只保存所属的非空气方块，由加载器补空气并合成完整运行分片，具体见拼接协议。配套JSON仅在接入房间时生成，内容需与模板一致。

先读任务携带的项目约束快照和上下文草案。围护密闭与通行洞口各自按项目决定。露天庭院、亭廊、开放街道保留设计留空。需要开洞前密闭证据的项目，在真实未开洞模型上检查。

1. **围护**：要求密闭时，为每个需要封闭的腔体设置实际空气探针。引擎以六邻接洪水填充检查外部空气是否可达探针，按完整逻辑空间验证并保存证据。开放空间可直接制作和检查通路。
2. **洞口**：独立项目按声明坐标、净宽、净高和墙厚制作，保留地板和相邻落脚面。启用 [SAODG 接入扩展](../constraint-extensions/saodg.json) 时，外侧居中端口为 6 格宽、5 格高，位置、朝向和 `door_y` 按[专用协议](saodg-constraints.md)设置。
3. **开洞后**：检查端口坐标及尺寸、门洞空气、地板、净空和必要路线；核对边界修改仅涉及已声明端口及其必要连接。可在验证副本中重新封住这些合法开口做漏口复查，临时封口不能写入正式制作源或交付NBT。没有声明端口时不执行开洞。
4. **制作源落盘**：保存并回读完整SNBT，核对尺寸、数量、坐标、palette索引和方块状态。只有用户明确要求定稿时，才另外导出并回读交付NBT；初稿检查与图像审阅不要求先生成NBT。保存开洞前密闭结果与开洞后端口/通路结果；最终有合法门洞的结构不能被标为“完全密闭”。

涉及台阶、半砖、多层通路或旋转时按实际碰撞和声明旋转验证，不用单层平地算法替代。未执行游戏加载、通行或多人检查时如实标记。

## 独立建筑的显式上下文

独立建筑的 `coordinates.json` 使用 `mode: "standalone"`。项目约束可写入以下字段：

- `require_enclosure` 为 `true` 时需要 `interior_probes` 并验密闭；`false` 跳过该项。旧上下文省略此字段时，仍按已有室内探针执行验漏。
- `openings_policy` 可为 `optional`、`required` 或 `none`。默认 `optional`。`required` 需要至少一个通行洞口声明，`none` 使用空列表并禁止声明。露天边界和采光留空由结构设计表达。
- `opening_size: [净宽, 净高]` 以方块计。省略时每个洞口可使用各自尺寸。`openings` 每项为 `{id, lo, hi, facing}`，XYZ 上下界包含端点，`facing` 为向外的水平方向。宽度沿垂直于朝向的水平轴计算，第三轴的范围决定墙厚。无声明填写 `openings: []`。

同一上下文保留真实 `start`、非空 `targets` 及适用的保护区域、专项路线和相机。`validate_whole` 检查已声明洞口的实际空气、地板与邻接空间，以及碰撞通路。要求密闭时，最终检查只在副本中回封声明洞口；真实开洞前证据另存。未要求密闭时，报告中的 `recapped_seal` 为 `null`。

独立模式支持内存 Volume 的各轴 1～294 范围；交付机械拆为各轴 ≤48 的 XYZ 块，边块保留真实尺寸和偏移。继续保留显式全局墙 mask；确实没有墙层时声明 `allow_empty_wall_mask: true`。旧坐标文件未给 `mode` 且使用 `ports` 或 `door_y` 时，按旧 SAODG 端口协议读取；其余默认独立模式。

独立模式也可显式给非空 `cells` 指定有效XZ占地（边长取 `cell_size`，未给时兼容旧版 48 格）。要求整数非负、唯一、四邻连通且每格起点在真实尺寸内；非空气方块不得写入缺角。交付在每个有效格内按各轴最多 48 方块机械切片，大格分成多个子片，小格沿真实边界裁齐。各片记录偏移和实际尺寸，缺角区域不出片。未给cells或`cells: []`才表示完整自由尺寸包围盒；不得丢弃提示词工作台已经声明的占地。

有预览时查看生成图像，区分外观、剖视和真实开口。不要为仅更新skill说明而重建模组或重跑所有示例。

当前通路检查对少量已核实的 1.20.1 薄构件提供保守障碍上包络；代理不作地面支撑，报告明确保留非精确形状结论。适用名单、版本证据与 strict 模式见 [细件保守通路](collision-envelopes.md)。其余未知形状仍阻止认证，不删除细件或放宽范围来制造通过。

初稿完成必须分别记录技术验证、空间设计、构造细节和主题表达的结论。NBT格式、密闭、端口、通路、切片重组通过，只证明对应技术项目通过；不能使设计质量自动通过。代表节点缺失、道具仍是占位物或主题仅靠命名/换材质时，标记“初稿设计未达标”，先补足初稿再重新看图与重验受影响项目，不用“等待精修”掩盖缺项。49运行接缝、实际游戏验证与旋转支持继续单列，不能因48路线通过就标为可接入。按 [设计验收记录](spatial-detail-design.md#设计验收记录) 保存证据。
