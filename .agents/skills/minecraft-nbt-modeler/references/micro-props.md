# 细微道具与部件

适用于新建房间的近观道具、已有道具的初稿补足，以及用户看图批准后的细部精修。目标是让玩家在正常站位看得出用途、使用侧和安装方式。本文提供可扩展的构造方法，不是每房必须照抄的道具清单，也不为既有模型自动授予精修许可。

## 先辨认用途，再增加小件

从本房间的行为选道具：谁拿取、放置、旋转、检修或阅读，手和脚分别在哪里。先定主体与支承，再挑能说明功能的薄边、接头、把手、夹口、挂点或小件组；不要用一个整块方盒和名称代替完整设备，也不要在所有空地随机撒装饰。

小件保持玩家尺度。台面、座椅、存取架和手边控制件按站位安排，设备整体可以大，操作部件不能随其一起等比放大。仅能在飞行相机看到的零碎不优先于入口、桌边、桥头和操作点。原版方块有自身几何尺度，不能在NBT中虚构任意缩放、旋转角或自定义1/16体素；更小的轮廓由实际允许的原版方块状态表达。

## 用合法状态表达细部

以下是候选做法，按环境、导入策略和工具支持选择，不要求全部使用：

| 表达对象 | 可采用的方块构造 | 连接与使用侧 |
| --- | --- | --- |
| 台沿、抽屉口、靠背、夹具 | 上/下半砖、内外角楼梯、倒置楼梯组合出薄面、缺口与托座 | 区分台面、腿和膝部空间；夹具对着真正作业面 |
| 柜门、护罩、托条 | 原版活板门、楼梯/半砖的边框；可用按钮作可辨小凸件 | 保存facing/half/open等适用属性，有铰接或固定边，不悬空贴片 |
| 手柄、手边标记、管线端部 | 原版按钮、拉杆、避雷针、末地烛等允许构件 | 按实际attach face/朝向安装，有实体载体；不宣称已实现控制逻辑 |
| 工具架、吊点、薄隔栏 | 链、铁栏杆、栅栏、墙、玻璃板或相应状态组合 | 挂点连接真实横梁，栏杆连续到端头；显式核对邻接属性 |
| 书案与档案小件 | 半砖/楼梯表达折叠册页、收纳格、书托与椅背，普通bookshelf承担书脊纹理 | 桌面与阅读站位相邻，避免用单一大方块命名“书卷” |
| 仪器、阀座、封缄构件 | 小型轴套、框、指针/刻度载体和成组对位构件 | 传动与被作用对象可追溯；静态外观不宣称动作或交互 |

方块实体、实体装饰、模组微缩方块并不因本文而获准。面向当前SAODG继续保持空entities、无方块实体和实际导入策略；不能靠物品展示框、盔甲架、任意头颅/容器数据来补本轮静态道具。按钮/拉杆等也可能随游戏交互或邻块更新改变状态，未游戏验证时按静态意图交付并记录限制，不擅自增加红石、奖励或玩法。

## 保留细节，也诚实处理工具限制

NBT写入器能保存状态，不等于渲染器或碰撞器已支持该形状。现有半格预览主要精确表达完整块、半砖和楼梯，活板门、按钮、链、栏杆等可能被近似成完整块；现有碰撞器会把未知形状列入unknown_shapes并拒绝总通过。

- 不因工具限制把所有小件删掉、放大，或直接视为空气；更不能删除unknown_shapes、忽略失败目标来得到绿报告。
- 可以在全局主模型中保留实际小件，同时补充有依据的形状支持、使用能表达实际形状的预览/游戏检查，或明确标注哪些几何、邻接更新与通路尚未验证。若细部需要比半格更细的碰撞表达，应使用精确AABB/原版形状依据，不能把细窄构件默认当作可靠地板或半格支撑。
- 工具扩展须单独维护与验证：检查不同朝向、开合、支承/碰撞、落盘回读及有障碍反例。批量委派由一个负责工具的agent统一维护，其他agent调用同一版本，避免并发各改一套形状规则。
- 未知装饰远离路线并不自动使现有check_routes通过；如采用保守包围体证明某条通路，必须另列该证明的范围与不依赖未知形状支承的证据，不能改写成完整原版碰撞验收。

## 从最终模型检查近处细节

用实际落盘NBT，从可站立脚位上方约1.62格拍未剖切近景。画面包含主体、细部、连接对象与使用侧，不能只拍颜色、把细件藏在柱后或用标题补足画面。整体图继续证明空间独立性，近景证明人尺度与部件，不互相替代。

在`coordinates.json`或已有道具记录里简记用途、包围尺寸、关键部件坐标/状态、支承和玩家站位；在`design_review.json`记录实际看图结论、源文件哈希及未支持形状。初稿已有代表性细微部件；获准精修后再全面统一细部，不给每间房设机械数量配额。新增道具后重新检查受影响的门后净空、路线、墙mask归属与密闭，重验后才冻结新版本。
