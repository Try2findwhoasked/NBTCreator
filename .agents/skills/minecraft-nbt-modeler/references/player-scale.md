# 玩家尺度与尺寸起点

用于新建、重设计以及修复“建筑过大、近处没内容”的问题。先按人的活动组织几何，再形成整体轮廓；丰富细节不需要先造巨壳。下列数值单位均为格，是未指定尺寸时的设计起点，不是所有题材的上限、固定配方或运行协议。用户明确的大小、宏伟感、简单程度与玩法需求优先。

## 量什么，先决定什么

- **玩家校尺**：用宽1、高2的站立包络判断比例，供设计而非精确碰撞模拟。使用当前版本实际玩家碰撞验通行，必要路线不依赖潜行、飞行或职业位移。门后、梁底、楼梯高端也要检查；两格高只说明可能容身，不能作为所有房间的舒适净高。
- **净尺寸**：净宽/深是墙、柱、设备和装饰完成后的可用距离；净高是可站立表面到最低阻挡底面的垂直距离，不是NBT的Y尺寸。例：整块地板占局部Y=1，脚位Y=2，顶板最低底面Y=6，则净高4；Y=4～5伸出的梁会降低梁下净高。楼梯/半砖以实际表面与碰撞计算。
- **先放活动，再围合**：先排操作面、玩家站位、通行带及必要战斗空间，决定邻接和高差，再包墙与顶部；已经指定48/96外包围时，在其中安排这些局部尺度。不能先拉满包围盒，再靠放几个巨型道具解释空旷。
- **分开记录**：整体X/Y/Z、有效cells、主要空腔净尺寸、局部脚位Y、最窄路线/最低净空和代表道具尺寸。整体高24不代表每个活动区净高24；厚岩体、顶构、夹层与通高区分别说明。

## 未指定尺寸时的常用起点

表内房间宽深为内部可用空间的概略起点，不是把任意房间强制成矩形；家具摆放后仍保留所需路线。先从满足用途的较紧凑方案出发，再按实际需要放大。

| 场所/构件 | 可采用的净尺寸起点 | 调整依据 |
| --- | --- | --- |
| 普通探索通道 | 宽2～3、高3 | 单人短窄段可宽1，但不默认用于主要路线；会车、携行感或战斗需要更宽 |
| 多人主通道/桥面/楼梯 | 宽3～4、高3～4 | 宽度不含栏杆、支柱、墙饰；战斗桥与大怪通行另按用途放宽 |
| 普通内部门/短喉道 | 宽2～3、高3 | 仅内部设计参考；SAODG对外端口仍为宽6、高5，厚墙后通道也须符合协议 |
| 日常侧室、值守/储物间 | 宽5～9、深6～12、高3～4 | 按家具与站位增减，不给每间配通高穹顶 |
| 小型工坊、药剂/维修作业区 | 宽8～14、深10～18、高4～6 | 设备旁有操作和搬运侧；局部设备挑高不要求全室等高 |
| 小型集会/探索主室 | 宽10～18、深12～24、高5～8 | 按视线、停留人数和布置确定；小规模战斗另留连续活动面 |
| 有意庄重的厅堂 | 宽16～28、深20～36、高8～14 | 可局部更高、更宽；用入口、侧带和人尺度节点建立比较，不成为所有题材默认值 |
| 操作台/长凳/货架 | 台面高0.5～1、深1、长2～4；货架深1、高2～3 | 数字指家具外形；台前通常另留宽2～3的站位/通行带，不把家具和人一起放大 |
| 可近观的墙脚/壁龛/接头 | 常以0.5～1的进退、1～3的局部构件组织 | 采用合法半砖、楼梯等状态；按构造成组，避免每格一处凸块 |

楼层间高度还要加楼板、梁和管线厚度，不把净高直接当层高。楼梯优先采用普通玩家连续可走的楼梯/半砖构造，按高差预留实际水平展开与转折平台；不能画一条很短的斜线便声称解决十格高差。逐段验头部空间，尤其折返、穿梁及上层平台边缘，不用“总高够”代替检查。

## 48格占地与宏大空间

**SAODG单元不是一个必须挖空的48格大厅。** 48×48模板可容纳连续作业带、大小不同的空腔、厚实体、局部通高与路线留白；这些关系按场所组织，不按切片边界分房。外门6×5是接口尺度，不要求所有内部门都一样大，也不能以本表为由收窄接口或其必要喉道。房间总高度仍满足实际协议。

未指定宏伟感的日常空间若大部分活动面净高超过8，或普通操作区出现二十余格无用途净跨度，先核对为何需要这样大：设备、人数、战斗回避、运输、视距或场所成因能否解释？这是复核信号，不是判错阈值。按需要保留的大净空可成立；不要机械塞柱、加墙、加楼层或均匀填满道具。

用户明确要求96格大殿、巨型洞穴、广场或Boss场地时保留所需整体尺度与主要开放区域。建立**整体体量—可停留/穿行的局部空间—近处节点**三个层次：大炉体、巨大岩拱可做远景主体，炉前操作台、检修带、桥头与人的通行仍保持可用比例。不是把小房间所有尺寸乘四，也不是把大殿切成许多小盒子。战斗区域的空地有玩法用途，不当作缺细节；细节可落在入口、边缘、停留点与设备接口，不能挤占必要活动面。

多格主模型在48连续坐标中统一设计，切片保持机械性；不在48/96切面加隔断或缩窄来“恢复人尺度”。49运行展开、封闭及连接仍按当前代码另验，不以尺度设计替代兼容性检查。

## 细节如何在人身边成立

先完成玩家实际会靠近的操作面、壁龛、门套、墙脚、楼梯转折与主题部件。日常设施先考虑脚位上方约0～3格的可见、可接近内容，再处理远处梁架与奇观；高处细节仍可有构图与主题作用，不强制每面墙都装饰到同样密度。以部件、接口、支承和使用侧建立辨识，不以材质数、随机噪声或道具数量替代。

发现“小桌子淹没在巨壳里”时，先判断是整体/局部净跨度过大、活动区离墙太远、墙边缺用途，还是桌子本身缺可辨部件。依问题调整净高、功能邻接、空实关系或局部构件；不是统一放大桌子，也不对已有建筑盲目等比缩小。缩小会影响标准端口、碰撞、高差、墙mask与切片，修改后重验受影响项目。尺寸合适但细节仍空泛时，继续补初稿必要节点，不能以“已经缩小”宣布通过。

## 玩家视角复核与记录

在初稿缩略图审阅前，用实际模型检查比例与近处细节。复用入口、节点和室内仰视即可，不强制额外图片配额：

1. 相机设在真实可达脚位上方约1.62格，使用一致的正常视角；记录位置、朝向及工具可用的视场参数。不同方案对比不靠极广角、飞行高机位或透视变化掩盖空旷。无法生成真实玩家透视时，注明替代视图的局限，玩家体验仍列未验证。
2. 入口与代表性活动点能同时判断近处尺度参照、通行带和主要空间；整体剖视可附仅用于QA的1×2玩家标尺，标尺不写进交付NBT。不能凭鸟瞰微缩图认为细节充足。
3. 检查近处主题道具是否看得出部件与使用侧、墙顶是否只剩遥远平面、宏伟空间是否仍有能停留并近观的内容。保留完整顶构查看局部压迫与挑高，不为拍图删掉遮挡或把相机放进墙里。

将实际净尺寸、路线低点/窄点、代表道具/站位、放大理由，以及关联坐标和已看图结论写入现有 `coordinates.json` / `design_review.json`，不用另造审批阶段。尺度、细节与技术各自给结论；仅有文字方案时只能称“设计推演”，不能填已看图、碰撞通过或初稿完成。缺乏玩家尺度或近处仍为空壳时先修初稿；用户看过缩略图后的精修授权边界保持不变。

## 应用与 Agent 共用的通路可视化

模型编辑视口的“玩家 / 通路”读取当前3D画面，显示宽0.6、高1.8格的实际玩家占位盒。默认使用坐标资料的 `start` / `targets`；也可点击地面顶面填入玩家脚底，或手工输入有限XYZ。脚底不是脚下方块编号，例如方块(2,0,3)上的玩家脚底是[2.5,1,3.5]。台阶点位可以手调，脚下支撑与净空仍由引擎验证。选点不会创建评论或改变编辑选区。

外部 Agent 无需打开应用：`python .agents/skills/nbtcreator-workspace/nbt.py control walk-inspect --request walk-request.json --output build/walk/本次新目录`。请求使用相对 `source`、其 `source_sha256`，可选 `context`、`geometry_sha256`、`start` 和最多32个 `targets`。未显式提供的起终点从坐标资料读取，缺失时明确报错。检查候选可提供 `--snapshot`，快照必须绑定原源哈希及完整主模型几何指纹；应用只允许使用已注册的快照键，不接收任意快照路径。

返回的 `poses` 区分超出模型边界、没有支撑、玩家占位被阻挡，`collisions` 是与玩家占位真正相交的半格碰撞单元。`report.targets[].path` 来自同一 `nbt_collision.check_routes` 引擎，不画虚构直线代替未找到的路径。蓝色表示可站立，红色表示无效占位/碰撞单元；绿色路径表示本次静态检查通过，黄色路径表示仍存在未支持形状等未定问题。高亮跟随剖切，定位会暂时取消剖切并显示全部图层。

搜索最多25万个站姿；达到上限返回 `search_limit_reached`，不是“不通”的证明。仅支持普通步行及半格上下台阶，不模拟跳跃、游泳、攀爬、伤害和动态方块。已核对的保守包围体只作障碍，不能当作地板支撑；未支持形状阻止通过。这里只检查列出的起点到终点，不替代额外 `route_legs` 屏障条件、封闭检查、游戏验收或用户看图确认。结果保存在独立任务目录并进入任务记录；不写NBT、不修改原模型。
