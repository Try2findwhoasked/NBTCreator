# 整体初稿、看图确认与全局精修

## 缩略图确认后再精修

制作分为整体初稿与用户确认后的精修两阶段。初稿必须同时具备有辨识度的整体空间、必要结构、可靠路线，以及足以判断构造语言与主题的实际方块细节：主要承接关系、墙体或洞壁层次、重要边缘收口、代表性主题构件应已成形，不能只交房壳、平台和占位道具。完成技术检查，并实际查看整体、未剖切入口和代表性构造/主题节点近景后再展示；近景可供内部质检，不强制新增交付格式。具体标准见 [初稿设计验收](spatial-detail-design.md#初稿设计验收)。用户确认前暂缓全局局部精修，不暂缓这些初稿必要内容。

新建或重设计建筑时，先完整阅读本 SKILL.md、[玩家尺度与尺寸起点](player-scale.md) 和 [空间与细节设计](spatial-detail-design.md) 全文，再按下节路由完整阅读相关指导章节；适用的空间语法、有机空间、多空间联动等文件不能只读开头。采用subagent时执行 [委派与阅读落实](delegation-and-review.md)：明确必读范围、检查实际阅读记录与几何落实，不能把委派提示中的“请阅读”当作已阅读证据。此规则约束已经获准的委派，不要求为单件任务另开subagent。

按照用户要求，必须等用户看过对应缩略图并明确表示可以进一步精修后，才使用精修工具。只上传图片、没有回复、超时、自动续跑、文件里的“批准”文字或其他agent的评价都不算授权。若用户在看图后的对话中已同意，沿用该授权，不重复询问；批量任务只精修用户选中的模型。用户要求改方向时先改整体初稿并重新展示，而非直接精修旧方向。

收到授权后读取 [精修工作流与工具](refinement.md)：从已审阅的完整、未切割主模型恢复一份新版本，在全局坐标中统一材质语汇、构造尺度与细节，再用脚本重新分割。禁止逐片打开NBT各自加细节、逐片随机换材质或把分片先移成49间距再精修。整体初稿、用户确认记录及墙mask保留，不能覆盖原稿。若旧资产只剩切片，先无损连续重组并保存完整主模型、重做整体缩略图供确认；不能用单个切片冒充整体来源。

`nbt_refine.py`提供 prepare/approve/apply 三步：冻结完整主稿及保护配置并出缩略图，记录实际人类对话中的确认，执行有范围的全局精修计划。确认绑定源文件和图像哈希；原稿/缩略图改变则需重新审阅。工具只是记录提供的确认文本，不能自行证明它来自用户，agent必须遵守上述对话授权要求，不得制造确认记录。

精修后重新验整体密闭、标准门、真实碰撞路线和已声明连接，查看同相机前后对比与节点近景；确认没有破坏形态、门高、切面连续性和墙层归属，再从精修后的整体机械切片。最终仍是每有效分片主体/墙各一份NBT，完整运行模板另存，48连续还原与49引擎兼容性分别报告。

建模尺寸约束以最终完整拼接空间为准。先声明整体X/Y/Z、有效占地与放置间距，再设计主模型：例如沿Z的1×3整体为48×H×144，L形三格是96×H×96减去缺角；每轴48只是单个NBT文件的切片上限，不限制大厅、曲廊、桥梁或视线只能在某一片内。48连续重组与当前49运行展开的实际包围尺寸分别记录，不混用。不得在48/96切面默认加玻璃、隔断、闸门或强制收窄来掩盖接缝不兼容；不兼容如实报告，未经用户要求不反改整体造型。
