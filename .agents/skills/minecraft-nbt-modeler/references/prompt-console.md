# 创作方案与批量提示词

“创作方案”面向建筑师：先保留 AI 编写入口，生成一座或多座建筑的设计要求，再由人工逐条审查修改，自动保存，最后明确交接给外部建造助手。软件不会自动触发外部 Agent，也不会在编写提示词时创建建筑。

## 使用

1. 在提示词列表中“新增一条”，描述建筑用途、空间、动线、风格和构造。默认 AI 只编写设计要求；结果按字段展示，可以直接修改文字后采用。
2. “批量编写”可填写共同要求，以及每行一座的建筑清单（最多 20 座）。每座建筑独立生成并归档，初始均为待审查。停止批量生成会保留已保存草稿和未生成项目。
3. 在“审查与修改”中核对建筑概况、空间动线、材料构造、保留和补充要求。输入停顿后自动保存；切换条目、引用已有建筑和正常退出前刷新保存。列表从当前项目的实际归档恢复，不把别的项目的浏览器暂存当作本项目内容。
4. 点击“这条已审查”表示人工核对了设计要求。继续修改会重新变为待审查。“生成下一条”编写尚未生成的下一座建筑；没有下一座时先新增条目，不会接着润色上一条。
5. “交接已审查的提示词”批量创建制作任务；“确认并交接这条”只交接当前一条。交接后由人工在外部助手对话中调用工作区 Skill，再通过 `prompts tasks --after <cursor>` 和 `prompts task --id <id>` 读取新增任务。已交接任务保留原修订，改稿须重新审查交接。提示词任务与建筑批注的 `feedback` / `feedback-tasks` 接口分开。

需要修改已有建筑时，先在建筑库打开它，再用“为当前建筑写修改要求”明确引用。源文件、哈希、尺寸、通路和保护配置仍绑定实际建筑；提示词页的编辑不反向改写编辑器参数。新提示词默认用于新建筑，不会因为打开页面就引用当前模型。

AI 编写默认不要求建筑师阅读 JSON。工具步骤、坐标保护配置和原始 AI 数据均在高级选项中，原有参数编辑、工具排序、复制、删除与校验继续可用。采用 AI 建议只改变提示词，不构成精修批准。具体几何、状态、碰撞和支承仍需建造时按实际模型验证。

## 文件与界面

有效提示词、方案、操作计划和上下文草案保存在建筑目录的 `提示词方案/`。保留历史修订，交接任务绑定当时的具体修订和源哈希。读取已有稿不会重新编译并产生无意义的新修订。索引、CLI 和迁移读取见 [提示词归档](prompt-archive.md)。

制作源使用 `master/model.snbt`，用户明确定稿后再将 NBT 导出至 `nbt_models/_exports/` 的镜像建筑/版本层级，见 [SNBT 制作源](snbt-authoring.md)。正式标注始终保存在被标注版本的 `修改意见/`。

宽窗口显示提示词列表、编写/审查、完整提示词三个区域；较窄窗口通过“查看完整提示词”展开交接内容，为设计文字留出足够宽度。编写页的确认和下一条操作保持可见。

仍可在浏览器独立打开 `prompt-console/index.html` 离线编辑和下载文件；工作区自动保存、AI 和任务交接需要 NBTCreator 桌面版。页面使用本地 HTML/CSS/JS，无 CDN。

## 维护验证

`core.js` 是设计字段、提示词编译和校验的共用实现；`workspace.js` 管理独立提示词队列，`autosave.js` 复用后端归档。工具定义以 `tool-catalog.json` 为准，修改目录后运行项目 `sync:tools`。

`npm run test:architect` 覆盖批量生成、人工修改、逐条审查、交接、关闭恢复、易读 AI 结果和面板尺寸。`npm run test:studio` 检查画布、可调面板和原控制流程。`tests/prompt-task-desktop.mjs` 与 `tests/prompt-archive.py` 检查真实 Skill 增量读取、修订、幂等交接和边界。测试不代替真实建筑的设计审阅或游戏验证。

桌面桥接仅提供固定的生成、保存、读取与交接操作，静态服务白名单列出确定的提示词资源；继续保留 Host/Origin、源哈希与本机路径边界检查。
