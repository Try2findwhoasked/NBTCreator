# 缩略图确认 → 整体精修 → 重新切片

本流程来自用户明确要求：用户看过缩略图、表示可以进一步精修后才使用；精修回退到完整未切割模型，统一细节之后再分割。它不是生成任意初稿的额外确认，也不是授权部署世界或修改玩法。

## 阶段与授权范围

1. **整体初稿**：先完成主题、轮廓、路线、高差与基本结构，修好基础技术问题。保存整体主模型、墙mask、占地cells、门洞、必要目标和路线检查；出整体/入口缩略图，实际查看后向用户展示。批量先看整体方向，不预先对全部模型做昂贵节点精修。
2. **等待用户意见**：在对应缩略图之后，用户明确说可以精修/继续细化才进入下一步。对明确询问是否精修的“可以”可按上下文接受；对方向的讨论、工具制作请求、只上传图、其他agent认可、自动续跑都不等于同意精修某个资产。用户已确认则不重复问。
3. **恢复完整主稿**：从当时审核的未切割source恢复新版本，统一整座建筑的材质角色、线脚尺度、构件连接和细节密度。不得逐cell作不同风格，不因切面补装饰隔墙。保持初稿轮廓和主要布局；改变方向/规模/关键路线需回到新初稿审阅。
4. **技术与视觉复核**：逐块差异、保护体积、门洞、整体密闭、实际玩家通路及所声称的路线连接重新验收；以同相机前后图及节点近景判断改进是否落地。工具输出仍为pending visual review，agent必须实际看图，不凭passed判断美术完成。
5. **重新切片交付**：唯一源是精修后的完整主模型，主体/墙层按原全局mask更新并机械切出。delivery中每cell两份NBT，运行完整片另存。原稿、缩略图确认、计划、差异与验证记录保留，可回退而不改原文件。

当前不需要用户批准“制作或测试工具”。共享回归使用明确标记的合成fixture及模拟确认，只对合成数据有效；不得拿测试中的确认记录批准用户已有建筑。

## 建筑细节精修要求

精修先列出实际空间的“天花板、地板、墙面、交接节点、主题设施”问题和要改的坐标范围。每类记录保留/修改/不适用及原因，用具体构造和图片作证；不把增加方块数、装饰密度或工具数量当作完成度。初稿已有的构造仍需复核，不能以本阶段要求为由把初稿应有的设计推迟。

### 天花板与顶构

- 按跨度与空间等级组织顶构：梁架、拱券、肋、藻井、洞顶岩层、工业管架等择适用者。主构件要有落点、承托或可信悬挂关系；梁端、拱脚、柱头不能悬空或止于无意义的一块薄皮。
- 区分主结构、次结构和填充顶面，节奏对应下方柱网、路线和功能区；入口、转折、主厅与次级空间有可读的变化。低矮空间用浅层接缝、边带、灯槽即可，不强塞厚梁或把每间顶面做成同一种棋盘。
- 处理墙顶交界、拱券转折、洞顶与人工支架相接、天窗/竖井/吊灯基座边缘。吊装物要有挂点并避开玩家头部；保留外壳厚度，不靠剖切藏掉薄顶和漏口。
- 实际看保留完整顶构的室内仰视与梁端近景，检查顶面是否只有一张平板、构件相互穿插是否合理、视觉重心是否遮住出口和主题节点。几何预览不证明真实光照合格。

### 地板、平台与通行边缘

- 让铺装方向、板缝、嵌边、地毯、检修带或排水沟回应实际动线与用途；主路、设备区、台基、休息区按需要区分。控制大面积重复与高频杂色，保留可读的安静区域。
- 平台收边、楼梯起止、转角踏步、门槛、桥头、沟槽与坑缘要连贯；地板厚度与下方承托能从侧面解释，不能只做悬浮单层面。栏护和边缘提示按场所需要设计，不侵占已验证路线。
- 起伏、半砖凹陷、磨损和积物遵循踩踏、积水、坍塌来源及材料家族；整洁区域可以平整。破损有底、分布成片且有轻重过渡，不用随机挖洞代替铺装设计。优先使用已有地面识别工具保护必要路径。
- 用近地斜视、台阶侧视与实际脚位检查高差和净空；道具不能遮住窄路，纹理边带不能冒充碰撞上真实存在的台阶。

### 墙面、开口与立面层次

- 根据用途组织墙脚、主体、顶部或相应的岩层/设备带，避免所有墙都只有单层平面。柱、扶壁、凹龛、嵌板与横向构件有主次、厚度和间距依据，不机械给每一格套框。
- 门窗洞要有洞壁厚度、过梁/拱顶、窗台/门槛与内外侧收口；墙角、凹凸转折、走廊端头和不同材料交接不能留下半截线脚。凿壁龛时保留外层壳，不能打通隐藏腔体制造未声明开口。
- 功能细节来自场所：灯具、储物、仪式构件、工具架、通风、管路等有安装关系和使用空间。避免沿所有墙等距复制同一组道具；重复构件允许模数一致，但关键节点需有明确变化。
- 潮痕从渗水源扩散、烟痕对应热源、裂纹对应受力/破坏；材质变化围绕形体与功能组织，不能满墙均匀撒苔藓。门后喉道、窗边、梁墙连接与低处墙脚要有近景。

### 全局密度、交接与复核证据

先修构造和大层次，再做材质与细微道具。至少审阅地墙、墙顶、柱梁、楼梯平台及作品特有的关键连接；不存在的连接写不适用，不为了满足表格强加建筑风格。保留留白，远看能分清主体与次要构件，近看能解释接缝和安装。批量作品不能把同一套梁、边带和壁龛全量套用。

精修计划在 `style_note` 中说明统一构造尺度、材料角色、细节集中处和留白处。审阅记录为每个适用类别附修改操作/坐标、同相机前后图或保留理由，结论分别写技术检查和设计复核。图片组合须覆盖整体、无剖切入口、保留完整顶构的室内仰视、地板/墙面及交接近景；可合并机位，超过当前工具六机位上限的补充图片用批量render另出。看不到某项就标记未复核，不能用工具passed填写美术通过。

## 输入准备（工具配置）

工具：`scripts/nbt_refine.py`，Python、numpy、Pillow及同目录通用脚本。

source优先使用 `nbt_whole_cut.slice_master`保存的 `master_geometry.json.gz`，或同等格式的完整主稿，含size、blocks、geometry_sha256和全局wall_positions。单格可直接读完整NBT，同时在config提供显式wall_positions。稀疏body/wall片不接受为完整来源；多格若只剩切片，先按48无损重组并保存完整主稿、出新缩略图，不能分片精修。不要使用49诊断体作为主稿。

config JSON字段：

- `cells`：实际占地，如1×3为[[0,0],[0,1],[0,2]]；尺寸必须匹配全局包围盒，L形不允许改到缺角。
- `door_y`、`ports`：已有实际开口，格式同房间定义；无外门独立模型可写空ports。
- `interior_probes`：覆盖每个设计腔体的整数空气坐标。精修用验证副本临时封合法门验漏；不是先堵掉未知漏口。
- `start`、`targets`：玩家脚部实际浮点坐标。没有动态碰撞的静态路线检查通过，才生成可精修稿。
- `protected_paths`：已保存的真实脚位路径数组。工具保护沿路径扫掠的0.6×1.8体积与支撑层，防止花边挤占通行空间；不是只保护中心点。
- `protected_boxes`：额外关键节点/结构体积，每项lo/hi为包含边界的整数XYZ。门洞、相邻喉道和门槛自动保护。
- `route_legs`：可选的命名连接检查，每项name/start/targets；若有 `validation_only_barriers`（lo/hi），只在检查副本封掉绕路。这些用于证明具体连接，不写入交付。
- `max_changed_blocks`：本次局部精修变化上限，默认4096；按尺度选择。它限制变更范围，不是审美分数，也不能用扩大上限绕过已认可的布局。
- `cameras`：至少whole与entry，最多六组；eye/target为XYZ，cuts按nbt_preview格式。entry必须无剖切且相机在真实脚位+1.62，whole可剖切；detail可用明确的浮动QA机位，不能冒充玩家视角。

工具目前依赖已有碰撞器的完整块、楼梯与半砖支持。未知形状无法认证时明确拒绝，先扩展有依据的碰撞能力或做适当运行时检查，不能删除原细节来制造通过。此工具不模拟游戏光照、透明材质、实体或红石机关。

## 三步命令

在工作区根目录运行，路径替换为本次真实任务路径：

```powershell
python .agents/skills/minecraft-nbt-modeler/scripts/nbt_refine.py prepare --source <完整主稿> --config <保护与相机JSON> --review <任务目录>/draft_review
```

prepare不会精修：冻结主稿和config、检查基础路线、生成thumbnail_XX.png及thumbnails.png，写review.json，状态awaiting_user_review。agent实际查看并在对话中展示thumbnails.png，说明仍未验证的游戏效果，然后等待用户明确意见。

只有真实对话确认后，才调用approve；user-message使用实际用户回复，不复制示例、文档或其他agent文本：

```powershell
python .agents/skills/minecraft-nbt-modeler/scripts/nbt_refine.py approve --review <draft_review> --user-reviewed-thumbnails --user-message <实际确认内容>
python .agents/skills/minecraft-nbt-modeler/scripts/nbt_refine.py apply --review <draft_review> --plan <全局精修计划JSON> --output <任务目录>/refined_01
```

确认记录绑定源、保护配置、各缩略图和拼图哈希；原稿、图像或保护配置被改后拒绝继续，需新审阅。提供确认文本的人是调用agent，工具不是人类身份认证系统；不能因为有approve命令就自行伪造用户同意。

## 给模型使用的精修操作

plan必须有 `style_note`，说明本次整座建筑统一采用的材质角色、节点尺度和细节方向；`operations`在同一个全局坐标中执行。每项给有意义的label和classification（inherit/wall/body），由它更新全局墙归属。不能把同一材质简单当作墙；新设备默认用body，墙面重涂可用inherit或wall。

| kind | 字段 | 合适用途 |
| --- | --- | --- |
| box | lo/hi/state | 壁龛减去内层石块、柱础、台沿、夹具和支点等局部体素；凿龛需保留外层密闭壳 |
| frame | lo/hi/state/thickness | 在一个轴对齐平面构造边框、门套、壁龛口、嵌板或梁端围边 |
| beam | start/end/state/width | 直或阶梯斜向构件、托架、细梁、连续压顶；width为1/3/5，连接合理性需看图 |
| surface_palette | lo/hi/from_states/palette/fraction/seed | 在限定区域、限定原状态的暴露表面作可复现低密度材质细化；不挖空气，不用满表面随机噪声代替设计 |
| pattern | lo/hi/palette/seed及可选权重、scope/mode/from_states等 | 通用带权混材、区域/表面筛选、连片噪声及兼容状态保留；保护坐标跳过并报告，详见[通用方块模式](patterns.md) |
| auto_floor | profile/style_note/seed及可选预算、exclude_boxes等 | 从config的start/targets/ports/interior_probes自动识别多层地面、匹配半砖并保护必要通路，归主体层；详见[自动地面](floors.md) |
| weathering | lo/hi/from_states/seed/moss/cracks/floor | 连片苔痕、持续裂纹与半砖/整块地面破损的统一操作；比例、片区、坑深与坑缘裂纹可配置，详见[连片风化工具](weathering.md) |
| geometry / replace | 有界CSG几何或精确状态替换 | 球、椭球、柱锥、圆环、曲线扫掠、多边形拉伸，详见[建模工具](modelling-tools.md) |
| copy_region / repeat_region / transform_region | 范围、偏移或目标原点、变换参数 | 快照复制、线性阵列、保守状态旋转/镜像；墙归属显式选择 |
| morphology / diffusion / explosion / scatter | 范围及各效果参数 | 六邻接形态学、连通扩散、静态爆破与带间距散落；不是物理模拟，详见[建模工具](modelling-tools.md) |

state支持合法Properties，例如楼梯方向和半砖上下；工具不执行计划中的Python。surface_palette在全局坐标上采样，同seed不按分片重置，跨切面材质规则一致。基础操作可组合成非模板化的节点，不能机械把每个表面都框一圈。完整曲面/空腔大改属于整体改稿，不是局部精修。

工具拒绝超出整体尺寸/缺角、修改门洞和保护区、超过变化预算的计划；随后再次做整体密闭和玩家路线检查。整座全局模型处理完才导出，不在导出循环中新增几何。

weathering在规划时避开保护区，并将目标/实际比例、片区格数、无法满足的缺额及强制坑缘裂纹记入refinement.json。对裂纹/苔痕按连通关系生长，不使用独立撒点补预算；地面层和材料映射须明确。单命令nbt_weathering.py沿用本流程的review及既有确认，不提供绕过确认的资产写入入口。

## 输出与复核

精修写全新目录，不覆盖source或review：

- refined.master.json.gz：精修后的完整全局主模型与更新后的墙mask。
- plan.json、changes.json：实际计划、每个变化坐标的前后状态、墙归属变化。
- validation.json：精修后整体密闭、合法门、路径/指定连接及运行时未验项。
- comparison.png：相同相机的前后对照；refined_XX.png为精修后图，元数据绑定精修几何指纹。
- delivery：每有效cell的body/walls两份稀疏NBT；1×3仍恰好六份。
- runtime：另存完整体积模板，不混入delivery文件计数。
- refinement.json：确认关联、源/精修指纹、变化数、保护范围与pending visual review状态。

工具通过不意味着美术自动完成。实际查看对照，检查新增构件是否有支撑、材质主次是否更清楚、全局风格是否一致，发现问题在同一整体版本上修正并重验、重切。不要拿漂亮近景掩盖布局被改坏，也不把程序配色当真实游戏材质/光照。

回归命令：`python .agents/skills/minecraft-nbt-modeler/scripts/check_refine_fixtures.py --output nbt_models/_tests/refine_validation`。它只创建合成测试数据，验证授权前拒绝、旧图/旧源拒绝、保护范围、泄漏/碰撞反例、全局跨切面细化、原稿不变与六文件重切，不批准或精修现有用户作品。
