# 空间与细节设计

本参考用于解决“同一个模板”“平层”“细节空泛”“创意不充分”。目标是把想象落实成可观察、可穿行的方块建筑。示例提供推演方式，不规定题材、层数或构件清单。

若重复首先来自空间骨架，先用 [开放选型与空间设计语法](design-grammar.md) 重新考虑邻接、空实、剖面和视线；需要新的场所用途时选读 [扩展场所原型库](structure-atlas.md)。增加道具、材质和节点密度不能代替这一步。后文的桥、书库、工业设施只是说明方法，不使这些题材成为默认选项。

新建或重设计建筑时完整阅读本文，不能只读标题、开头、摘要或从中搜索几个关键词替代。遵守SKILL.md的两阶段流程：整体初稿先落实空间构想、基本构造和代表性主题细节，经过下列设计验收再向用户展示缩略图；用户明确同意后，才把节点细化方法全面用于精修。精修恢复完整未切割主模型统一处理，完成后再机械切片，不能逐片套用不同构件风格。

## 初稿设计验收

尺寸推演先用 [玩家尺度与尺寸起点](player-scale.md)：围绕两格高的玩家设计包络安排站位、道具和通行，再决定净跨度与顶高。48格占用单元不等于48格净空厅；细节丰富不以扩大建筑实现。宏大场所保留整体意图，同时让局部活动区和近处构件能以玩家尺度阅读。

初稿是可判断设计方向的建筑，不是技术占位体。构造细节会影响比例、风格、空间用途和玩家感知，因此不能全部留到精修。以下按作品中实际存在的内容检查；不适用项说明原因，不强制任何建筑都用拱、梁、栏杆、机器或装饰。用户明确要求灰模、极简或特定简化程度时按该范围验收，不擅自扩大任务。

| 检查维度 | 初稿应已有的几何证据 | 不足以通过的表现 |
| --- | --- | --- |
| 空间与用途 | 主次空间、真实层级、停留/操作/通行位置与相应视线 | 只有房壳和几块平台，标题替代用途，空地没有空间作用 |
| 玩家尺度 | 已记录主要活动区净尺寸、路线净宽/净高及代表道具与站位；玩家视角能判断近处构件和整体比例 | 将48格模板挖成默认巨厅；家具随建筑等比放大；远景有轮廓但日常路线旁没有可读内容 |
| 支承与连接 | 可读的梁柱承接、拱脚落点、桥头、根岩过渡或作品自身的幻想支承规则 | 薄板直接悬空，柱顶硬接细肋，树干与岩体简单相交且无过渡 |
| 围护 | 按构造组织的墙厚、进退、开口深度或洞壁成因 | 无特征平墙围满全场，均匀随机换材质 |
| 天花板与顶部 | 与用途、跨度相称的可见顶面，连续的支承关系、墙顶收口及分区过渡；详见下节 | 只补密闭平板、贴悬空肋、换色或撒灯；仅凭去顶剖视宣布完成 |
| 边缘与转折 | 重要台阶转折、平台端部、池岸、座席排端、护边或压顶与整体相称 | 所有边缘裸切、立柱间没有声称的栏杆、设备与步行面互相挤占 |
| 主题构件与配套 | 主要构件有可辨的部件、支承、接口/使用侧及相邻配套；自然主题以地形/生长关系表达 | 用长杆、色块或方盒命名“设备”，只放中央奇观，外围仍是无特征盒子 |
| 风格与主次 | 从轮廓、跨间、构造尺度、材料部位和重点节点能读出所选方向 | 只靠颜色、招牌、标题或一枚标志宣称特定风格；所有表面同密度碎装饰 |

先选对全模型有代表性的节点，完成真实连接与基本收口，再把相同构造规则落实到其余主要区域。不能只做一个精致角落供拍摄、其余全是占位物；也不要求初稿把每个背景角落全部精修。留白应有用途或构图理由，克制构造也可以完整，不以装饰数量、方块数量、材料数或固定节点配额衡量质量。

初稿可暂缓的是全表面微小接缝、全套次要道具、细微风化差异和整批局部纹理优化；不能暂缓承接、主要边缘、可辨主题构件及整体构造语汇。若这些项目不足，先修初稿而不是直接宣布进入等待精修；不得伪造批准或调用需要用户确认的精修apply来绕过阶段边界。

查看实际落盘模型的整体、未剖切入口和能看清代表构造/主题部件的近景；有实际高差时补能判断高低关系的视角。若顶壳被剖切隐藏，另看完整顶构或室内支承视图；若相机看不清部件，调整后重新看图。远景色块、图已生成、渲染像素非零、代码中有名为“设备”的函数，都不能作为细节通过证据。预览能力不足时记录具体未验证内容，不能把“无法判断”写成通过。

## 天花板与顶部构造

从玩家站立位置向上设计，区分密闭顶壳、可见顶面和承托/吊挂构件的作用；它们可以由同一构造承担，不要求额外叠三层。设计笔记说明顶面如何回应空间用途、跨度与主要视线。初稿就要形成主要轮廓、支承、墙顶交接及代表节点，不能把整个天花板推迟到用户批准后的精修。

- **顶面有组织**：按空间选择梁板、折面、券顶、穹面、井格、玻璃框架、连续岩层或其他合理形式，不设必选类型。平顶允许用清楚的板跨、厚边、局部凹入或克制的整体面成立，不强迫拱顶、吊灯、复杂花纹或固定高差；单块均质盖板若仅为封口、与室内关系不明，则需修改。不要在全部房间重复同一套肋架后仅换材料。
- **跨度与支点可读**：主梁、次梁、拱肋或岩体过渡应能解释顶面由哪里承托；构件尺度与跨度相称，柱顶、梁端、拱脚有实际落点及必要的托座或加厚。检查斜梁和阶梯肋的转折连续性，不能仅靠方块棱角碰触、隔空对齐或视觉投影重合宣称连接。吊挂件接到真实梁架、锚座或明确的幻想支承，不在薄玻璃上无理由挂重物。这是几何与构造表达检查，不宣称工程承载验算。
- **上部体积与用途相应**：顶高、跨间、实体厚度和留白应服务于下方活动及视线。多区域可以共享屋顶，也可用不同跨度、构架或局部顶高表达主次；分区交界要有共同梁、连续板面、收边或其他可读过渡，不能只把两种平板沿分界线硬拼。若使用错高，模型中落实过渡与封闭，不强制各区都升降。
- **墙顶和边界有收口**：墙、柱、顶面交接处按建造逻辑形成边梁、压顶、拱脚、凹槽或自然岩肩；无需机械给所有面加边框。玻璃顶有面板边界与框架承接，洞顶有连续岩体和洞壁过渡，不能以随机凸块冒充地质形态。屋脊、采光带、烟道和顶面破损仍遵守封闭交付要求；模拟天窗时明确其封闭材料，不虚构真实采光效果。
- **照明与设备服从顶构**：灯槽、吊架、管线和风罩按路线或功能节点布置，保留载体、接头与端部关系；允许不设吊挂设备。避免满顶等距发光块、密集吊杆或无用途的装饰网格。程序预览无法验证的透光、阴影、材质与实际亮度单列未验证。
- **检查最低净空**：以实际步行面为基准检查梁底、拱脚、吊灯、管线和台阶转折；上层平台与楼梯高处也要检查，不能只用房间总高推断可通行。在 `coordinates.json` 记录关键低点的坐标/底面Y及对应脚位Y，半砖和楼梯按实际碰撞形状计算。必要路线上的新增顶部构件要纳入通路复验，门后仍保留标准门洞及喉道净空。

**顶部视觉验收**：从最终落盘NBT实际查看室内仰视，保留视线内完整的顶面、支点和墙顶连接；相机设在真实可站立点脚位上方约1.62格。覆盖每种不同的主要顶构及分区交接，并查看能判断构件接触的代表节点近景；可以复用已有入口/节点图，不要求固定图片张数。浮动QA相机可以补充接头，但不能代替玩家视角判断压迫感、遮挡与顶高体验。剖去屋顶的鸟瞰图、外部屋面图或只拍到一块板的仰视均不足以验收室内天花板；剖切隐藏了哪个构件，就不能据该图验收它。

在设计验收记录中单列顶部的组织与主题、支承与收口、路线净空及已查看证据。发现无支点肋架、未处理的分区顶面或大面积封口占位板，先补足初稿并重验；若预览不能判定连接或顶面效果，记录具体未验证项，不把密闭通过当作顶部设计通过。后续精修沿用同一标准并查看前后对比，不要求重做已充分表达的克制平顶。

## 从场所的成因推演形态

先形成一个能指导建模的概念：这里原本如何使用，发生了什么变化，玩家沿怎样的路线读懂它。只写“废弃神庙”“复杂书库”不够；继续推演到能改变空间的事件、用途或结构关系。

例如“山体挤压了一座地下渡槽，维护人员沿断裂水槽修起绕行栈道”：水槽应有连续的流向和高程，断口对应错位的支座，栈道绕开危险断面，沉积集中在低处，旧水位痕迹留在墙上。每个细节都有位置原因，不是随机裂纹加随机桥梁。

幻想不必受现实建筑形式限制，但要有作品自身的一致逻辑。悬浮机关可以用能量环、锚座与对位关系表达支撑；巨木档案馆可以让根系托住书台、裂缝导入光线、旧通道沿年轮绕行。奇观同时改变体量、路线、尺度或观察方式，不能只是普通大厅中央多放一个装饰球。

## 把构想发展成整体

先在脑中或草图里检查入口、主视点、转折、上下层连接和终点。安排进入时的局部遮挡、转弯后的展开，以及从新高度回望旧路线的关系。高处应有值得抵达的空间，低处应有与上层不同的体验；路线可以相互看见而不处处相交。

为主体选择相称的构造语言。厚重遗迹可用收分、扶壁、深门套与承重拱；轻型工坊可用梁架、吊挂、维护平台与设备接口。结构和道具围绕主构想生长，不把同一套柱阵、四门和中央圆环套在所有题材上。

不同作品可以共享一个世界观与材料体系，同时拥有不同构造。例如同一古代水利设施里，落水竖井、沉砂池、悬渠检修段各自有完全不同的剖面与路径。创造力不要求每件作品都更换世界观。

## 按观察尺度细化

| 观察层次 | 建模内容 | 检查重点 |
| --- | --- | --- |
| 远看与入口 | 主体轮廓、空腔、挑空、楼层错位、标志性构筑物 | 不靠标题能否辨认空间，视线有没有重点 |
| 行走中 | 梁架、拱券、凹廊、楼梯、支座、桥面、墙体厚度 | 构件是否有连接关系，高差是否影响行走与观察 |
| 靠近时 | 门槛、栏杆端头、柱础、压顶、接缝、壁龛、嵌件、主题道具 | 细节是否实际存在，是否符合所在部位的用途 |

墙不能只是一张平面加随机异色方块。可以围绕结构节奏安排墙脚、凹槽、壁柱、检修口或深窗；顶部应有与空间相称的梁、拱肋、岩层或覆盖构造。桥不能只是一片悬空薄板，要考虑桥头如何落地、转折如何连接、边缘如何表达。选用适合概念的做法，不机械填满表格。

允许使用合法的楼梯、半砖、墙等形态细化轮廓，正确保存Properties与方向；现有简易写入器不支持的状态需要扩展写入器，不能以工具限制把所有精细构件退化成完整方块。方块实体、动态机制等仍遵守当前加载约束。

## 细节密度与空间叙事

把细节集中在有意义的位置：入口、构造转折、视线焦点、可探索侧区与功能节点。保留大块干净体量和净空，给人判断尺度与方向的余地。重复构件应服从结构节奏，在节点处变化，避免全表面均匀装饰。

材质按用途分配：承重、铺装、金属接口、修补、沉积各有位置。损坏沿受力、积水或使用痕迹发展。光源有载体、朝向和节奏，用明暗组织路径与焦点；不能把每根柱顶统一换成灯就算完成照明。没有在游戏中看过时，不宣称实际亮度或氛围已经验证。

道具应可从几何辨认其用途或主题：操作台、卷轴架、排水闸座、运输吊架、祭仪残件等，需要尺度、部件与摆放关系。不支持的容器和方块实体可用静态几何表达外观，不能宣称具有交互功能。

手边的小道具和部件按[细微道具与部件](micro-props.md)处理：可以使用合法原版薄构件和方向状态，把工具挂点、把手、夹口、书托等落实为实际几何。主体、支承、细部和使用侧共同入画；不以大方块占位或给整方盒改名代替细部，也不以均匀增加小件数量作为完成标准。预览/碰撞不支持的细形状保留具体限制或补有依据的工具支持，不能为绿报告抹掉细节。

细节不能只集中在一个中央奇观上，外围始终留作无特征盒子。围绕主角继续推演配套空间与关键连接：工业建筑的运输、加工、操作与检修如何衔接；书库的存放、取阅与阅读如何展开；祭仪建筑的进场、聚集与仪式位置如何组织。按题材选择有意义的关系，不强制把所有建筑都做成工厂。道具既要有可辨认的部件，也要与人的站位、通道和建筑尺度相称；命名成“设备”的几个小方块不算完成设备设计。

对于结构连接，近看桥梁支座、平台托架、梁柱节点和栏杆实际状态。重复小立柱不自动构成连续护栏；预期横向连接、收口或承重关系时，需在几何或有效方块状态里落实。不要为增加复杂度添加无法解释的悬空细杆、均匀柱帽或密集色带。

## 批量创作与复核

在开始批量建模前，为各件作品用简短设计笔记记录概念、空间骨架、竖向路线、主焦点和局部特色；材料颜色不算空间骨架差异。笔记存入任务输出目录即可，不要求用户逐件审批。

先对照本批笔记检查构图套路：若每件都是方形高井、四周楼梯和中央悬物，即使中央物体题材不同，也需要重新构思其中的空间组织。高差可以来自不同的地形、建筑用途与结构关系，不能自动把“多层”翻译成同一种竖井。这里判断的是作品间实质差异，不是禁止任何单件使用竖井或中央主角。

先完成一件有代表性的初稿，由负责汇总的主agent实际查看入口玩家视角、剖视和构造/主题节点近景，记录缺项并修至初稿标准，再开始其余作品的主体建模。可以同时构思其他方向、准备工具和核对协议，但不先让全部生成器复制未经视觉验收的简化手法。若剖视只有空盒子加平台，继续发展体量和连接；若近景仍是大平墙加散点，细化节点与构件；若满屏碎块，减少噪声并强化主次。随后制作其他独立构想，不复制第一件的骨架批量换皮。代表作通过不免除每件自身的视觉与技术检查。

从实际画面写下最影响完成度的具体问题，再决定是否需要修改几何。修正不能仅限把标题改得更漂亮、把相机改到看不到缺陷的位置，或把所有局部夸成“细节丰富”。确认被指出的设计缺口已在最终NBT里改善；修改受影响的验证也要重新运行。

视图要证明其声称的内容：宣称登高改变观察体验，就拍一张可站立上层位置的玩家视角；浮动检修相机只能证明节点几何。剖切隐藏了屋顶时，不能同时据该图宣称顶部吊挂连接已验收，应另选能看清支点的视图。剖切元数据完整记录所有删除平面，既不让外墙遮住主体，也不把柱头、拱肋的剖切断面当成真实破损。近景标题所指的地面设备、支架或接口必须实际入画。

最后检查设计是否落实到最终NBT，预览与数据是否一致。区分设计复核、密闭验证、标准开洞和游戏通行验收；它们不能互相替代。装饰修改可能造成漏口或挡路，修改后重跑受影响的检查。遵循SKILL.md中先密闭验收、再标准开洞的顺序。

## 设计验收记录

在每件任务目录的 `design_review.json` 或已有同等报告中记录下列内容，不另建只检查文字匹配的测试来冒充视觉验收：

- **阅读范围**：引用 `reading_record.json` 中本件适用的文件/章节、读取状态与影响设计的具体决定。
- **技术项目**：开洞前密闭、端口、碰撞路线、落盘回读、48重组分别通过/失败/未验证；49必要路线、49围护和旋转单独列出。部分目标通过不能概括为全部通过，失败目标保留名称和坐标。
- **设计项目**：空间、构造细节、主题表达分别给通过/需修改/未验证，并写实际几何位置与对应图；不用一个总 `passed=true` 覆盖缺项。
- **尺度项目**：引用主要活动区净宽/深/高、路线最窄/最低点、代表道具与玩家站位坐标；说明必要大净空的用途，并关联实际玩家视角的比例与近处细节结论。仅设计推演不填写已看图或碰撞通过。
- **细微道具项目**：有此类设计时，记录实际小件状态、安装/支承与使用侧、近景证据、邻接或碰撞未验证项；初稿必需部件不能一律留给精修。
- **顶部项目**：单列顶面组织与主题、支承与墙顶收口、最低通路净空的结论，关联实际坐标和保留顶构的室内仰视/节点图；技术净空与设计质量分别判断，不用去顶鸟瞰代替。
- **已查看证据**：图像实际路径、源NBT/主模型指纹或可追溯清单、相机与剖切元数据、实际观察结论。记录的是已经查看的图，不能预先填完成标志。
- **缺项与处置**：具体问题、是否影响初稿方向判断、补改及重验结果；用户确认后的进一步精修另列，不与初稿必要修复混写。

技术通过而构造或主题不足时，总结为“技术项目通过，初稿设计未达标”，不能称“可审阅初稿完成”或“只差精修”。满足适用的初稿设计标准且已完成相应技术检查后才标记初稿完成；运行适配失败的设计可以作为明确标注的素材/兼容问题样本展示，但不能称可正式接入。自报阅读、文件哈希和报告字段本身都不能证明审美质量，主agent仍须复核实际图像。

SAO层主题或房间选址需要额外参考时，再读 [房间风格与选址参考](SAOartguide.md)；该文件用于主题适配，不替代当前工程的运行协议，也不自动授权修改玩法或房间池。
