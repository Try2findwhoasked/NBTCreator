# 整栋建筑量化规划

复杂整栋的平面分区、跨层交通、净面积和体量可以先用布局报告检查，再对实际制作源复验。有参考图时，从可辨轮廓、入口、层级和主要空间反推任务书。用途、活动和建筑语法仍按设计需要选取。简单亭子可用[短路线](simple-building.md)。

## 把设计意图写成任务书

- 给楼层、空间和要求的连接分配稳定 ID。房间记录用途、层级、净地面面积区间，可另定目标和最小可用跨度。用 `source` 区分用户、项目与 Agent 推导，用 `note` 记录来源或取舍。项目的文字规范由 Agent 转写为明确字段，项目规则和用户要求冲突时，把冲突和影响交给用户决定。
- 楼层 `footprint` 是空间可以进入的 XZ 网格范围。所有平面矩形包含两端，可取多个矩形的并集。层间用脚位标高和顶界区分，挑空与楼梯预留用当前楼层的区域表示。需要约束实际实体时，另给整栋 `max_extent` 或逐层 `envelope`。
- 几何相邻、留出墙内门位和实际通过属于不同的证据。直通门用共墙中的开口图形。跨层连接用上下层实际脚位，需要走指定梯段时给出建筑方案中的楼梯 ID。需要从入口经过门与梯段进入各空间时，用 `entry_space` 声明入口归属。
- 面积区间、必经通路等作为硬约束。目标面积偏差、交通面积和重排改动数供候选比较，后续再用剖视和实际玩家视角核对空间主次。

从创作项目根目录查询真实字段。将[两层档案馆规划样例](../assets/examples/whole-building-planning.json)放在创作项目，例如命名为 `planning.json`。

```powershell
mise run nbt -- capabilities --architect-action layout-check --field program
mise run nbt -- capabilities --architect-action layout-search
mise run nbt -- architect layout-check --request planning.json
```

## 布局、编译与复验

1. 用 `layout-check` 检查手写的 `program + layout`，按问题的层级、世界坐标和稳定 ID 调整。规划净地面积取房间格的并集。候选阶段的门位宽度基于房间中间一格隔墙的连续开口，跨层阶段核对停靠点位置与标高。
2. 需要探索候选时，把已有布局作为 `baseline` 调用 `layout-search`。保留指定空间时使用 `locked`，保留上下层脚位时将其登记在基线的 `links` 中。搜索新增空间以正交矩形为单位，已选区域可用多个矩形。相同输入得到相同的候选顺序。`infeasible` 表示已穷尽支持的布局空间或发现固定条件冲突，`budget_exhausted` 表示本次搜索预算内未找到候选，`input_required` 返回缺失的楼梯停靠点。
3. 把选定的 `program + layout` 和建筑方案模板一并交给 `layout-prepare`。回执的 `plan` 包含分区、脚位与规划绑定。由 Agent 按门位、围护和跨层预留完成实际构件、开洞和视角，再把 `plan` 传给 `plan-build`。模板中的构造、已登记活动和保护上下文继续适用。布局锁定保护候选中的房间范围，已有方块由制作源的保护与续版约束控制。
4. 保存并回读时，把 `source + source_sha256` 传给 `layout-check`。成品净地面积统计声明区域内有真实支撑且未被标注墙体占用的格。可站面积再检查净空，可达面积按指定入口的静态碰撞通路统计。挑空检查指定楼层脚位处的地面，明确登记的楼梯预留区可以承接梯段。直接门位单独实测，绕行只说明目标房间可达。
5. 回执的 `status`、`expected`、`actual` 和 `positions` 分别给出状态、目标、实测与位置。入口可达的检查已找到合格路径时可通过，完整可达面积在预算耗尽或存在未知碰撞时保留待测。按首次失败的条目修改，变更后保留原任务书条件重测。发布初稿、用户看图确认和手动定稿继续走[建筑方案闭环](architecture-workflow.md)。

桌面从「建筑工具 → 整栋建筑规划」打开。可导入同一个请求、编辑面积区间、锁定空间、比较候选，按回执查看逐层平面与指定 Z 的剖面。打开有配置绑定的 SNBT 后可直接复验制作源。
