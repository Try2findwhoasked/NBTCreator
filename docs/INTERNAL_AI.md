# 内部AI与对外Skill

AI助手设置分为两个独立页面：

- **内部 AI · API / 工作流 / 资料**：左侧配置应用调用的API连接；右侧按使用位置设置补充要求、Rule规范和内部资料。
- **对外 Skill · Agent 知识暴露**：控制当前项目中Codex/文件式Skill Agent读取的知识路由，生成原有工作区Skill入口；不自动上传给API。

内部AI有6个工作流：完整初稿、控件配置、文字编写、局部编辑、小型结构/3D放置、资产管理独立结构。每个流程显示实际处理步骤，并可独立编辑设计要求和规则、选择资料。生成接口自动匹配使用位置，用户不用每次手选工作流；内置返回协议、选区约束、保护与批准仍由应用控制。

内部库支持5份内置参考和自定义Markdown/TXT。导入只复制资料，不默认选中；在需要的流程勾选并保存后，点击生成才把该流程选中的**全文**发给当前API。其他流程未选择的资料、对外Skill知识列表和本地路径不会自动附加。

内部配置在当前工作区 `.nbtcreator/internal-ai/config.json`，导入文档在其 `knowledge/` 目录，以内容SHA256去重。API Key仍在Windows用户加密配置中。切换工作区会加载目标自己的内部AI配置，不读取上个工作区的资料；对外Skill配置继续使用原 `.nbtcreator/skill-exposure.json`，两者互不修改。

可通过取消勾选减少某流程发送的资料；导入的原文保留。单文件最大256KiB，单次选中全文合计最大48000字符，超出时明确要求减少选择，不静默截断。规则和资料不能授予自动精修批准、越界写入或任意代码执行。这里配置的是现有功能的处理规则，不是任意可执行脚本或自主Agent流程。

保存内部规则不会生成Skill文件；保存Skill暴露也不会修改内部流程。内部资料是用户选择发送给API的任务参考，应只导入愿意发给所配置服务的内容。

1.7为内置资料添加摘要与适用场景，内部和外部资料均可查看原文；外部知识组列出实际文件，并可预览已生成的Skill入口。基础规则始终随对应流程发送，已保存的自定义Rule另行保留；二者仍不能改写本地执行协议。小型结构固定使用选区相对坐标，AI无需输出NBT编码或palette索引，脚本负责平移、注册表/保护/预算检查、合并与导出。


## 各区域创作滑块与 Skill 共用

每个工作流有独立的创作自由度、描述详细度、装饰复杂度、方案变化度（0～100）。四组分别对应保守／天马行空、简洁／详细、朴素／丰富、延续现有／探索变化。配置保存在工作区 `.nbtcreator/ai-style.json`，应用请求会附带本流程数值和对应说明，外部 Skill 入口也指向同一配置，并提供 ai-style show/set/prompt 命令。原内部规则、截图开关、知识库选择继续保存在 internal-ai/config.json；创作滑块不会将内部资料或凭据暴露给外部。

生成时读取最新共用配置；外部改动后，页面可用“重新读取”刷新。用户本次要求优先，偏好不会改变返回协议、选区、保护、预算或看图确认要求。


## API 详细请求配置与 JSON

AI助手的内部API连接区域提供“详细请求配置与JSON”。采样温度 temperature（0～2）、top_p（0～1）、输出长度 max_tokens（1～32768）、presence/frequency_penalty（-2～2）、seed可用控件填写；JSON还支持stop（最多4条）、reasoning_effort（low/medium/high）和thinking:{type:enabled/disabled}。是否接受这些参数取决于接口和模型，不保证所有服务支持。留空项不发送，长度留空沿用应用默认：文字4096、构件/控件8192。

JSON与控件互通，编辑JSON后可回填控件，点击“保存连接”才进入主进程校验、保存并用于请求。请求超时5～300秒，输出长度字段可选 max_tokens 或 max_completion_tokens；后者将相同长度映射为该参数名，不同时发送两个长度字段。模型、消息、stream和结构JSON返回协议由应用管理，不能通过高级JSON覆盖；不接收自定义脚本、HTTP头、Key、路径或消息数组。

连接及请求参数与原API配置一起保存在当前Windows用户目录，Key单独加密，不写入项目或Skill。表单/JSON保存失败保留已有有效配置；API接入关闭时仍不联网。保存部分配置不再丢失其他已配置字段。UI对照和本地模拟请求验证参数实际发送，未验证真实服务商兼容性或生成质量。

## 请求减量与耗时诊断

文字润色只发送设计字段和工具意图摘要，不发送工具坐标、几何数组或完整工具序列。相同意图合并计数，未启用与不同材质的步骤保留区分；本地原工具计划、保护配置与阶段规则不受润色影响。12000字符的润色摘要限制只适用于文字模式，控件和完整初稿仍保留完整工具上下文；各模式对用户实际指令的12000字符限制继续生效。

基础规则与已保存Rule完全相同时只发送一次；自定义Rule继续与基础规则共同发送。勾选知识仍按上文发送全文，未做静默章节抽取或裁剪。结构任务要求紧凑JSON和简短summary，完整初稿的空间、动线与承托要求保留。

任务详情显示截图、API往返、生成候选合计和本地预览耗时。候选合计不包含用户之后的审阅等待。每次API尝试分别记录响应等待、接收、解析、请求/响应字节量、输入文字规模、返回原因，以及接口实际提供的token统计；失败、取消、截断精简重试也保留测量。JSON解析与本地参数校验单列。非流式接口的“等待响应”可能同时包含排队和生成，不能据此区分服务商内部阶段。

重试的token数量按接口已报告的用量累计，并保留每次数据；未提供用量的尝试显示为缺失，不按零消耗计算。新增测量字段使用白名单和长度上限，不保存API请求体、响应原文、截图内容或认证头。跨Electron桥的生成失败使用内部`api_error`数据封装，调用层再转为错误，避免跨进程丢失诊断字段；其他IPC权限与工作区失效检查保持。

## 控件工具的增量返回

控件配置请求会附带`operation_base`：完整方案基线SHA256和从1开始的各步骤编号/原步骤SHA256。应用另外对包含源路径、保护设置等本地状态的完整表单计算`baseline_binding`，只发送哈希，不发送其中路径。不同源或本地状态不能复用旧候选。

AI仅修改已有步骤参数时，可返回`operation_patch:{"baseline":"原基线","changes":[{"step":12,"expected":"原步骤SHA256","set":{"state":"minecraft:andesite"}}]}`，最多16项，不与`operations`混用。应用先核对两个指纹、步骤范围和字段白名单，原子合并到请求时的完整本地序列，再沿用整体参数校验、用户采用以及后续引擎预览检查。收到候选和采用前也继续核对完整表单绑定；生成期间或审阅期间的本地编辑会使候选失效。

增量不会修改工具类型、覆盖开关、写入组或单步预算。新增、删除和重排仍用原完整序列协议（最多64步），不猜测增量动作。原方案最多128步，完整保留而非截断；可对其中任意一步做参数增量修改。API返回的是短增量。主进程先对发送上下文验证合并，界面再在绑定未变的完整本地序列上重放已校验增量；不会用精简后的API上下文覆盖本地原序列，也不会丢掉未上传的写入组、体素等字段。应用内候选显示合并后的完整序列，便于审阅和沿用原导入导出流程。

## 小构件名称与一个建议视角

小型结构可在返回JSON的根对象加入`structure_name`（1～120字）和一个`camera:{"azimuth":45,"elevation":25}`。水平角范围-180～180度：0从+Z观察，90从+X观察；俯仰角范围-90～90度，正值俯视。旧接口没有这两项时，用第一步名称和45°/25°作为默认观察建议，不影响旧候选兼容性。

AI只给两个角度，本地脚本以平移后的构件操作范围和当前视口比例补齐`eye/target/up/fov`与观察距离。构件预览后可点击“查看构件视角”，切换相机而不改变几何、剖切、图层或光照。该机位用于观察，不声明玩家可站立或保证无遮挡。视角参数可在面板展开查看；名称与角度随版本绑定的构件草稿保存，整体移动后重新计算实际镜头。它们不写入Python操作字段，也不触发正式NBT导出或确认。


## 资产管理独立结构

资产管理增加“Agent创建独立结构”和“独立3D查看”。新建不依赖当前建筑；可使用内部API生成，也可粘贴外部Agent参数，并可引用已有资产的编号与内容哈希。内部AI只接收精简的参考元数据，由同一Python引擎解析完整体素、组合与预览。保存按钮只对当前已加载的真实候选开放，参数改动后须重新预览。已有资产3D查看保持只读，不影响模型编辑状态。

所有入口共用tool-catalog.json的agent_tools参数Schema和component-assets.md规范。结构工具覆盖list/read/view/preview/write/place，CLI通过components agent调用，应用通过同源components/agent调用。预览、保存新资产、按参数放置与手动NBT导出分阶段进行，仍保留真实看图与源/几何哈希检查。独立结构使用新增component创作偏好与内部工作流；旧五区域配置保留并补齐新区域，旧截图选项不会自动发送给新工作流。
