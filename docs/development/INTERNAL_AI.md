# 内部 AI 与对外 Skill

AI 助手设置分为两个独立页面：

- **内部 AI · API / 工作流 / 资料**：左侧配置应用调用的API连接；右侧按使用位置设置补充要求、Rule规范和内部资料。
- **对外 Skill · Agent 知识暴露**：控制当前项目中Codex/文件式Skill Agent读取的知识路由，生成原有工作区Skill入口；不自动上传给API。

内部 AI 有 7 个工作流：提示词交接要求、控件配置、文字编写、局部编辑、小型结构/3D 放置、资产管理独立结构、选区自然语言编辑。每个流程显示实际处理步骤，可独立编辑设计要求和规则、选择资料。生成接口按使用位置自动匹配工作流，无需每次手动选择；内置返回协议、选区约束、保护与批准仍由应用控制。

内部库提供 10 份内置参考，也支持自定义 Markdown/TXT。新增的构件、纹样来源、纹样拟合、贴面安装和对象联动专题可独立选择，不默认勾选；根据当前阶段添加资料。导入时只复制资料，不默认选中。在相应流程中勾选并保存后，点击生成才会把选中资料的**全文**发送给当前 API。其他流程未选择的资料、对外 Skill 知识列表和本地路径不会自动附加。

内部配置在当前工作区 `.nbtcreator/internal-ai/config.json`，导入文档在其 `knowledge/` 目录，以内容SHA256去重。API Key仍在Windows用户加密配置中。切换工作区会加载目标自己的内部AI配置，不读取上个工作区的资料；对外Skill配置继续使用原 `.nbtcreator/skill-exposure.json`，两者互不修改。

取消勾选可减少某个流程发送的资料，导入的原文仍会保留。单文件最大 256KiB，单次选中全文合计最多 48000 字符，超出时会提示减少选择，不会静默截断。规则和资料不能授予自动精修批准、越界写入或任意代码执行权限。这里配置的是现有功能的处理规则，不支持任意可执行脚本或自主 Agent 流程。

保存内部规则不会生成 Skill 文件，保存 Skill 暴露配置也不会修改内部流程。内部资料用于发送给 API 作为任务参考，请只导入愿意发送给所配置服务的内容。

内置资料提供摘要与适用场景，内部和外部资料均可查看原文；外部知识组列出实际文件，并可预览已生成的 Skill 入口。基础规则随对应流程发送，已保存的自定义 Rule 另行保留；二者仍不能改写本地执行协议。小型结构固定使用选区相对坐标，AI 无需输出 NBT 编码或 palette 索引，脚本负责平移、注册表/保护/预算检查、合并与导出。

提示词方案默认只辅助人编写简明设计意图，不生成工具步骤或运行 Python 几何预检；高级工具提案继续使用受限工具协议。完整流程见[首次创作](../guides/PROMPT_CREATION.md)。

## 人工参数、局部建议与任务交接

`tool-catalog.json` 的 `prompt_design` 统一定义人工设计字段、默认 AI 修改范围和尺寸策略，生成的提示词前端目录、主进程协议与 Python 归档校验共用该契约。新增空间特色、材质分工、光线氛围和避免项；各部位意图可留空，由执行 Agent 推导具体构造。新建独立建筑默认参考尺寸，旧方案、已有模型和 SAODG 使用固定尺寸。

前端发送 `task: "brief"` 和 `brief_scope.editable_fields`。内部 Skill 只要求简短 `summary` 与部分 `project_patch`，至少包含一项允许修改的建议；未返回字段保留人工值。主进程拒绝修改未勾选字段，过滤原样返回的非选中字段，前端采用时再次核对范围。尺寸策略、源路径、阶段、保护和批准不属于补丁字段。请求指纹绑定设计内容和修改范围；已采用说明只绑定设计内容，避免下一轮调整范围时丢失已采用文字。

最终提示词只有一个组合入口：人工参数、可选设计说明、通用执行与存放约束按固定次序输出，补充说明不覆盖结构化硬条件。批量新条目默认继承设计值、尺寸策略及修改范围，可关闭继承；不复制当前模型、操作或确认。发布沿用带内容哈希的不可变任务修订，完整保存设计、正文和上下文，外部执行 Agent 通过既有 CLI 领取。

该改动不新增自主 Agent 调度层。内部模型负责文字建议，软件负责字段边界、组合、绑定和存档，执行 Agent 负责建模与验证。旧配置中完全等于原出厂值的提示词方案规则会加载为新规则；自定义规则、补充要求、截图开关及资料选择保留。


## 各区域创作滑块与 Skill 共用

每个工作流有独立的创作自由度、描述详细度、装饰复杂度、方案变化度（0～100）。四组分别对应保守／天马行空、简洁／详细、朴素／丰富、延续现有／探索变化。配置保存在工作区 `.nbtcreator/ai-style.json`，应用请求会附带本流程数值和对应说明，外部 Skill 入口也指向同一配置，并提供 ai-style show/set/prompt 命令。原内部规则、截图开关、知识库选择继续保存在 internal-ai/config.json；创作滑块不会将内部资料或凭据暴露给外部。

生成时会读取最新的共用配置。外部修改配置后，可在页面点击“重新读取”刷新。本次用户要求优先于创作偏好；偏好不会改变返回协议、选区、保护、预算或看图确认要求。内部提示词编写／润色把“详细度”解释为设计意图和取舍的说明程度；外部执行 Agent 仍沿用建造说明，两者读取同一组数值。


## API 详细请求配置与 JSON

AI助手的内部API连接区域提供“详细请求配置与JSON”。采样温度 temperature（0～2）、top_p（0～1）、输出长度 max_tokens（1～32768）、presence/frequency_penalty（-2～2）、seed可用控件填写；JSON还支持stop（最多4条）、reasoning_effort（low/medium/high）和thinking:{type:enabled/disabled}。是否接受这些参数取决于接口和模型，不保证所有服务支持。留空项不发送，长度留空沿用应用默认：文字 6144、结构/控件 12288。

“最终结果字数上限”默认 0，表示不设应用字数限制；可配置为 100～60000 个 Unicode 字符。只统计提取后的最终正文，包含正文内空白、JSON 键名和标点，不计可分离的思考或说明。关闭该限制仍受服务端令牌预算、本地最终结果 12 万 UTF-16 码元和总响应 2 MiB 上限约束。完整 JSON 或明确闭合的最终文字结果可继续校验；残缺结果不会拼接应用。

JSON与控件互通，编辑JSON后可回填控件，点击“保存连接”才进入主进程校验、保存并用于请求。请求超时5～300秒，输出长度字段可选 max_tokens 或 max_completion_tokens；后者将相同长度映射为该参数名，不同时发送两个长度字段。模型、消息、stream和结构JSON返回协议由应用管理，不能通过高级JSON覆盖；不接收自定义脚本、HTTP头、Key、路径或消息数组。

连接及请求参数与原API配置一起保存在当前Windows用户目录，Key单独加密，不写入项目或Skill。表单/JSON保存失败保留已有有效配置；API接入关闭时仍不联网。保存部分配置不再丢失其他已配置字段。UI对照和本地模拟请求验证参数实际发送，未验证真实服务商兼容性或生成质量。

## 请求减量与耗时诊断

文字润色只发送设计字段和工具意图摘要，不发送工具坐标、几何数组或完整工具序列。相同意图合并计数，未启用与不同材质的步骤保留区分；本地原工具计划、保护配置与阶段规则不受润色影响。12000字符的润色摘要限制只适用于文字模式，控件和完整初稿仍保留完整工具上下文；各模式对用户实际指令的12000字符限制继续生效。

基础规则与已保存Rule完全相同时只发送一次；自定义Rule继续与基础规则共同发送。勾选知识仍按上文发送全文，未做静默章节抽取或裁剪。结构任务要求紧凑JSON和简短summary；提示词方案允许部分字段建议，建造和验收规则由本地组合器附加到最终交接。

任务详情分别显示截图、API 往返、生成候选合计和本地预览的耗时。候选合计不包含用户后续审阅等待的时间。每次 API 尝试都会记录响应等待、接收、解析、请求/响应字节量、输入文字规模、返回原因，以及接口实际提供的 token 统计；失败、取消和截断后的精简重试也会保留测量数据。JSON 解析与本地参数校验单独列出。非流式接口的“等待响应”可能同时包含排队和生成时间，无法据此区分服务商的内部阶段。

重试的token数量按接口已报告的用量累计，并保留每次数据；未提供用量的尝试显示为缺失，不按零消耗计算。新增测量字段使用白名单和长度上限，不保存API请求体、响应原文、截图内容或认证头。跨Electron桥的生成失败使用内部`api_error`数据封装，调用层再转为错误，避免跨进程丢失诊断字段；其他IPC权限与工作区失效检查保持。

## 控件工具的增量返回

控件配置请求会附带`operation_base`：完整方案基线SHA256和从1开始的各步骤编号/原步骤SHA256。应用另外对包含源路径、保护设置等本地状态的完整表单计算`baseline_binding`，只发送哈希，不发送其中路径。不同源或本地状态不能复用旧候选。

AI修改已有步骤参数时，可返回`operation_patch:{"baseline":"原基线","changes":[{"step":12,"expected":"原步骤SHA256","set":{"state":"minecraft:andesite"}}]}`，最多16项，不与`operations`混用。应用先核对两个指纹、步骤范围和字段白名单，原子合并到请求时的完整本地序列，再沿用整体参数校验、用户采用以及后续引擎预览检查。收到候选和采用前也继续核对完整表单绑定；生成期间或审阅期间的本地编辑会使候选失效。

增量不会修改工具类型、覆盖开关、写入组或单步预算。同一批次可使用 insert、remove、move 在基线步骤前后插入、删除或移动步骤。移动同时绑定原步骤和锚点的指纹，每个基线编号只允许引用一次，定位不会随前面的动作移位。每批最多16项，合并后最多128步。可先审阅、采用一批，再基于新方案继续。完整序列协议仍支持最多64步。API返回的是短增量。主进程先对发送上下文验证合并，界面再在绑定未变的完整本地序列上重放已校验增量；不会用精简后的API上下文覆盖本地原序列，也不会丢掉未上传的写入组、体素等字段。应用内候选显示合并后的完整序列，便于审阅和沿用原导入导出流程。

## 小构件名称与一个建议视角

小型结构可在返回JSON的根对象加入`structure_name`（1～120字）和一个`camera:{"azimuth":45,"elevation":25}`。水平角范围-180～180度：0从+Z观察，90从+X观察；俯仰角范围-90～90度，正值俯视。旧接口没有这两项时，用第一步名称和45°/25°作为默认观察建议，不影响旧候选兼容性。

AI只给两个角度，本地脚本以平移后的构件操作范围和当前视口比例补齐`eye/target/up/fov`与观察距离。构件预览后可点击“查看构件视角”，切换相机而不改变几何、剖切、图层或光照。该机位用于观察，不声明玩家可站立或保证无遮挡。视角参数可在面板展开查看；名称与角度随版本绑定的构件草稿保存，整体移动后重新计算实际镜头。它们不写入Python操作字段，也不触发正式NBT导出或确认。


## 资产管理独立结构

资产管理增加“Agent创建独立结构”和“独立3D查看”。新建不依赖当前建筑；可使用内部API生成，也可粘贴外部Agent参数，并可引用已有资产的编号与内容哈希。内部AI只接收精简的参考元数据，由同一Python引擎解析完整体素、组合与预览。保存按钮只对当前已加载的真实候选开放，参数改动后须重新预览。已有资产3D查看保持只读，不影响模型编辑状态。

所有入口共用tool-catalog.json的agent_tools参数Schema和component-assets.md规范。结构工具覆盖list/read/view/preview/write/place，CLI通过components agent调用，应用通过同源components/agent调用。预览、保存新资产、按参数放置与手动NBT导出分阶段进行，仍保留真实看图与源/几何哈希检查。独立结构使用新增component创作偏好与内部工作流；旧五区域配置保留并补齐新区域，旧截图选项不会自动发送给新工作流。

## 小型结构易用性与响应优化

小型结构可在选定构件类型后直接生成。描述为空时，会补入保留通路、采用现有材质的基本要求。API 优先返回紧凑的 `settings_patch.boxes`：每项 `[x0,y0,z0,x1,y1,z1,state]`，本地展开为标准 box 操作，仍须通过相同的坐标与材质校验。复杂构件继续支持完整 operations。建议操作数降至 24，摘要缩短，配置改为并行读取。这些调整减少传输和生成中的冗余，不保证服务商端的固定响应时间。

AI建模默认勾选“自动移除候选中与保护区冲突的方块”。生成、移动和旋转的box/beam/frame步骤保存 `skip_protected` 布尔值；引擎只过滤候选写入，不删除保护区原有方块，也不改变保护位置的墙层归属。关闭时沿用冲突拒绝策略。预览与正式精修共用过滤函数；全局预算、实际看图与手动导出流程继续适用。

设置→常规配置→建模工具启停保存当前工作区的 `disabledTools`。停用后会隐藏手动添加选项，并拒绝通过对应命令/快捷键新增步骤；已有序列、AI 生成接口和无界面 CLI 仍可用。这项设置只控制界面入口，不控制引擎权限。
