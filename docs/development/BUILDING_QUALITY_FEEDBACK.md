# 建筑质量评分与建模反馈设计

本文记录整栋评分的原始设计和将其设为默认反馈的验收条件。首版面向 Minecraft Java 1.20.1 的整栋建筑，从建筑方案、落盘模型和真实渲染中生成五项评分、证据覆盖率和待修问题。评分用于定位修改和比较同一任务的候选。必要路线、操作面及项目已有的技术检查各自给出通过状态，建筑仍按现有流程提交缩略图审阅、取得精修批准及手动定稿。

现有 `room-score` 用于单间或走廊，已提供净空、连通、支撑、风险等证据。整栋评分优先接入建筑方案已有的 `requirements`、`activities`、`review_locations` 和风格规则，复用静态碰撞与图像审阅。对比验收通过后，再将建模流程的默认反馈切到新报告，保留既有房间评分的调用和历史报告可读性。[房间质量辅助模型](../guides/ROOM_QUALITY.md) · [建筑方案闭环](../../.agents/skills/minecraft-nbt-modeler/references/architecture-workflow.md)

NBTCreator 5.0.0 已在 CLI 和桌面开放试用。现行流程保留原反馈入口，用户可显式查看整栋评分。实际命令和复验方式见[整栋建筑质量评分](../../.agents/skills/minecraft-nbt-modeler/references/building-quality.md)。

## 五个评分维度

| 维度 | 评分单位与判据 | 主要证据 |
| --- | --- | --- |
| 建筑完成度 | 每条需求或设计承诺的实现程度。检查预定空间、主体构件、功能布置和配套是否实际落地。 | 需求 ID、空间或构件 ID、回读检查、适用的图像观察 |
| 美观度 | 整体轮廓与比例、视觉主次、色材与明暗构成、不同视角的表现。 | 整体、入口玩家视角及必要的室内视角，逐项记录图像与判断依据 |
| 玩家通路合理性 | 每项活动的必经路段是否可达，停靠点能否操作，以及路线的净空、转折辨识、停靠与流线是否符合用途。 | 分段步行报告、操作面检查、瓶颈坐标、玩家视角 |
| 风格完成度 | 每个已选风格特征在其适用部位实现得有多完整。按体量与屋顶构成、开间与构件节奏、材质角色、标志性构造等按需登记。 | 风格规则、构件比例与材质实测、参考图或设计说明、分区观察 |
| 细节质量 | 每个代表节点的部件关系、交接收口、使用或视角适配。 | 门槛、檐角、梁柱节点、栏杆转角、设施等节点的近景和几何 |

同一事实指定一个主要计分项。例如檐口漏看一处背面属于证据缺口，发现檐角端头悬空属于细节质量，背立面整排檐口偏离已选构造规则属于风格完成度。若漏设必需的梯段导致断路，用同一条问题关联完成度与通路阻塞，后续仍按一项修复追踪。

### 通用计分与覆盖率

每个适用项记录稳定 ID、权重、评分证据和状态。首版同一维度内等权，除非下文另设权重。有两级聚合时，每组的权重平分到该组内所有适用项，再按各项权重计算分数和覆盖率。例如有两项风格特征，分别适用两处和四处，则两组各占一半，各自部位分别占风格分的四分之一和八分之一。已测项归一化为 `0–1`。待测和能力未覆盖项保留在分母。确属不适用的条目附原因，从分母排除。没有适用项时，该维显示为不适用或待定义，具体取决于是否已有评估计划。

- `W` 为适用项权重之和，`M` 为已测项权重之和，`E` 为已测项的权重乘归一化分数之和。
- 覆盖率为 `100 × M / W`。全量分为 `100 × E / W`，在 `M = W > 0` 时给出。
- 覆盖不全且已有有效观测时，显示可能分数区间 `[100 × E / W, 100 × (E + W − M) / W]`。完全没有证据时只显示待评估及缺项。用户和 Agent 均先读阻塞项，再看分数和覆盖率。

| 档位 | 建筑完成度 | 美观度 | 风格完成度的单个特征在一处目标 | 细节质量的单个判据 |
| --- | --- | --- | --- | --- |
| 0 | 有证据表明目标缺失 | 明显失衡，表现妨碍识读主题或空间主次 | 缺失或明显偏离约定 | 部件缺失或有可见断裂、悬空等问题 |
| 1 | — | 意图可见，问题很突出 | 只见表面迹象，特征的主要关系缺失 | 节点已有轮廓，主要交接或配套未处理 |
| 2 | 已有主体，关键条件仍待落实 | 基本可读，有具体且明显的弱点 | 主要特征可辨，仍有重要构造或材质角色偏差 | 基本成形，关键接缝、边缘或用途表达仍有缺口 |
| 3 | — | 整体协调，局部可以调整 | 主要关系与角色符合约定，局部略有偏差 | 近看关系完整，只有次要收口可改 |
| 4 | 目标及验收条件均有证据支持 | 各适用机位表现协调，视觉重点符合本次意图 | 当前部位完整落实约定特征，或符合预先登记的变体 | 当前判据的预期关系均清楚，近景或几何证据足以核对 |

这些是初始档位。各评分项按下文指定适用档位，并在积累同类样例后校准。首版输出五个维度及阻塞状态，总分等对比数据支持权重选择后再确定。

### 建筑完成度

建模前从用户要求和本次采用的设计推导登记验收项。每项写清来源、所属阶段、是否必做、构件或空间 ID，以及判定条件。必做项权重为 2，其他已承诺项为 1。取 `0、2、4` 三档，除以 4 后计分。构件存在只证明存在性，涉及使用、结构表达或主题辨识的条件还需要对应证据。初稿包含该阶段应有的主体、基础构造和代表性细节。经确认的精修任务可使用下一阶段验收清单，每版记录实际采用的清单版本。[需求、活动和操作面的已有证据](../../.agents/skills/minecraft-nbt-modeler/references/architecture-workflow.md#需求落实与活动动线)

### 美观度

使用表中五档，每项分数除以 4。同一建筑的候选采用统一相机、剖切、材质渲染和光照设置，实际查看整体与玩家视角。每项记一条可指向图中位置的观察，涉及整体判断时引用多个必要机位。校准时匿名展示 A/B，允许平局，交换顺序检查 AI 评审的一致性，并记录用户偏好与评审来源。渲染结论按预览范围报告，游戏内光照需要游戏证据。

### 玩家通路合理性

1. **先查能否完成活动。** 从 `activities` 读取使用者、有序停靠点、分段路线和操作面。必要路线有一段不通，或必要停靠点失去支撑、站错操作侧、操作面被挡，整项活动标为阻塞。搜索上限、未知碰撞和缺少起终点分别记为待核查或引擎未覆盖，并附原因。复用现有半格静态步行和操作面检查，记录采用的碰撞模式。
2. **再评估通行体验。** 对可证实的路段评四项，分别是沿途净空宽裕、转弯与停靠空间、岔路与目的地辨识、路线与用途匹配。每项 0 表示有明确不合用的证据，0.5 表示能用但存在具体瓶颈或绕行，1 表示达到事先登记的用途目标。先在活动内聚合，再让各适用活动等权计入维度分。必要活动存在阻塞时，展示已测分项及坐标，维度主状态显示阻塞。必要活动的可行性仍有待核查或引擎未覆盖时，主状态显示对应证据缺口。必要活动均有证据支持静态可行后，才显示通路维度分。
3. **把尺寸和体验依据留在报告里。** 首版可以复用现有 `1.2 × 1.8` 格的宽裕体积探测，记录适用步行路径上满足该体积的采样比例和失败点。普通步行的净空宽裕项可暂定为 `80%` 及以上得 1 分，`50%` 至不足 `80%` 得 0.5 分，其余得 0 分。个别窄点仍列出实际位置和所用的净空阈值。转角和操作区优先对照设计声明的站位和活动空间。主路、观景路或迷宫采用各自的绕行判据。跳跃、游泳、动态门和机关的效果待实际游戏验证。

### 风格完成度

建模前用 `style.materials`、参数、规则及现有设计说明登记有辨识度的特征。每条特征写清适用的主要部位、目标做法、允许的变体和观察机位。例如“主楼与侧翼使用连续深檐，入口跨可加深”，可在主立面、侧翼转角和背立面分别核对。可实测的材质角色、尺寸、比例和配方参数复用现有规则，构造语汇能否被读出来由人工或 Agent 实际看图记录。

每个适用部位按表中 `0–4` 评分，同一特征下各登记部位等权平均，再让各特征等权计入风格分。局部样板通过只覆盖该样板所代表的部位。预先声明的留白、混合风格和变体按各自意图评判。另报实现达标的部位数与适用部位数，达标暂定为 `3` 档及以上。例如同一深檐特征在主立面、侧翼和背立面各得 `4、4、1` 档，则该特征得 75 分，达标 2/3 处。[已有材质角色与风格规则](../../.agents/skills/minecraft-nbt-modeler/references/architecture-workflow.md#入口与设计责任)

### 细节质量

从玩家使用路线和建筑构造里选代表节点，覆盖主要入口、跨层交接、构件收口及主题设施中当前适用的部位。重复节点抽一个典型位置和容易出问题的转角或端头。每个样本在候选前登记位置、构件、预期关系和取证视角。对每个节点的三个适用判据按表中 `0–4` 评分。

- **部件关系。** 层次、支承、厚度、方向和局部尺度符合该节点的做法。
- **交接与收口。** 接缝、边缘、转角和端头有连续做法，观察实际方块状态及邻接关系。
- **使用与可读性。** 从玩家来路或近景能辨认用途，必要部件和配套的关系成立。

节点内各适用判据等权，各登记节点再等权计入细节分。例如一个梁柱节点在部件、收口和可读性三项各得 `4、2、3` 档，节点得 75 分，并优先回查接缝。极简节点也可以获得完整档位。库组件应该按装配后的实际接头和姿态检查。样本的质量与代表区域的证据覆盖同时显示，避免用一个精修角落代表整栋楼。[空间与细节设计](../../.agents/skills/minecraft-nbt-modeler/references/spatial-detail-design.md) · [现有精修项目](../../.agents/skills/minecraft-nbt-modeler/references/refinement.md)

## 建模反馈与版本绑定

1. **方案阶段冻结对照条件。** 沿用建筑方案中的需求、活动和审阅位置，补上风格特征、细节样本和量表版本。方案变更保留增删理由与新旧 ID 对应。每项缺证据时列出下一次要测的尺寸或机位。
2. **制作源回读后先做自动检查。** `architect plan-check` 的回执补充可测分项和阻塞。若 `plan-build` 已因必要路线或操作面失败，直接从失败回执提取定位并反馈。草案无需先生成成功的制作版才能指出断路。
3. **出图后登记视觉观察。** `review-prepare` 沿用已登记机位，`review-record` 登记外部 Agent 或人工的观察，绑定实际图片及世界坐标或构件 ID。CLI 和桌面端消费同一份 Python 评估结果。整份报告绑定源、几何、评估清单和量表版本，视觉条目另绑定机位、渲染证据和审阅修订。
4. **按问题修改并复验。** Agent 先处理必要项目和安全阻塞，再选影响最大的局部问题。新版用 `review-compare` 或已有增量诊断按稳定 ID 找回目标，检查受影响路段及必要相邻路线，视觉项用同机位复验。优先展示新增、持续、已复验解决和待复核的问题。要求清单、量表、样本范围或机位发生实质变化时报告差异，仅对双版范围和条件一致的项目比较分差。用户看到实际缩略图并明确同意后才进入精修。

报告短摘要列出五维分、覆盖和最多三条当前优先问题，完整结果提供原报告路径与 JSON Pointer 或图片引用。问题至少包含稳定 ID、主归属、严重度、目标或世界坐标、证据、建议与复验条件。例如 `file_books` 第一站 `return_desk.intake` 返回 `wrong_side` 时，标为必要活动阻塞，建议核对第一站脚位和柜台朝向，复验条件是原三段路线及该操作面均通过。[增量诊断](../../.agents/skills/minecraft-nbt-modeler/references/diagnostic-guidance.md#增量诊断) · [同机位复查](../../.agents/skills/minecraft-nbt-modeler/references/architecture-workflow.md#三层真实看图与问题回写)

## 验收与替换条件

| 样例 | 预期结果 |
| --- | --- |
| 归卷阁正常、堵梯口、柜台背面三个现有版本 | 正常版通过声明的静态活动检查。堵梯口版定位到梯顶脚位。柜台背面版即使三段路走通，也指出具体操作侧错误。 |
| 移除必需设施，或仅完成设施主体 | 完成度分别给 0 档和 2 档，报告列出相关需求及缺失条件。 |
| 只有正立面符合目标风格 | 正立面高档，适用但仍偏离的侧面或背面低档，反馈能定位到未落实的特征。 |
| 只破坏一个代表节点的收口 | 细节分随对应节点变化，问题指向接头或端头。 |
| 两个同机位候选只调整构图或配色 | 美观度变化有可指认的图像依据。盲评汇总用户选择、AI 选择和平局。 |
| 缺图、未知碰撞、变更目标或过期的审阅记录 | 缺口和绑定差异可见。有效范围内的已有证据仍可读，需要重新核对的项目保留待评估。 |

第一批复用[归卷阁样例](../../.agents/skills/minecraft-nbt-modeler/assets/examples/reading-loft/README.md)。再用不同用途、尺度和装饰密度的留出样例校准，避免量表只适用于归卷阁。

替换旧反馈前，对同一批初稿，在相同 Agent、源模型、基础技术回执和修改预算下，分别追加旧评分和新报告，各修改一轮。记录旧评分覆盖的实际范围，优先比较两组都有有效评分的样例。由不知道分组的评审复查必做问题修复率、新增阻塞、用户视觉偏好与修改成本。必要路线和操作面反例均应被正确定位。新反馈需要提高关键问题修复率，且在抽验中没有增加必要路线回归，再启用为默认整栋反馈。小样本阶段保留逐例结果和评审分歧，据此调整量表。
