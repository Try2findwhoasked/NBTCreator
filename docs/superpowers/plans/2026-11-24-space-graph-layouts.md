# 空间关系候选实施计划

**目标**　在同一建筑任务下比较粗布局，让每个通过的候选都能交给 `architect plan-build`。归卷阁用于复验工位与梯口的真实通路。

**设计**　沿用原工作区原型的 `layout-search` 和位移参数。在同一入口增加 `graph` 模式，共用种子方案、面积约束、建模与问题回执。建筑方案现有 `spaces` 提供节点。边表达同层侧邻接或具名活动的跨层路段，候选以稳定 ID 绑定粗构件、空间范围与脚位。Agent 提出有限份候选，Python 检查后交回作者选用。关系表达参考 [Graph2Plan](https://arxiv.org/abs/2004.13204)。

- [x] 在 `nbt_building/layout.py` 复用位移绑定、组合上限和诊断提取，令两种请求共用公开 `plan-build` 的编译检查。原工作区的请求级引擎快照和局部重建可独立集成。
- [x] 在 `nbt_building/layout_graph.py` 实现候选坐标绑定、画布与围护足迹检查、同层侧邻接和跨层活动边验证。入口至第一站复用宿主路线，逐段运行、净空及操作面复用既有方块证据。
- [x] 在工具目录、公共注册器和建筑方案指南登记同一个入口。验证内联与保存种子，拒绝不明确的模式、重复绑定和未通过的布局。
- [x] 用同一归卷阁粗种子验收两种入口至工位组织、梯顶堵塞和柜台错侧。涵盖无效边界和对角邻接，记录失败脚位与活动 ID。
- [x] 通过公共入口保存正向梯候选，回读制作源、生成三张三层审阅图及三张平剖图，并登记实际图像观察。目录同步、建筑工作流、预览、桌面和完整检查均已通过。用户确认与手动定稿由各自入口处理。
