# 整栋生成与修改基准实施计划

复用 MineCEraft 的自然语言指令与程序验收思路。归卷阁首批任务固定活动顺序、必要开口与路线，并用同一制作版上的三格压条变更测量局部修改。[MineCEraft](https://arxiv.org/abs/2608.28884)

- [x] 在 `tests/support/building-generation-cases.json` 冻结任务文本、用例版本、候选及修改预算和视觉问题。`tests/support/building-generation-benchmark.py` 用现有 `plan-build` 和制作源回读一并复验固定任务与实际候选。用失败质量回执绑定堵梯口与错侧基线，局部修改从同一已保存的初稿出发。
- [x] 运行两组同预算的候选和修复。默认操作者重演已知夹具并根据诊断执行固定动作。导出冻结输入，接受来自外部操作者或布局搜索的候选计划，记录提交哈希及每轮实测结果。两组共用预算，删除必查条件、超额候选、错误输入哈希或局部越界均应被拒绝或计为失败。
- [x] 为每对通过的候选调用现有真实渲染和匿名审阅入口。复用固定外观、入口和书柜机位，保存私有绑定及可独立交给评审的公共图包。缺候选和待评分分别记录。
- [x] 增加 `building-generation-benchmark` 套件，复验首轮 `2/4`、修复后 `4/4` 及各例的诊断、修改量和保留项。执行全流程出图并保留报告，运行项目环境、整栋质量与桌面检查。真实用户确认和正式 NBT 导出仍由现有独立入口完成。
