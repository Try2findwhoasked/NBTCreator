# 每条约束独立目录实施计划

**目标**　项目按约束组织房间，起草时读取并引用规则，通过脚本预检、迁移和验证旧工作区副本。

**架构**　按目录内的规则文件和房间元数据读取。归属决定房间路径，引用通过房间编号反查。兼容旧约束快照和旧路径，设置页通过专用后端接口调用迁移工具。

**设计**　[审查稿](../specs/2026-11-18-constraint-room-layout-design.md)，采用每条约束独立存放的最终选择。

## 约束与房间

- [x] `nbt_rooms.py` 负责项目布局、房间登记及路径解析。房间元数据区分实体归属和引用，版本复用现有结构。
- [x] `nbt_constraints.py` 支持布局内 `约束/<名称--ID>/约束.json` 和 `历史版本/`。旧格式原样读取。列表摘要与单条快照读取分别供起草勾选和规则详情使用。
- [x] 建筑库用目录和房间元数据生成约束树。重复读取使用进程内规则缓存。

## 创作方案

- [x] 起草和审查共用约束选择状态。选中读取并保存完整快照，保存过的方案保留原修订。
- [x] 带预定归属的草稿先保存到草稿区。登记或交接时创建房间目录，归档使用同一方案编号。

## 迁移工具

- [x] `tools/constraint-room-migration/migrate.py` 用同一套布局与规则接口生成预检清单、独立副本、旧路径映射和验证报告。确认归属前只读旧工作区。
- [x] 桌面设置支持选择目录、校验工具、预检、确认、迁移和验证。用固定入口调用 Python。发行资产适配现有打包流程。
- [x] 在合成工作区验证旧格式读取、约束冻结快照、路径保护、迁移复跑、模型哈希、旧任务和旧版本读取。
