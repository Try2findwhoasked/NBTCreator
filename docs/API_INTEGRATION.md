# API与Skill配置 · 0.3.0

## 1.2新增

在提示词方案右侧的 AI 中，可选择“配置左侧控件与工具序列”，将当前设计文字/工具参数交给 API，审阅返回的 JSON 后再回填。AI 可修改设计字段和合法工具序列，不得改写源/输出路径、阶段、保护上下文、预算、批准或已有源模型尺寸。采用结果只修改方案表单，不写入建筑 NBT；改动前的候选仍须通过版本绑定检查。原有的“润色文字建议”也可继续使用。

在 Skill 设置右侧可添加 Markdown/TXT（UTF-8，单份≤2MiB，每次≤32份，最多100项）。文件会复制到工作区 `.nbtcreator/knowledge`，并生成相对知识链接。每份资料可单独启停，关闭不会删除原文。切换工作区时会携带自定义知识与选择；目标已有配置时，保留目标的知识列表。

这些资料供当前项目中读取 SKILL.md 的 Codex 或兼容文件式 Skill 的 Agent 使用，不用于 Minecraft 服务器插件，也不会自动上传为 DeepSeek 远程知识库。自定义文档仅供参考，不增加批准权限。

**0.3.0当前布局**：AI助手工作区仅保留API和AI相关配置，右侧为当前工作区的Skill暴露配置（可选知识组）。生成任务不在此页：提示词使用“提示词方案”的AI完善方案，结构建议使用“模型编辑 → AI建模”。结构建议控件已迁往模型编辑，协议与安全边界不变。

在桌面右上角点击 **AI 助手 / API**。API 默认关闭，离线使用的 Skill、CLI、参数工具、标注和导出均不依赖模型服务。

## 配置和调用

1. 选择DeepSeek预设，或兼容Chat Completions接口。
2. 填API根地址、模型ID、Key，勾选启用并保存。地址应为HTTPS；本机服务允许127.0.0.1/localhost HTTP。根地址后由程序追加 `/models` 或 `/chat/completions`；例如兼容服务通常需要根地址包含 `/v1`。
3. 点击“测试连接 / 获取模型”请求模型列表。模型ID可手动填写，不把静态预设当作账号实际可用模型清单。
4. 在本页保存API配置或知识组后，切换到提示词方案生成设计建议，或在模型编辑的AI建模页规划简单结构。保存配置、打开设置页不发网络请求。

Electron 主进程使用 safeStorage 异步加密 Key，将其保存在当前用户配置目录的 api-settings.json 中，不写入工作区、模型文件、导出参数或资料库。保存后，界面清空 Key 输入框，只接收 hasKey 状态。服务地址不变时，留空会保留旧 Key；更换服务来源但未输入新 Key 时，会清除旧 Key，以免发给另一服务。点击“删除Key”可明确删除。加密不能保证同一 Windows 用户下的其他程序绝对无法访问。配置文件损坏时，API 会恢复为关闭状态，不影响离线建模。

可使用无需 Key 的本机兼容服务。访问需要认证的远程服务时，缺少 Key 会返回 HTTP 错误，应用不会自动寻找环境或其他应用中的凭据。请求超时为 90 秒，可取消，不会自动重复发起可能计费的重试。

## 两种任务

### 提示词方案工作区的 AI（0.2.1）

从顶部“提示词方案”进入，在右侧点击“AI完善方案”。直接复用已保存的主界面API配置，不在子页面保存Key；“API设置”切换到主AI工作区，关闭后返回原提示词页。主进程仍只接受主frame IPC，提示词iframe通过受限父页面桥接调用prompt模式，没有开放Key管理或任意IPC。

填写补充要求后生成候选，可手动编辑再“采用AI建议”。仅把AI文本用于设计要求段；本地任务输入元数据、阶段执行边界、工具序列JSON、验证上下文和交付要求继续由原参数生成。下载Markdown与复制读取实际采用的版本；计划JSON仍只导出本地操作计划。修改表单后AI稿失效，自动回到参数生成稿；可重新生成或点击“使用参数生成稿”。保存/导入方案保留与当前参数绑定的AI稿。

自动发送范围为建筑设计文字和筛选后的工具参数，不包含source/output/contextPath/reviewPath、保护配置或自动加入的源哈希说明。用户手写的补充文字仍会发送。方案过大时先缩短再生成；未启用API、独立浏览器/file页面均可继续离线编辑。

### 主 AI 工作区

- **提示词**：返回可复制/下载的中文任务正文，不执行工具。
- **简单结构**：先在“修改范围”取消整座建筑并指定局部XYZ。API仅生成局部填充、挖空、外壳、移动、地板、天花、围墙、边框或精确换块的settings_patch。检查结果后点击“载入参数并预览”，本地后端先检查源哈希和参数，再按原保护区计算效果。正式NBT仍需用户明确导出。

建议生成后，若模型或任意效果参数改变，就不能直接载入旧建议。生成计划不得扩大用户选区，移动目标也必须位于选区内。不接受任意 Python/shell、导出路径、批准字段或未支持的工具。原引擎仍负责验证方块注册合法性、保护、预算、碰撞与导出条件，JSON 合法不代表建筑已完成。

载入计划会替换结构/换块模块，保留其他效果模块。预览后仍需检查支承、净空和实际图像，不能据此视为运行验收通过。第一版不支持自主 Agent 循环，不会自动读取图片或修改意见，也不会自动批量导出。

## 发送范围

发送用户本次输入，以及已打开模型的尺寸、选区、最多32种材质/数量；不自动发送模型路径、完整方块数组、图片或意见文件。用户自己写入输入框的文字会随请求发送。API请求与响应不落入模型任务日志；用户可主动下载生成结果。

配置错误、空输出、截断输出、401等接口错误会提示；错误响应正文不直接展示，避免服务端回显密钥。JSON模式可针对不支持response_format的兼容服务关闭，但结构输出仍需能解析为合法JSON。

## 验证范围

`npm run test:api`：默认关闭不联网、加密保存/删除、最小上下文、受限结构、非法字段/越界、空/截断输出、错误信息、独立取消、有界并发、队列上限、输入快照、配置保存互斥和工作区切换取消。

`npm run test:api-desktop`：本机模拟HTTP接口 + 真实Electron safeStorage和Python引擎，检查配置、模型列表、提示词、局部计划、旧参数拒绝、本地预览和原稿保留。没有使用真实DeepSeek Key，不宣称真实服务连通或模型质量已经验收。

0.2.1联调还包含提示词iframe共用连接、AI稿采用/失效/方案往返、真实Electron文件下载、共用设计变量，以及顶部功能页和窄屏切换。

官方协议参考：[DeepSeek JSON输出](https://api-docs.deepseek.com/guides/json_mode/)、[模型列表](https://api-docs.deepseek.com/api/list-models/)、[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。


AI 连接默认允许 2 个并发生成，可在设置中选择 1～4 个；每个请求有独立编号、超时和取消信号。批量提示词按建筑独立保存，失败/取消的条目可重试，同一建筑的采用和预览仍依次执行。`npm run test:ai-batch` 验证并发、结果归属、部分失败重试和批量取消。

外部 Agent 使用 `machine --schema` / `machine --request <JSON>` 获取版本化契约和统一错误封装；任务租约、幂等回执与独立批注读取见 [机器接口说明](../.agents/skills/minecraft-nbt-modeler/references/agent-protocol.md)。`npm run test:agent-protocol` 验证跨进程领取、超时重领、旧执行者拦截、提交中断重试和回执校验。

内部 AI 的构件、选区和工作台任务按本次要求及已有操作附带工具说明，保留所选工具的必填字段和参数限制；工具或几何参数校验失败时，在原有重试次数内补充完整工具说明。此调整不改变后端允许的操作、工作区绑定或审阅流程。建筑交接要求按空间、构件及连接关系表达，未指定的实现细节由接收任务的 Agent 推导。提示词长度和本地模拟接口已验证，尚未用真实模型做质量对照。

AI 资料准备最多同时进行 2 项。请求入队时，固定工作流配置、创作偏好与所选文档版本；取得准备名额后，再读取大段文档和检索集合。排队期间若文档发生变化，会拒绝旧快照，不会直接改用新内容。几何预检复用工作区绑定的 Python 进程，取消、空闲退出与切换清理见[建模会话](../.agents/skills/minecraft-nbt-modeler/references/parametric-components.md#建模会话与结果复用)。测量记录分别保留 capture_ms、context_prepare_ms、queue_ms、validation_ms；这些阶段可重叠，不能简单相加当作总耗时。

外部 Agent 可使用 scene_compile / scene_read / scene_update 编译和修改建筑对象关系，再显式 scene_save 保存图谱新版本；工具 Schema 统一加入 agent_tools，session 也支持纯候选动作。图谱可驱动尺寸、接触与装饰贴附，更新绑定父版本并保留保护、留白、路线与预算。图谱不会自动识别手工 SNBT 中的对象，也不修改当前建筑或执行定稿导出；将图谱结果接入建筑时，仍须经过原有的候选预览与源绑定流程。详见[建筑对象图](../.agents/skills/minecraft-nbt-modeler/references/object-scenes.md)。
