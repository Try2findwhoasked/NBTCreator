# 面向建筑师的工作区与创作流程

本轮以已确认的使用流程为准，不把界面重构变成新的工作流程。

| 已约定的要求 | 实现与操作入口 |
| --- | --- |
| 保留 AI 编写 | 创作方案的新提示词默认打开「AI 编写」；也可以手工填写建筑要求。 |
| 多条提示词，支持先批量生成再逐条审查 | 左侧提示词列表；「批量编写」接收共同要求和每行一座建筑；每条独立生成并保存为待审查草稿。 |
| 继续生成是下一座建筑的提示词 | 「生成下一条」编写列表中尚未生成的建筑；没有下一座时新增一条，填写想法后再生成。不会接着润色上一条。 |
| 人工审查、修改和自动保存 | 「审查与修改」按建筑概况、空间动线、材料构造、保留要求分组。AI 结果可直接逐项修改。停下输入后自动归档；切换前和正常关闭前刷新待保存内容。 |
| 只有人工决定交接，外部助手人工触发 | 「这条已审查」标记设计要求已核对；「交接已审查的提示词」或「确认并交接这条」创建任务。应用不自动启动外部 Agent。 |
| 任务与批注接口分开 | 新增提示词任务由 `prompts tasks --after <cursor>` / `prompts task --id <id>` 读取。建筑修改意见继续使用 `feedback` 接口；整理后的批注任务使用 `feedback-tasks`。不会因保存标注自动生成新的制作任务。 |
| 标注正式保存到被标注版本 | 在建筑编辑中选择「标注」，文字、位置、证据自动写入该版本的 `修改意见/`。继续输入更新同一条，「开始下一条标注」建立下一条。 |
| 简单修改可手工或由软件内 AI 完成 | 「建造」面板保留原工具、选区、材质与 AI 构件流程；修改先预览，再保存制作版。 |
| 建筑版本管理 | 「版本」记录来源版本、修改说明、作者、任务/标注关联与主要编辑版本；对比实际几何，从旧版继续会另存新版本。 |
| Git 不依赖用户安装 | 便携版内置锁定 MinGit，历史位于项目 `.nbtcreator/history/`，与项目自己的 `.git` 分开。 |
| 未定稿使用 SNBT，定稿专用目录 | 编辑器保存新制作版为 `master/model.snbt`；明确「定稿导出 NBT」后才在 `nbt_models/_exports/` 下生成相同建筑/版本层级的交付文件。原稿和批注保留原位，旧 JSON.GZ 兼容。 |
| 项目、素材与 AI 设置辅助流程 | 建筑库打开版本、素材库保存/放置构件、AI 与知识库选择服务和资料；创作方案可引用当前建筑并查找本地参考。 |
| 操作面板有足够空间 | 建筑编辑面板默认 400px，分隔条可拖动，方向键调整，双击恢复默认，可收起。创作方案在较窄窗口按需展开完整提示词，为编写/审查保留空间。 |

「提示词已审查」只表示建筑师核对了设计要求，不是既有建筑的精修看图确认，也不生成 `approval.json`。真实缩略图确认与明确手动导出流程保持独立；外部助手回传后仍待人工查看建筑，定稿不代表游戏实测通过。

提示词列表从当前项目的实际归档恢复；不依赖浏览器暂存来跨项目复用内容。已交接任务保留当时的不可变修订，后续修改必须重新审查交接。生成中可停止批量编写，已经保存的草稿保留，未生成的建筑继续留在列表中。

验证入口：`npm run test:architect`、`npm run test:studio`、`npm run test:feedback-autosave`、`npm run test:history`、`npm run test:desktop`。
