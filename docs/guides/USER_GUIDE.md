# NBTCreator 使用指南

NBTCreator 是面向 **Minecraft Java 1.20.1** 的 Windows NBT 建筑创作工作台，可在同一工作区管理建筑、预览材质、编辑结构、生成 AI 构件，并与外部 Agent 协作。

支持打开 Java 结构 NBT 和完整主模型。修改后先预览候选效果，再由你手动导出下一版，原稿会保留。

## 下载与启动

从 [GitHub Releases](https://github.com/Try2findwhoasked/NBTCreator/releases) 获取 Windows x64 版本。

| 交付形式 | 用途 |
| --- | --- |
| 完整免安装文件夹 | 直接运行文件夹内的 `NBTCreator.exe` |
| `windows-x64-portable.zip` | 首次下载，完整解压后运行 |
| `windows-x64-app-update.zip` | 已有兼容运行环境，仅更新应用 |
| `windows-x64-runtime.zip` | 与应用更新包解压到同一父目录，合并同名文件夹 |

完整版内置 Python、NumPy、Pillow 和 Chromium，Electron 提供 Node 运行环境，无需另行安装开发工具。**保留完整目录，不要只复制 EXE。** 应用更新包不包含完整运行环境，启动时会检查兼容性。

首次使用时，选择创作项目的根目录，建筑默认存放在工作区的 `nbt_models/` 中。应用目录与创作工作区可以分开。

## 快速上手

1. **打开建筑**：在“建筑库”选择已有建筑，或点击“打开 NBT…”。没有建筑时，先在“创作方案”编写初稿要求，交给外部 Agent 制作。
2. **查看模型**：点击建筑卡片或“查看与管理”，在同一窗口预览 3D、调整所属菜单和创作阶段；进入“建筑编辑”后可切层、剖切、取材和标注。
3. **进行修改**：限定修改范围，使用建模工具，或让 AI 添加局部构件。更新效果预览后，可撤销、重做和对比。
4. **检查结果**：检查当前效果、保护区与适用的通路报告，再实际查看图片或 3D。
5. **保存下一版**：继续修改可点击“保存制作版”，另存 SNBT；确认定稿后点击“定稿导出 NBT”。生成建议、恢复编辑进度或检查通过都不会自动导出正式 NBT。

建筑名称下固定显示版本和正在查看的原稿或候选。顶部“准备编辑 / 检查与交付”切换同一座建筑的工作视图，保留镜头、剖切、选区和参数草稿；醒目的主按钮随当前状态提示下一步。参数改变后先“更新预览”，保存和导出才会恢复可用。保存完成后点击“打开新版本”继续编辑，或点击“查看保存结果”在运行记录中查看文件位置。旧版本会暂停保存和导出，避免重复提交到已更新的版本。底部的编辑进度自动保存与建筑制作版是两回事。

“准备编辑”的检查器显示当前对象的名称、尺寸和 XYZ 坐标，单位为方块格。整栋与选区使用现有范围参数；构件实例使用同一操作序列中的构件组，选择构件工具后可查看偏移和旋转。取材、标注、两点选区、构件手柄及只读版本对比均在画布显示模式，按 Esc 退出并返回对应控件。普通手动编辑的建模检查、实际看图与 Agent 精修的真实确认各自独立。

“检查与交付”集中显示候选检查、进一步检查和保存位置。继续创作使用“保存制作版”，另存 SNBT；需要游戏文件时显式点击“定稿导出 NBT”。检查问题有坐标时显示坐标并可定位；没有坐标时按报告建议核对参数或补充检查。原文件、源哈希与候选绑定规则保持有效。

运行记录位于窗口右上角，先显示对象、动作、结果和下一步，路径、计时与 JSON 收在详情中。记录中的返回操作只导航，不自动重做写文件任务。设置按外观与启动、画布与操作、工作区与文件、AI 连接与知识、更新等目的分类；界面设置随工作区保存，本机密钥单独加密保存。

创作方案支持“手动填写要求”，无需先配置 AI。顶部步骤可返回编写、审查方案或查看交接内容；交接仍需点击“确认并交接”。关闭方案页会回到进入前的页面。

在建筑库中，点封面查看预览和版本资料，点卡片下方的“打开建筑”直接进入编辑。需要挑选版本时，点击工具栏的“比较”，选两张卡片后点击“并排比较”。切换搜索词或版本范围会保留已选项。对照表可打开任意一版，也可将左侧作为基准，查看右侧的三维差异。“建筑库工具”中可以切换工作区、批量处理和补齐预览图。

素材库按建筑构件、效果预设和纹样浏览，每一类可以单独比较。构件的审阅状态和排序在“筛选”中设置。打开构件后可查看目标建筑、指定锚点并点击“预览放置效果”。要更换建筑，点击“更换目标建筑”，在建筑库点击“选为目标建筑”，软件会返回同一个构件。重命名、标签和回收操作在“管理构件资料”中，导入与批量资产在“素材库工具”中。

图片选择器在浮窗中显示缩略图，浮窗可拖动、缩放，大图和标注保留在主视口。拖动左下角方向球可环绕观察，点击坐标轴可切换正视图。“显示”菜单集中管理材质、图层、剖切、玩家路径与保护区。

在“创作方案”中通过“起草要求 / 编辑与审查 / 交接结果”处理同一份文档。手写要求与 AI 起草共用这份方案；AI 建议需采用后再审查。点击底部的 **确认并交接**，即可创建带日期的任务文件夹，自动保存完整提示词、方案、操作计划和上下文。页面会显示任务目录及外部 Agent 的读取命令；顶部“方案文件”中可导入或下载，侧栏“列表工具”中可批量编写并重试未完成项。

“创作方案”的默认流程是 **编写设计要求 → 审阅 → 保存任务 → 交接下一个 Agent**。方案描述关键空间与构件的用途、特征、包含和连接关系，具体实现由接收任务的 Agent 决定，用户指定的细节与硬约束仍须保留。AI 编写时不要求生成具体工具步骤，不发送整套工具参数目录，也不运行 Python 几何预检。接收任务的 Agent 根据实际源模型、标注和工具接口编写脚本，完成制作与验证。需要手动配置工具序列和验证上下文时，可打开“建造与约束”；展开或收起不会删除已有步骤。

创作 Skill 只在实际创作项目中生成。NBTCreator 软件源码及安装目录不作为默认创作工作区，也不生成 `nbtcreator-workspace` 入口；维护软件时使用共用引擎源码。使用外部 Agent 时，请在创作项目中打开会话并引用该项目的 Skill，以免读到软件目录里的测试或旧任务。

外部 Agent 从工作区根目录运行 `python .agents/skills/nbtcreator-workspace/nbt.py prompts tasks --status pending` 查看待办，或用 `prompts tasks --after <上次cursor>` 发现新增提示词；`prompts task --id <id>` 返回实际文件夹、正文和经哈希检查的方案。进度通过 `prompts task-status --id <id> --status in_progress/completed` 登记。任务文件位于对应建筑 `提示词方案/任务/`；重复保存同一修订不创建重复目录，普通编辑草稿继续自动归档。登记任务不会自动启动 Agent，也不表示模型已验收或精修已获批准。

## 主要功能

外部 Agent 可通过 `components agent --tool parametric_list/parametric_compile/parametric_preview` 查询、编译和预览参数化墙饰、吊顶、植物、柱、楼梯、桌及小型物品；无需启动 Electron。参数、安装面和从候选生成到放置的完整调用见 [参数化建模](../../.agents/skills/minecraft-nbt-modeler/references/parametric-components.md)。

### 项目与版本

- 按项目、形状、对象和版本浏览，组合筛选最新版本、历史版本、创作阶段与文件状态。
- 识别 `nbt_models/形状/对象/版本` 和 `nbt_models/项目名/形状/对象/版本`。浏览、排序与标记不移动实际文件；支持单独查看待修复文件。
- 在同一镜头下对比两个已保存版本或当前候选，标记新增、删除、替换及墙层变化。
- 批量生成截面图、检查文件与声明路线、标记阶段；制作批次可关联正式模型、交付图册和 Agent 任务。
- 自动保存编辑草稿，恢复参数、未导出步骤、镜头、图层、剖切和未保存标注。源文件变化时保留旧草稿，不自动套用。

项目页提供“生成并加载缩略图”：为当前筛选结果生成缺失缩略图，限制并发并显示进度，可随时停止。默认随滚动自动加载更多卡片，也可关闭自动加载并手动追加。

对 bugged 或无法读取的结构，可在卡片“查看与管理”中选择分类并点击“尝试修复并归类”。脚本只恢复可确定的数据，原文件保留；成功后生成新主模型候选并切换到目标分类，失败时给出报告。不会自动修补设计、删除冲突方块、丢弃实体或导出 NBT，候选仍需看图检查。报告位于 `.nbtcreator/repairs/`。

项目管理只列建筑，效果参数不混入建筑卡片，也不要求手动选择内容类型。点击“＋ 新建菜单”建立自己的建筑归组，在卡片“查看与管理 → 所属自定义菜单”中加入。Agent 生成的构件可直接通过 structure_save 进入资产库，或在“让Agent生成资产”中点击“生成并入库”；标签可选。

### 预览与建模

- 默认使用材质 3D，支持图片、视角预设、切层、剖切、保护区显示、取材与选点标注。
- 26 项共用工具涵盖方块、梁、边框、几何体、复制与变换、选区替换、对齐、阵列、楼梯、道路、屋顶、混材与风化。
- 几何工具支持截面扫掠、放样和旋转体；道路可按平面或地形生成，屋顶提供多种形态。
- 步骤可命名、启停、重排、复制和删除；操作历史支持撤销、重做和参数回退。
- 构件可通过数值、滑块和 3D 表面选点调整位置，支持绕 Y 轴旋转。

模型编辑提供“房间综合评分”，包含评估净空、连通、路线、支撑和风险的 12 项自动函数、10 项内部视觉量表，以及可选的 8 项外观量表。缺少资料或存在关键问题时不提供综合总分。报告可下载，功能分可在相同条件下对比。这套辅助评价尚未校准，不能替代看图或游戏验收。详见[评分模型与公式](ROOM_QUALITY.md)。

### 构件与配方

“资产管理”支持保存选区或独立创建构件，管理名称、标签、锚点与缩略图。构件可搜索、导入导出、回收站恢复、旋转、镜像及批量放置；常用工具序列可保存为配方，并复用材质主题。

“让 Agent 生成资产”中的“参数化模块库”提供16类模块、54条配方，无需调用 AI。先选择构件与对象配方，系统填入建议尺寸；可调整尺寸、主材和收边后预览并保存。库包含四种楼梯及外置扶手、独立栏杆、古典柱式和八角/束柱、梁与托架、拱框、门窗框、基座及家具。扶手保留踏步净宽，放置后仍须检查上下平台、玩家净空和承托。

构件放置先生成候选。暂不支持的方块朝向或状态变换会明确提示，不静默猜测。

配方载入时校验已读取的配置版本。若 Agent 在另一端更新了同一配方或材质主题，界面会提示重新选择，避免采用未查看的新配置；编译期间参数暂时锁定，仍可关闭窗口。CLI 也支持指定配方与主题的版本哈希。

在资产管理点击“批量资产 / JSON 清单”，可一次导入构件 JSON、结构 NBT 和主模型，也可生成、下载、读取带哈希的 JSON 资产清单。批次保存到当前工作区 `nbt_models/asset_batches/`，每批有 `assets.json` 和导入报告；原文件保留。支持摘要和完整方块数据两种读取方式，每批最多 100 项，导入总量上限为 32 MiB。清单使用工作区相对路径，迁移时保留整个工作区。

模型生成的构件可由脚本直接保存：对外 Skill 调用 `structure_save` 或 `asset-batches save`，内置 AI 点击“生成并保存资产”。系统生成真实预览后登记为待审阅资产，自动生成批次清单，手动导入继续可用。“整理现有资产”可补齐规范目录和清单，保留资产 ID 与预览草稿。

在资产管理打开“工具效果”，可管理道路、混材、自动地面、风化、结构编辑和建模步骤的效果配置。“保存配置”会保存当前工具到原生效果库；可在独立样例上切换前后预览，再载入当前建筑生成候选。Agent 通过 `effect-assets save/get/preview/compile` 使用同一入口，效果不携带建筑源文件、选区或预算权限。

完整版附带 **32 项初始工具效果**及预生成的修改前后 3D 样例，覆盖道路、半格坡道、屋顶、混材、风化、地面、几何、复制、阵列和扩散等。资产管理主界面提供“构件 / 工具效果”切换，没有构件时默认展示初始效果卡片和缩略图；点击卡片可查看修改前后的材质 3D 样例。首次打开时自动保存到当前工作区 `nbt_models/asset_library/tool_effects/`，无需联网或调用 AI；Agent 的 `effect-assets list` 也能直接读取。重复打开不重复入库，不覆盖已有同编号资产；用户回收或移除的初始效果不会自动恢复。初始资料只含效果配置与只读样例，不附带建筑或构件资产。修改效果请“保存为新效果”，手动导入继续可用。

在软件源码根目录维护初始资料可运行 `mise exec -- npm run build:starter-effects`，通过共享工具引擎生成配置、缩略图和真实前后快照；`mise exec -- npm run check:starter-effects` 校验定义、文件哈希和引擎版本，发布构建也会执行此检查。预生成样例可直接查看，载入用户建筑仍重新计算候选并保留原有保护、预算与显式导出流程。

Agent 可只保存需要改变的面板字段，其余沿用目标建筑的设置。面板配置会更新对应工具；需要继续加工刚放置的构件时，可将操作保存为有名称的工具步骤，按序追加。应用失败会恢复原参数和候选画面；预览失败会清空旧样例。

“整理资产”会清理纯序号标签、生成语义用途分组与统一索引，并把已有操作配方的默认配置接入效果预览；原配方的可调参数仍保留。规范目录为 `nbt_models/asset_library/`，工具效果位于 `tool_effects/`，预览过程位于 `_workspaces/effect_previews/`，不进入建筑列表。

### AI 与 Agent 协作

AI 是可选功能，普通浏览、编辑和导出无需 API。

内置 AI 使用独立的精简 Skill，为文字、局部编辑、小构件、独立资产、选区编辑和控件任务加载各自的规则。工具字段与限制仍由共用目录生成，示例、定义和默认工作流说明不重复发送。自定义规则、创作偏好和主动选择的资料继续生效，外部 Agent 仍使用完整 Skill。本地校验和手动导出要求保持不变。

AI 可返回紧凑区域及材质索引，由本地脚本展开为工具步骤、补齐步骤名称与默认归属，并合并连续、同材质且并集恰为长方体的区域；不补洞、不重排。控件增量只需给步骤编号与变化字段，原步骤指纹由脚本按原请求绑定。默认输出令牌预算为文字 **6144**、结构／控件 **12288**；手动配置的长度优先，原有几何、操作数、保护和改动预算仍生效。截断内容不会当作完整模型应用。

提示词编写只校验设计文字和交接格式。建模入口及高级工具提案会检查 JSON 与参数，核对 1.20.1 方块与属性；需要创建几何时，调用共用 Python 引擎。楼梯、屋顶、材质等错误会反馈给模型修正，总共最多请求 3 次。归属字段严格使用 `body / wall / inherit`，脚本可归一化等价的工具键、公共字段包装和标准 `Name/Properties` 方块状态。任务记录分开显示“接口已返回”和本地校验结果；几何预检不等于设计、通路或游戏验收。

真实服务回归可使用 `mise exec -- node tests/desktop/ai-live-desktop.mjs --profile <NBTCreator用户配置目录>`，显式调用该配置的实际 API，测试完整初稿、小构件和独立资产。检查使用隔离工作区，保留本次合成任务的真实最终返回与预览报告，结束后清理复制的加密连接文件；不会导出 NBT 或发布测试构件。普通自动测试不调用真实服务。

从软件源码根目录运行离线模拟验收： `mise exec -- npm run test:agent-simulation`；验证完整目录包用 `mise exec -- npm run test:agent-simulation -- --directory dist/<目录包>`。模拟服务覆盖全部生成入口、错误归属/材质/几何反馈、截断修正、重试停止和鉴权失败，测试会实际运行 Electron、Python 几何计算和外部 Agent 读写。随后执行界面采用、选区保护与回退、撤销、资产预览与入库流程，输出 `build/agent-acceptance-*/results.json` 和各项日志。目录包验收先比较共享引擎和桌面源文件哈希，再检查随包运行环境；不读取用户 Key 或调用真实 API。

增量参数按照共用目录的类型定义检查，支持镜像从空值改为X/Z、混材缩放从单值改为XYZ；不再用旧值的类型限制合法的新值。局部编辑与其他生成入口使用相同的标准方块状态归一化。新工具步骤的未知字段会明确报错；原方案已有的本地元数据可原样保留，不能由返回结果改写。

AI 助手默认不设应用字数限制。连接配置中的“最终结果字数上限”填 **0** 即关闭；也可填 **100～60000**，已有明确设置会保留。启用限制时，首轮请求就告知模型，本地只统计提取出的最终结果（Unicode 字符，包含结果内空白、JSON 键名和标点），不计可分离的思考、说明或包装标记。

程序优先提取唯一完整的 JSON 对象、JSON 代码块或明确的 `<final>…</final>` 正文，忽略独立思考字段和正文前标记为 `<think>`／`<analysis>` 的完整思考段；没有标记的普通文字不会猜测删减。即使接口报告达到令牌上限，只要最终 JSON 已完整且通过全部本地校验，或文字正文已有闭合的最终结果标记，也可继续使用。残缺或歧义结果不会直接应用。超限或本地校验失败时，携带错误自动修正，总共最多请求 3 次；重复截断时只精简重试 1 次，网络或鉴权错误不触发格式重试，可随时取消。

官方 DeepSeek 地址上的 `deepseek-flash`／`deepseek-v4-pro` 默认关闭思考，以便将返回预算用于最终结果；显式设置的 `thinking`／`reasoning_effort` 优先，其他接口不自动注入该参数。接口提供思考令牌统计时，任务记录会单独显示。关闭字数限制仍受服务端令牌预算、本地最终结果 12 万 UTF-16 码元和总响应 2 MiB 的处理上限约束；可在请求参数中调节模型支持的令牌预算，程序不会拼接残缺 JSON。

- 在“AI 助手”配置连接、模型与 API Key，可调整采样、输出长度、超时和请求参数。
- 小型构件可只选择参考类型直接生成，也可补充风格、材质与用途；生成后预览，再整体移动或旋转。
- 小型构件默认裁掉候选中与保护区冲突的方块，**保留保护区原有内容**。关闭裁剪时，存在冲突的候选会被拒绝；覆盖开关与改动预算仍生效。
- “选区自然语言工具编辑”读取真实选区方块，返回可审阅的命名步骤，再由本地引擎检查和预览。
- 各工作流可分别配置创作偏好、规则、知识资料和视口截图；截图需要模型支持图像输入。
- 可检索本地参考资料与现有构件，查看出处后选择发送；内部 API 与对外 Skill 的知识配置分开管理。
- 标注可整理为任务并交给外部 Agent；回传版本后可同镜头对比，逐条核对意见。

AI 返回内容须通过本地格式、工具、坐标、材质、保护和预算检查。API 的 JSON 模式不能保证返回内容符合全部建模规则；检查报告不替代实际看图或游戏内验收。

项目卡片提供统一的“查看与管理”入口：左侧预览，右侧可设置所属菜单和创作阶段、修复文件、查看版本历史；详细路径与版本默认折叠。点击“进入模型编辑”后再调整模型。

点击创作方案底部的“确认并交接”，可同时标记当前提示词已审查并保存任务；点击“下一条”可继续编写。需要集中交接时，在“方案操作”中选择“仅标记已审查”，再使用“列表工具”中的批量交接入口。“方案操作 → 删除这条方案”经确认后移出列表，重启后也不会恢复；归档文件、已交接任务与建筑保留。

## 外部 Agent 与命令行

让 Agent 在创作项目的根目录读取 `.agents/skills/nbtcreator-workspace/SKILL.md`，按任务进入所选知识路由。应用与 CLI 使用同一套引擎，建模无需通过 GUI 自动点击完成。

完整建筑的组合与续版可使用统一 `model` 入口：`capabilities --model` 查询请求契约，`model --request <JSON>` 编译并安装构件、应用宿主修改或更新受管组合。显式 `save_draft` 保存带实例基线的 SNBT 制作版，换版会检查手改冲突并恢复原底材。柱梁组合支持具名承托接口与自动跨接。详见[统一工作模型](../../.agents/skills/minecraft-nbt-modeler/references/working-model.md)；开发验证在本项目根目录运行 `mise run model:test`，真实预览回归运行 `mise exec -- npm run test:model-preview`。

```powershell
python .agents/skills/nbtcreator-workspace/nbt.py capabilities
python .agents/skills/nbtcreator-workspace/nbt.py paths
python .agents/skills/nbtcreator-workspace/nbt.py feedback scan --workspace .
```

便携版也可通过 `NBT工具.cmd` 使用内置运行环境：

```powershell
.\NBT工具.cmd --workspace "D:\MyMinecraftProject" capabilities
```

各命令用 `--help` 查看参数。对外工具与知识可在应用的 AI 设置中管理；Agent 回传结果、标记任务完成或通过工具检查，均不表示用户已批准。

## 更新与常见问题

**如何更新？** 在“设置 → 更新”检查稳定发行版并下载，校验后关闭应用，再解压到新目录或按更新包说明合并。保留原工作区，不覆盖运行中的程序。

**为什么有些模型只能查看？** 编辑可能需要补齐坐标、开口、墙层或验证上下文。界面会列出缺失项；未知碰撞形状、通路失败与文件损坏会分别说明。

**为什么 AI 生成后没有 NBT 文件？** 返回的是建议或候选。先载入预览并检查，最后手动导出下一版。

**为什么切换默认预览后仍恢复旧镜头？** 草稿优先恢复上次状态。默认设置用于新开的预览，可在常规设置管理草稿恢复。

**如何反馈问题？** 在 [GitHub Issues](https://github.com/Try2findwhoasked/NBTCreator/issues) 提供版本、操作步骤、任务错误与必要截图，不要附带 API Key 或私人工作区数据。
