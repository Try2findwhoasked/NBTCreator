# 首次创建模型与 AI 方案

提示词方案页默认用于首次创建完整模型，不会自动载入“模型编辑”中正在查看的建筑。“新建初稿”清空已有模型关联；“载入当前建筑与参数”才切换到已有模型的只读规划。已有作品精修仍需对应源、保护设置与真实看图确认。

## 形状与保存位置

归档形状使用 Skill 的 8 个标准目录键：single、long、square、l_shape、t_shape、cross、irregular、standalone，最终按真实模型登记。切换形状时，下拉框下方会显示匹配的形状约束数量，并可跳到「我的项目」勾选。切换后保留已选的项目共用约束，原形状专属的引用会取消。单独选择分类不会改写尺寸和有效网格。

建筑库在「我的项目」下并列显示已保存的约束。点击约束会显示引用该规则的房间。旧项目通过已交接方案、初稿回传和房间专属规则定位实际建筑。形状目录仍可单独浏览。选中项目后可打开「管理约束」。新布局每条规则有自己的 `约束.json` 和 `历史版本/`，旧项目继续读取原有的 `项目约束.json`。选「全部项目」可编辑工作区共用约束。

「起草要求」在「我的项目」下并列显示 1×1、2×2、L 形等内置约束，以及项目和工作区约束。勾选会同步到「编辑与审查」，并以快照进入方案和交接。展开「查看要求」可看完整内容和来源。需要改变内置参数时，从「管理约束 → 从模板起步」填写并保存自己的规则。为已登记房间写修改要求时，应用自动带入其引用。方案最多引用 16 项约束。

展开「已选」可核对生效尺寸、网格和规则版本。发生冲突时，可以保留当前选择，或确认替换冲突的规则。切换归档形状后，页面会提示本次移除的形状约束。

建筑库的「筛选」可同时限制归档形状和实际引用的约束。选择内置约束时，匹配范围取自房间的已保存引用或已交接方案。

打开建筑详情并展开「引用约束」，可查看房间登记、交接方案、初稿回传和手动关联的来源，点击来源可复制路径。旧房间可通过「未引用约束」筛出，再点「多选 → 关联约束」。确认前会合并同一房间的多个版本。

可以在起草时设置预定归属。点击「登记房间」或「确认并交接」后，方案使用归属约束下真实的房间目录。建筑库中的「房间管理」可修改名称、引用和归属，多个约束可以引用同一份房间资料。旧项目可从「设置 → 项目与文件 → 旧项目迁移」预检并迁入独立副本。

「管理约束」中可以编辑、让 Agent 创建草稿或刷新列表。方案保存的是已勾选的修订，更新文件夹中的规则后，可以点击「改用第 N 版」更新引用。外部 Agent 可通过 CLI 编辑同一文件，详见[项目约束接口](../../.agents/skills/minecraft-nbt-modeler/references/architect-tools.md)。

在「管理约束」中可分别设置密闭检查、通行洞口策略和洞口净宽 × 净高。露天项目可选「不要求密闭」，通行洞口可由设计决定、要求至少一个或指定不设置。固定尺寸以方块计，独立建筑也可留空让执行 Agent 按每个洞口决定。需要接入 SAODG 时，在创作方案勾选「SAODG 房间接入」，会附上标准 6 × 5 端口与密闭要求。约束会随交接任务及坐标草案传递。[验证字段](../../.agents/skills/minecraft-nbt-modeler/references/validation-workflow.md)

新建时不要求填写已有主模型、保护文件或审阅目录。归档根目录由形状与中文名生成相对路径 `nbt_models/<形状>/<中文名>`，字段只读并随名称更新。实际制作时，由 Agent 使用 Skill 的 `nbt_library.py new` 分配新的日期版本，保存主模型、脚本、图片、坐标、验证及 `room_description.json`。新制作版使用 SNBT；定稿 NBT 经明确导出后存入 `nbt_models/_exports/` 的镜像层级。仅在本页选择目录不会在磁盘上生成建筑。

## 编写、审阅与交接设计要求

「待领取」只显示已经交接、当前可以领取的任务。外部 Agent 成功领取后，列表和复制读取命令会自动收起；任务释放或租约到期后会重新出现。任务文件和方案修订可继续读取。

填写主题与用途后，可让 AI 编写建筑要求，也可直接手工编辑。人工参数按建筑概况、空间与体验、风格与部位意图、硬条件与补充分组：除名称、形状和用途外，可填写核心空间特色、分区与高差、动线、材质分工、光线与氛围、顶构／地面／墙面／道具意图、保留项和希望避免的设计。可选项允许留空，不要求逐项补满；每项文字最多 4000 字，超出会提示修正。已保存方案保留原有文字。

新建独立建筑的尺寸默认是参考值，执行 Agent 可按用途调整并说明；选为“固定尺寸”后必须满足。已有模型、旧版方案和 SAODG 接入沿用固定尺寸。人工明确给定的尺寸与硬条件始终优先。

在“AI 可修改的设计项”中选择本次需要建议的字段，其他人工值作为参考保留。默认允许修改用途、空间、风格和各部位意图；名称、形状、尺寸、占地、保留项、避免项和其他要求默认由人控制，也可手动勾选允许建议。尺寸的参考／固定策略始终由人设置。AI 可只返回一两项建议，无需重写整份方案；收到候选后仍须人工采用，采用前修改设计或本次范围会使旧候选失效。采用后再调整下一次的修改范围，不会丢失已采用的说明。

内部 AI 只辅助表达用途、核心空间特色、风格氛围和清楚的连接关系。用户未指定的构件数量、方块配方、坐标与施工脚本由接收任务的 Agent 决定。默认编写流程不生成工具序列，也不运行 Python 几何预检。最终提示词由应用统一组合人工参数、设计说明和执行／存放规则，文字润色不会替换人工硬条件。

人工审阅并修改后，点击“确认并交接”，在对应建筑的 `提示词方案/任务/` 保存不可变任务修订；页面显示实际目录和读取命令。任务包含最终提示词、全部人工参数、尺寸策略、本次 AI 修改范围及既有计划／上下文快照，后续编辑不会改写已发布任务。应用不自动启动外部 Agent。接收任务的 Agent 再读取真实模型、标注和工具接口，完成建模、开口、通路验证与审阅图交付。需要手工配置工具序列和验证上下文时，可使用“建造与约束”，展开或收起不会删除已有步骤。

## 批量编写

从创作方案顶栏打开“批量编写”。正在编辑单条方案时，可从“更多”打开。选择继承当前方案，即可用它的设计参数、约束快照、尺寸策略和 AI 修改范围作为模板。每条方案独立保存、审阅和交接。用“更多”中的“重试未完成项”补写失败条目。

外部 Agent 在创作项目根目录查看待办与任务正文：

```powershell
mise run nbt -- prompts tasks --status pending
mise run nbt -- prompts task --id <id>
```

方案回填、“参数有效”或任务登记完成都不代表已有 NBT、设计合格或精修获批。文字润色仍须保留本地存放规则、阶段和交付约束，不得改写既有源路径、保护与批准。完整审查流程见[建筑师工作流](ARCHITECT_WORKFLOW.md)，任务接口与源绑定见[共享工作区](SHARED_WORKSPACE.md)。

## 模型编辑的小型结构 AI

在“修改范围”中明确局部 XYZ 选区，或使用 3D 选点设置部件位置，再到 AI 建模选择“AI 添加小型结构”。当前提供 6 组 45 种构件参考，可补充材质、尺度和使用要求；生成后可整体移动 XYZ 并重新预览。

API 返回使用选区相对坐标的方块、梁、边框或 blocks 数组，归一化后最多 128 步，不直接拼接二进制 NBT 或执行任意代码。先在本地校验选区、端点、厚度、状态与写入量，再转换为全局坐标。采用后追加至共用工具序列并计算临时预览，可用“检查当前效果”检查保护、预算与整体通路，满意后显式导出下一版。模型或参数发生变化后旧候选检查失效。

API 默认只发送本次要求、设计参数或局部选区/材质摘要，不发送本地路径、完整模型和确认记录。各工作流可显式开启视口截图，需视觉模型支持；所选内部规则/资料库只提供给相应工作流。请求、取消、校验、预览和整体移动在任务记录保留阶段日志，不记录密钥或截图 base64。真实模型仍可能返回不合规方案，模拟联调通过也不能证明设计质量。
