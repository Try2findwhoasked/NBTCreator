# NBTCreator migration

This is a standalone Windows-first Electron migration project for Minecraft Java 1.20.1 NBT authoring. Do not edit the original SAODG workspace as part of work here.

- `references/saodg-2026-11-02.zip` and the expanded snapshot are immutable migration reference material. `manifest.json` records original source paths, sizes and SHA256 values; verify with `npm run verify:archive`.
- `.agents/skills/minecraft-nbt-modeler/` is the active, portable skill and current Python engine/frontend source. Modify this copy, not the reference snapshot. Preserve real thumbnail confirmation and the separate explicit manual-export flow.
- `desktop/` owns Electron lifecycle, a bounded preload bridge and the local backend worker. Python/NumPy work stays outside the renderer and main event loop.
- `scripts/cli.mjs` is usable without opening Electron. Keep CLI and UI on the same active Python engine. Never require GUI automation for agent modelling.
- `tools/structures/workbench/` is an imported compatibility component; its SAODG mod-management operations remain integration-specific and are not yet exposed as a general NBTCreator feature.
- Default authoring workspace is the calling Agent project root; outputs live in `nbt_models/`. Explicit/manual workspace choices remain supported. Do not default to installation resources, and do not package user assets or credentials.
- Discover the workspace skill through `.agents/skills/nbtcreator-workspace/SKILL.md`, generated by the AI settings knowledge selector. `.agents/skills/minecraft-nbt-modeler/` remains the shared implementation/reference source; obey the selected knowledge routes, not all implementation references by default.
- `tool-catalog.json` inside the engine skill is the single source for tool definitions and CLI mappings. Run `npm run sync:tools` after changing it and `npm run check:tools` before packaging. Keep the generated facade and catalogue in sync with Python support.
- Run `npm run doctor`, `npm run test:desktop`, skill checks and focused Python regressions appropriate to changes. A packaged executable is not evidence of a bundled Python runtime or production acceptance.

Production packages use prebuilt frontend assets and a loopback static HTTP host in a managed Node utility process. Vite remains an explicit/unbuilt-source development fallback, not a production runtime dependency. Run build:web before frontend tests; package builds automatically. Keep Host/Origin protections, sandbox/context isolation, source hashes and new-version exports. Do not expose arbitrary execution through IPC. Preserve the documented fullscreen issue without triggering it unless requested.
