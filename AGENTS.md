# NBTCreator migration

This is a standalone Windows-first Electron migration project for Minecraft Java 1.20.1 NBT authoring. Do not edit the original SAODG workspace as part of work here.

- `references/saodg-2026-11-02.zip` and the expanded snapshot are immutable migration reference material. `manifest.json` records original source paths, sizes and SHA256 values; verify with `npm run verify:archive`.
- `.agents/skills/minecraft-nbt-modeler/` is the active, portable skill and current Python engine/frontend source. Modify this copy, not the reference snapshot. Preserve real thumbnail confirmation and the separate explicit manual-export flow.
- Keep public command scripts and documented Python imports at the top of the active skill's `scripts/`. Place engine internals in the relevant domain package. See `docs/development/ARCHITECTURE.md` for the directory map.
- New modular recipe/component data belongs in the independent `NBTCreator-AssetLibrary` repository. `assets/extension-library/` inside the engine skill is its bundled release snapshot, verified with `mise run assets:check`; import an explicitly selected source with `mise run assets:sync -- --source <library>`. External libraries are JSON data only; listing stays offline and only explicit discovery/refresh uses the network. See `.agents/skills/minecraft-nbt-modeler/references/asset-libraries.md`.
- `assets/viewer/src/library/asset-workspace.js` inside the skill is the unified material browser for local, bundled and connected editions. `asset-libraries.js` in the same folder manages source connections. The UI uses `asset-libraries browse` and binds source, version, manifest, asset and compiled-content hashes for preview, copy and placement.
- `desktop/` owns Electron lifecycle, a bounded preload bridge and the local backend worker. Python/NumPy work stays outside the renderer and main event loop.
- `scripts/cli.mjs` is usable without opening Electron. Keep CLI and UI on the same active Python engine. Never require GUI automation for agent modelling.
- `tools/structures/workbench/` is an imported compatibility component; its SAODG mod-management operations remain integration-specific and are not yet exposed as a general NBTCreator feature.
- Default authoring workspace is the calling Agent project root; outputs live in `nbt_models/`. Explicit/manual workspace choices remain supported. Do not default to installation resources, and do not package user assets or credentials.
- Discover the workspace skill through `.agents/skills/nbtcreator-workspace/SKILL.md`, generated by the AI settings knowledge selector. `.agents/skills/minecraft-nbt-modeler/` remains the shared implementation/reference source; obey the selected knowledge routes, not all implementation references by default.
- The software source root is not an authoring workspace. Do not generate `nbtcreator-workspace` here; that facade belongs in the user's creative project. For maintenance here, read the active engine and relevant references directly. Keep existing user projects and their generated facades intact.
- `tool-catalog.json` inside the engine skill is the single source for tool definitions and CLI mappings. Run `mise run tools:sync` after changes and `mise run check` before packaging. Keep the generated facade and catalogue in sync with Python support.
- Run `mise run doctor`, `mise run test -- desktop` after building the frontend, and focused regressions appropriate to changes. Use `mise run test -- --list` to locate existing test suites. A packaged executable is not evidence of a bundled Python runtime or production acceptance.
- Tests are grouped by execution environment in `tests/engine/`, `tests/node/`, `tests/desktop/` and shared `tests/support/`. Define reusable regression suites in `tests/suites.mjs` and invoke them through `mise run test` locally and in CI. When moving tests, update suite, acceptance and fixture references. See `tests/README.md` for build prerequisites and packaged coverage.

Production packages use prebuilt frontend assets and a loopback static HTTP host in a managed Node utility process. Vite remains an explicit/unbuilt-source development fallback, not a production runtime dependency. Run build:web before frontend tests; package builds automatically. Keep Host/Origin protections, sandbox/context isolation, source hashes and new-version exports. Do not expose arbitrary execution through IPC. Preserve the documented fullscreen issue without triggering it unless requested.
